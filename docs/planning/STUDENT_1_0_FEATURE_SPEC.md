# 학생 1.0 기능별 개발 명세

작성일: 2026-11-07 · 기준 main: `6dd838934b4b27731c12d06f9ef3dd0530d4596e`

**문서만 작성한 개발 명세다. 구현·DB 변경·미디어 삭제·배포·PR 병합을 승인하거나 실행하지 않는다. 정책 우선순위는 최신 사용자 지시 및 [v1.2](../product/PRODUCT_DECISIONS_V1_2_2026-11-07.md) → 변경 없는 [v1.1](../product/PRODUCT_DECISIONS_2026-11-07.md) → 기존 초안이다.**

작업 ID는 세 문서의 동일 ID와 연결된다. 아래 데이터 필드는 개념 계약이며 운영 SQL이 아니다. 기존 선택 필드·ID를 최대한 유지한다. 원본을 잃지 않는다는 원칙은 이전·장애 보호에 적용하며, 사용자가 v1.2에 따라 최종 승인한 직접 삭제를 30일 보관한다는 뜻이 아니다.

## 공통 계약 보충

- **단일 로그인:** 기기는 서버의 활성 세션 식별자로 묶고 단순 deviceId 저장으로 보안 판단하지 않는다. 새 로그인 인증과 데이터 접근 승인을 구분한다. 인계 대기 토큰은 기존 자료 쓰기/정밀 분석을 허용하지 않는다. 승인 nonce는 짧게 만료하고 기존 세션 epoch를 조건부 교체한다. 만료 JWT·옛 JWT·구버전 직접 DB 쓰기·service-role 경로까지 검사한다. 오프라인 옛 기기의 임시 파일을 지우지 않고 같은 계정 재인증 후만 제출한다.
- **발급된 업로드 URL:** session 교체 뒤 기존 PUT가 객체를 만들 가능성을 가정한다. 권한 프록시·짧은 권한·quarantine·완료 단계 session 재검증으로 그 객체가 ready/재생/과금에 편입되지 않도록 한다. 원하는 즉시 취소 범위를 Phase 02에서 결정한다.
- **삭제:** UI 대상은 즉시 접근 불가로 전환하고 실제 바이트 삭제는 서버 작업으로 즉시 시작한다. 장애 시 '삭제 처리 중/실패'로 표시하고 재시도하며 성공을 가장하지 않는다. 휴지통이나 복구 UX는 없다. 삭제 표식/멱등 키는 재등장·중복 환급 방지용 최소 기술 기록이다. 사용자 본문 보관을 위한 휴지통으로 쓰지 않는다.
- **정산:** UI 항목 삭제/취소, 차감 역거래, 현금 환불은 다른 행위다. 레슨 삭제가 실제 환불 API를 자동 실행하지 않는다. 정산 원장의 최소 감사 보존 기간·필드·열람권은 결정 필요. 별도 앱/DB에는 하나의 원자적 트랜잭션을 가정하지 않고 상태 원장·재시도·재계산을 사용한다.
- **계획과 실제:** 목표는 planned minutes/count, 체크는 occurrence ID·실제 수행 session 참조, 세션이 실제 시간의 단일 원천이다. 목표 복사 시 원 추천/숙제 스냅샷·ID를 남기고 나중 추천 변경이 과거 수행을 덮어쓰지 않는다. 반복 예외·시간대·목표 수정 이력을 유지한다. 분/횟수 달성률은 별도 분모로 표시하고 목표 0은 미설정으로 처리한다.
- **악보:** PDF는 원본, MusicXML은 버전 있는 별도 자료다. 확인된 성부·조옮김·박자·템포 지도에서 기준 데이터를 생성한다. 반복/도돌이표·쉼표·못갖춘마디도 검증한다. 악보 개정 시 기존 분석은 이전 기준 버전에 연결하고 최신 점수로 오인시키지 않는다.
- **미디어:** Supabase는 권한/작업/구조 데이터, R2는 바이트다. RLS가 R2에 전파되지 않는다. 서명 URL은 이미 받은 바이트까지 회수하지 못한다. 기기 파일은 서버의 실제 무결성·재생 가능 확인 전 정리하지 않는다.
- **2.0 확장:** 학생 개인 레슨과 공동 수업 회차의 생명주기를 분리하고 학생/선생님 N:M·대상·작성자·소유자·권한을 혼합하지 않는다. 전체 보관함 공유·수정 제안은 이번 1.0 구현 대상이 아니다.
