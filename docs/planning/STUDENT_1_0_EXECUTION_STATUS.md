검증 SHA·결과·배포 상태는 #231에 기록한다. [계약과 한계](STUDENT_1_0_MEDIA_DELETE_RESUME.md). R2 원본의 원자적 버전 보호, 구 클라이언트/로컬 writer 통제, 복구 입력 보존/정리·용량 정책, 실제 HTTP·두 기기·iPhone 인수는 남아 있으며 Phase 전체/운영 완료로 표시하지 않는다.

실제 검사 SHA/결과 및 배포 여부는 #230에 기록한다. 합성 브라우저/격리 DB 통과를 실제 PostgREST·두 기기·iPhone 인수로 대체하지 않는다. [복구 연결 범위와 남은 조건](STUDENT_1_0_SNAPSHOT_RECOVERY.md).

다음 순서: 복구 입력의 명시적 보존/정리·용량 정책 → 이전 세션의 미완료 물리 삭제 재승인 → R2 개체 버전/구 클라이언트 서버 차단 → 운영 SQL 제한 설치와 실제 HTTP·두 기기·iPhone 인수 → 계정별 제한 활성화. 최신 공통 디자인을 재사용한 복구 작업 페이지 외의 UI 고도화는 이번 범위에 포함하지 않는다.

## 2026-11-10 후속 — 명시적 저장 복구 계약

[#229](https://github.com/eye215/Vocalzip/pull/229)에서 충돌·이전 로그인 미확인 요청의 확인/복구 계약을 transport에 추가했다. 새 동기화는 계속 **기본 OFF**이며 운영 DB·계정·미디어는 변경하지 않는다.

- 기기·서버·이전 pending을 보존한 뒤 사용자가 확인한 안을 현재 세션의 새 CAS 요청으로 저장한다. 한쪽에만 있는 기록 누락, 새 삭제, 확인 뒤 입력/서버/journal 변경은 확인 없이 반영하지 않는다.
- 레슨/파일 삭제는 복구용 보존 입력에서도 정리한다. 미완료 물리 삭제·generation 교체는 일반 복구 확인으로 진행하지 않는다.
- 현재는 독립 저장 계약과 합성/격리 DB 회귀 검사 범위다. **사용자 복구 화면, root 승인값 적용, 이전 세션의 물리 삭제 재승인은 미연결**이다. 단계 전체 완료/운영 인수로 표시하지 않는다.
- 실제 실행 SHA·검사 결과는 #229에 기록한다. [계약·검증·남은 조건](STUDENT_1_0_SNAPSHOT_RECOVERY.md).

다음: 승인된 시트로 충돌 필드 비교/선택 연결 및 다른 계정 로컬 데이터 보존 → 복구 입력 정리 정책/물리 삭제 재승인 → R2 버전/구 클라이언트 서버 차단 → 실제 HTTP·두 기기·iPhone 인수 → 계정별 제한 활성화. UI 고도화 작업의 공통 CSS/화면 파일은 이번 계약 작업에서 수정하지 않았다.

## 2026-11-10 후속 — 미디어 삭제 저장 계약 연결

[#225](https://github.com/eye215/Vocalzip/pull/225)에서 #214의 남은 클라이언트 미디어 삭제 경로를 연결했다. **새 동기화 기본 OFF·운영 DB/계정 전환 없음**을 유지한다.

- root revision의 파일 삭제 표시/참조 정리를 확인한 뒤 원본을 정리한다. 미완료 삭제 의도는 같은 계정/로그인 세션에서 재개하며 로컬 정리 완료 후 해제한다.
- 다른 기기의 메타데이터 변경·일반 저장 pending·저장 공간 부족·계정 전환·손상된 로컬 기록은 확인 없이 원본 삭제로 진행하지 않는다.
- 삭제 직후 계정이 바뀌어도 새 계정의 같은 ID 로컬 파일을 지우지 않도록 보강했다. 시각 디자인/공통 CSS는 변경하지 않았다.
- 기능 소스 검사: 단위 95, 기본 DB 108, rollout DB 40, 관련 브라우저 185 통과/7 skip. 상세 범위와 실제 기기/운영 검증과의 구분은 [미디어 삭제 연결 문서](STUDENT_1_0_MEDIA_DELETE_BRIDGE.md)에 기록했다.

현재 다음 순서: **충돌·이전 로그인 복구 계약/명시적 확인 연결 → R2 개체 버전 및 구 클라이언트 서버 차단 인수 → 실제 HTTP·두 기기·iPhone 인수 → 계정별 제한 활성화**. 파일/레슨 기록이 복구되는 모든 서버 변경 경로와 보관 정책도 함께 대조한다. 실제 미디어 일괄 삭제나 유료 AI 일반 공개는 수행하지 않는다.
