이 표는 코드 구현 확인이며 실제 iPhone/운영 서버 검증 완료를 의미하지 않습니다.

## 이번 개발

발견한 오류:
1. 시작 레슨 삭제 시 다른 레슨으로 이월된 숙제까지 삭제될 수 있었습니다.
2. 삭제나 숙제 상태 변경의 저장 실패 후 메모리에 변경이 남아, 이후 정상 저장에 섞일 수 있었습니다.
3. 곡/항목 추가 시 저장 실패에도 입력이 초기화될 수 있었습니다.

수정:
- 레슨 삭제는 연결만 해제하고 숙제·수행 메모·미디어 원본을 보존합니다.
- 삭제·숙제 상태·곡/항목 추가에 저장 실패 되돌리기를 적용합니다.
- 입력 초기화는 저장 성공 이후 실행합니다.
- 실제 보존 범위가 삭제 확인 문구에 표시됩니다.
- 최신 main의 디자인, 날짜 컨테이너, 개별 녹음 평가, 대용량 업로드 변경을 유지합니다.

검사: 기존 Chromium 모바일/데스크톱·WebKit 테스트에 다음 5개 시나리오를 추가했습니다.
이월 숙제와 수행 메모 보존/재접속, 삭제 실패 후 후속 저장, 숙제 상태 실패/완료/재접속,
레슨·숙제 저장 재시도 중복 방지, 곡 입력 보존/재시도.
최종 커밋 SHA와 실행 결과는 이 변경의 PR 본문 및 Checks에 기록합니다.

## 남은 작업 순서

1. 실제 iPhone Safari: 음성·영상 녹음, .m4a/.mov 가져오기, 재접속 재생, 권한 거부, 용량 부족.
2. 실제 계정으로 로그인·자동/수동 백업·복원·기기 변경·네트워크 중단 후 재시도.
3. 저장한 레슨의 내용 수정과 연결된 숙제·녹음 이력 편집.
4. 비교 리포트 수정·삭제·재열기 및 숙제 진행률 정의/추이 검증.
5. 표시 버전/문서 일치, 서비스 워커·공유 수신·배포 후 스크립트 갱신 검증.

실제 오디오의 음정·호흡·비브라토 분석은 구현 완료 범위가 아닙니다.
자동 테스트의 클라우드는 대역이고 녹음은 가상 장치입니다.
Linux WebKit의 MediaRecorder 미지원 검사는 제외하며 실제 iPhone 테스트를 대체하지 않습니다.
