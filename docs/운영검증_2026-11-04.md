## 운영 정산 DB — 확인 대기

운영 프로젝트: chxnbtiyuyhiywzeshis. 현재 연결된 Supabase 계정의 프로젝트 목록에는 이 프로젝트가 없다. 운영 DB 조회는 권한 오류로 거부됐으므로 테이블/RPC가 없다고 단정할 수 없다. 접근 가능한 계정으로 연결 후 아래 읽기 전용 점검부터 수행한다.

```sql
select to_regclass('public.vocal_billing_documents') as billing_table;
select p.proname, p.prosecdef, p.proconfig
from pg_proc p join pg_namespace n on n.oid=p.pronamespace
where n.nspname='public' and p.proname='vocal_billing_save';
select relrowsecurity from pg_class
where oid=to_regclass('public.vocal_billing_documents');
select policyname, roles, cmd, qual, with_check from pg_policies
where schemaname='public' and tablename='vocal_billing_documents';
```

결과를 billing/migrations/20261104_billing_cloud.sql과 비교한다. 적용이 필요하면 운영 테이블을 먼저 확인하고 해당 마이그레이션만 적용한다. billing/tests/sql-setup.sql은 임시 테스트 DB 전용이며 운영에서 실행하지 않는다.

## 실제 계정·기기 확인 절차 — 미실행

1. 실제 iPhone Safari에서 로그인 → 레슨/연습 음성 녹음 → 저장·재생·새로고침 후 유지 확인.
2. 사진/파일 앱 MOV·M4A 다중 가져오기 → 음원 추출·곡 지정·촬영일 확인 → 날짜 수정 후 유지 확인. 실패 시 원본 보존과 재시도 확인.
3. 본인 테스트 기록으로 기기 A와 B의 서로 다른 곡/레슨을 동기화해 양쪽에서 모두 보이는지 확인. 같은 레슨 동시 편집은 충돌 정책과 실제 결과를 별도 기록.
4. 정산 JSON 백업 후 기기 A에서 전용 클라우드 저장 → 기기 B에서 미리보기·가져오기 → 레슨권/결제/차감 합계 비교. 기존 데이터 교체 전 복구 스냅샷이 생성되는지 확인.
5. 다른 사용자 계정이 본인 정산 행을 읽거나 쓰지 못하는지 테스트 계정으로 검증. 토큰·비밀번호는 보고서나 GitHub 로그에 기록하지 않는다.
6. 백그라운드 전환·네트워크 중단·저장 공간 부족 시 성공으로 잘못 표시하지 않는지 확인. 기록 보존 후 테스트 데이터를 정리한다.

이 절차는 실행 결과가 아니라 남은 검증 목록이다. 실제 기기나 로그인 세션 없이 완료 처리하지 않는다.
