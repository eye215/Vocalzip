## 1. 출시는 2단계

- **학생 Release 1.0:** 학생 혼자 곡·녹음·연습·레슨 기록·숙제·성장·공연 기능 이용. 선생님 계정과 연결하지 않아도 사용할 수 있다.
- **선생님 Release 2.0:** 학생-선생님 N:M 관계, 1:1 및 1:N 그룹 레슨, 예약, 참여자 출석, 협업 피드백·숙제, 레슨비 정산.
- 한 계정이 학생과 선생님 역할을 동시에 보유할 수 있다.

## 2. 음성/영상 저장: 최신 확정 사항

- 일반 사용자에게 **영상 업로드·영상 파일 가져오기 기능은 당분간 제공하지 않는다.** 오디오 녹음·오디오 업로드는 제공.
- 영상 입력은 **서비스 소유자 계정 1개에만 허용**, 영상 길이는 최대 **10분(600초)**. 서버 측 허용 계정 ID 확인이 필요하며 UI 버튼 숨김만으로 권한을 제한하지 않는다.
- 소유자 영상 업로드 시 **원본 영상 저장 / 압축 영상 저장(720p 목표) / 음성파일로 변환** 중 택1.
- **영상으로 저장하면 영상 보관함**, **음성으로 변환하면 음원 보관함**에 넣는다. 두 형태를 한 사용자 항목으로 묶지 않는다.
- 압축/변환은 우선 기기에서 실행하고, 서버 처리에는 비용이 들 수 있으므로 사전 안내와 정책 결정이 필요하다.
- 선택하지 않은 형태의 사용자용 미디어를 자동으로 중복 보관하지 않는다. 분석 임시 파일은 별도 관리한다.
- 기존 파일을 새 제한 때문에 소급 삭제하지 않는다. **현재 실제 코드의 MOV 음성 추출 방식은 별도 호환·개선 작업 필요.**

## 3. 레슨·녹음 삭제: 최신 확정 사항

- 레슨 삭제 시 **“연결된 녹음도 함께 삭제할까요?”** 확인한다.
- **기본값: 레슨만 삭제**, 녹음은 보관함에 그대로 둔다.
- **레슨+녹음 삭제**를 선택하면 연결 파일 목록을 보여주고 선택된 원본 미디어만 함께 휴지통으로 이동한다. 다른 곡/연습/레슨/공연에서 쓰는 녹음은 영향 범위를 별도로 안내하고 확인한다.
- 삭제한 레슨·녹음은 **삭제 시점부터 30일간 복구**할 수 있다. **30일을 넘기면 영구 삭제**한다.
- 복구 시 기존 식별자·관계·미디어 소유권을 유지한다. 이미 삭제된 외부 공유권한은 별도 복원 확인이 필요하다.
- 기존 **레슨비 수강권 차감·결제 원장**은 레슨 삭제를 이유로 삭제하지 않는다. 정산 조정은 별도 거래로 기록한다.
- 휴지통 데이터의 요금제 용량 반영 정책은 실제 상품 가격·운영비 검토 후 결정한다.
- 이 **사용자 직접 삭제 30일**과 **구독 만료 유예 29일**은 서로 다른 시계다.

## 4. 녹음 집계·개인 레슨

- 곡이나 연습에 연결하지 않은 녹음도 보관함 및 **녹음 횟수·전체 녹음 길이 통계**에 표시한다.
- **실제 연습 시간**에는 자동 합산하지 않는다.
- 레슨비 자동 차감은 유지하되, **중복 차감·완료 취소·결석/보강**에 대응하는 거래 원장을 사용한다.
- AI 곡 매칭은 **후보 추천 후 사용자 확인**한다. 이전에 확정한 곡을 AI가 자동 덮어쓰지 않는다.
- 공연·오디션 기록은 학생 1.0 계획에 두되, 오디션 고도화는 후순위다.

## 5. AI 분석 표시 정책 — 확정

- 음정·박자·음역·비브라토 등은 **실제 검증된 측정값과 추정값을 구분**한다.
- 기준음/기준 멜로디 없이 정밀한 음정 정확도·박자 점수를 사실처럼 보여주지 않는다.
- 호흡·발성 건강을 음원만으로 단정하거나 임상적으로 진단하는 것처럼 표현하지 않는다.
- 측정 수치, AI 해석, 추천 연습을 화면에서 분리하고 신뢰도·오류 가능성을 고지한다.

## 6. AI 실행 정책 — 방식 C 확정

- **기기에서 가능한 저비용 기초 분석**(길이, 파형, 간단 측정)과 **규칙 기반 연습 추천**은 자동/무료로 제공 가능하다. 기존 `app/practice-tips.js`를 재사용·검증한다.
- **서버에서 유료 추론이 필요한 전사·정밀 분석·AI 성장 리포트**는 사용자가 요청했을 때 실행한다.
- **일정 요금제 이상 유료 가입자**에게 서버 정밀 분석을 허용한다. 우선 **Plus/Pro 전용**을 권장한다.
- 서버 비용이 생기는 기능은 **사용자별 일간 요청 수, 월간 파일 수, 월간 분석 시간, 파일당 길이, 동시 실행 수, 서비스 전체 예산**으로 다중 제한한다.
- 묶음 요청은 한 번의 UI 요청으로 계산하되, 각 파일은 **월간 파일 수·분 사용량**을 따로 소비한다. 파일 10개를 1회 요청했다고 1파일로 계산하지 않는다.
- 실패/취소로 실제 처리하지 않은 부분은 과금·사용량에서 복구한다. 중복 클릭·재시도는 멱등 처리한다.

### 6-1. AI 사용량: 출시 초기 권장 가안 (비용 측정 후 변경 가능)

| 항목 | Free | Plus | Pro |
|---|---|---|---|
| 규칙 기반 연습 추천 | 무료(기기 분석값 활용) | 무료 | 무료 |
| 서버 정밀 분석 | 미제공 | 사용자 요청형 | 사용자 요청형 |
| **사용자별 하루 묶음 요청 수** | 0 | **3회** | **10회** |
| **요청 1회에 선택 가능한 파일 수** | 0 | **최대 3개** | **최대 10개** |
| **한 달 실제 분석 파일 수** | 0 | **30개** | **120개** |
| **한 달 서버 분석 가능한 음성 총 길이** | 0 | **120분** | **600분** |
| **분석 파일 1개당 최대 길이** | 0 | **10분** | **10분** |
| **사용자별 동시 서버 분석 작업 수** | 0 | **1개** | **2개** |

- 동시 작업 제한과 묶음 선택 한도는 다르다. 예: Pro가 10개를 선택해도 동시에 2개만 실행하고 나머지는 대기열.
- 시간·파일 수·일간 횟수 중 **어느 하나라도 한도에 도달하면 새 서버 분석 요청을 제한**한다.
- 분석이 필요할 때마다 이미 있는 전사/측정 결과를 재사용해 추가 비용을 최소화한다.
- '파일 1개'의 분석에 전사·추천이 함께 포함되면 중복으로 파일 수를 차감하지 않도록 **분석 번들 단위**를 정의한다.
- 이 표는 **운영 비용이 확보되지 않은 초기 추천값**이다. 기능별 실제 비용을 측정해 출시 전 재확정하고 요금제 화면에 표시한다.

### 6-2. 서비스 전체 AI 비용: 소규모 시범 운영 권장치

- AI 외부 API·분석 서버 **월 5만 원**을 **소규모 비공개 시험 운영의 임시 목표 예산**으로 설정한다.
- **70% 사용 시 알림**, **90% 사용 시 긴급 알림**, **100%에 도달하면 신규 고비용 AI 작업을 안전하게 일시 제한**하고 운영자에게 알린다. 기존 진행 작업은 중단 방식에 따른 데이터 유실 없이 마무리 또는 재시도 대기.
- 일간 갑작스러운 비용 증가를 막는 **1일 5천 원 이상 지출 알림·추가 승인 기준(가안)**을 둔다.
- **학생의 녹음·저장·재생·기본 연습 추천은 AI 예산 한도와 무관하게 계속 가능**해야 한다.
- 유료 상품을 공개 판매하기 전에는 실제 유료 가입자 수·수익·트래픽·결제 수수료에 맞게 **예산 및 약속한 이용량을 재산정**해야 한다. 5만 원은 상용 서비스 전체에 영구 적용할 숫자가 아니다.
- 별도로 **R2 저장료·요청 비용·미디어 전송량·메일 발송 비용**도 추적한다. 현재 가격·비용은 실제 청구 데이터로 검증한다.

## 7. 학생↔선생님 녹음 공유 — 2.0 정책

**제품 요구:** 학생이 업로드한 자료를 선생님이 **매 파일마다 요청하지 않고 폭넓게 볼 수 있어야 한다.**

다만 학생 개인 정보와 녹음은 기본 비공개이므로 **선생님 연결 시 학생이 해당 선생님에 대해 한 번 명시적으로 승인**하도록 한다.

권장 연결 화면:
> “이 선생님이 내 Vocalzip 녹음·영상 보관함을 볼 수 있도록 허용할까요?”
>
> [전체 보관함 공유] / [레슨에 제출한 자료만 공유] / [나중에 결정]

- **전체 보관함 공유**를 선택하면 **그 선생님에게만** 승인 범위의 기존 자료와 향후 업로드 자료가 자동 공유된다. 기존 자료 포함 여부를 화면에서 명확히 보여준다.
- 학생은 파일별 **공유 제외**, 해당 선생님에 대한 공유 범위 변경, 연결 종료와 접근 회수를 언제든 할 수 있다.
- 학생이 2명 선생님과 연결돼도 **선생님마다 별도로 동의**한다. 다른 학생·그룹 구성원에게 자동 공개하지 않는다.
- 선생님이 볼 수 있는 건 **수업·학습 관련 녹음·영상과 제출 자료**이며, 결제 정보·계정 정보·민감한 비공개 메모까지 일괄 노출하지 않는다.
- 선생님은 기존 파일을 다운로드·복제하지 않아도 스트리밍·구간 피드백·레슨 연결 등을 할 수 있게 한다. 다운로드는 별도 정책으로 제한한다.
- 학생용 1.0에는 선생님 계정과의 상시 연결 기능이 없으므로, 필요한 경우 유효기간이 있는 개별 재생 링크를 제공한다.

## 8. 학생 기록의 소유권과 선생님 수정 제안 — 확정

- **학생이 만든 곡·연습·레슨·미디어의 소유자는 학생이다.**
- 선생님은 **권한을 승인받은 범위**의 학생 녹음/기록을 가져와 수업에 연결하거나, 새 피드백·숙제·자료를 **추가 제안**할 수 있다.
- 선생님이 학생 기록의 제목·곡 연결·날짜·연습 내용 등을 고치고 싶으면 **수정 제안**을 작성한다. 학생에게 **승인 / 거절**을 제공한다.
- 학생 승인 전에는 학생의 원본 기록·원본 음원·소유권을 **덮어쓰거나 삭제하지 않는다**.
- 교사가 직접 올린 자료는 교사 소유 자료로 유지하고 학생에게 공유할지, 학생에게 사본·소유권을 넘길지 명시적으로 정한다. 무단 소유권 이전 금지.
- 누가, 언제, 어떤 내용을 제안했고 학생이 승인했는지 이력을 남긴다.
- 그룹 레슨은 **공통 수업 내용·공통 숙제만 참여자에게 공개**, 학생별 녹음·개인 피드백·수강료는 기본 비공개이다.

## 9. 오프라인 — 확정

- 오프라인에서 가능한 **로컬 녹음·기기 저장 파일 재생·기록 임시 작성**은 지원한다.
- 서버 AI·결제·아직 내려받지 않은 클라우드 미디어는 오프라인에서 이용 제한될 수 있다.
- 오프라인 데이터와 업로드 대기열은 **로그인된 사용자 계정별로 격리**한다. 계정 전환 시 타 계정 기록을 자동 병합하지 않는다.
- 앱이 강제 종료됐을 때에도 저장한 로컬 음원/메모가 가능한 범위에서 복구되도록 개발·실기기 검증한다.

- 학생 일반 업로드에서 영상은 당분간 미제공. 소유자 전용 영상 테스트는 플랜 판매 권한과 별도다.

## 11. 구독 취소/만료와 충분한 사전 고지 — 확정 방향

- 구독 **해지 버튼을 누른 날**이 아니라, **이미 결제한 유효기간이 끝난 시점**부터 용량 초과 유예기간을 계산한다.
- 유료 상품 **결제·갱신 화면**에서 만료 후 용량 제한, **29일 유예**, **30일 차 초과 미디어 정리 가능성**, 내보내기 방법을 반복해서 고지한다.
- 인앱·이메일 서비스 고지를 **유료기간 종료 7일 전 / 종료 당일 / 유예 14일 차 / 25일 차 / 29일 차 / 실제 정리 결과** 시점에 보내는 안을 기본으로 한다.
- 가입/최초 결제 때도 보관·삭제 정책을 명시한다. 주소 반송/발송 실패를 추적하고 앱 내 알림센터에도 동일 내용을 남긴다.
- 유예기간 중 사용자가 초과 파일을 선택해 삭제하거나 내보낼 수 있어야 한다. 실제 결제 복원·재구독이 확인되면 정리를 중단한다.
- **자동 영구 삭제는 법률·개인정보·약관·앱스토어 정책 검토 및 데이터 복구 가능성 검증 후 구현/적용 승인**한다.
- **사용자가 직접 삭제한 레슨/녹음의 30일 휴지통**과 **구독 만료 후 초과 용량 정리**는 서로 다른 정책이다. 하나의 기간으로 혼동하지 않는다.
- 광고·마케팅 메일이 아니라 **데이터 보관에 관한 중요한 서비스 알림**으로 설계하고 발송·열람 이력 및 개인정보 동의 근거를 관리한다.

## 12. 운영환경 검증 — 이번 확인 결과와 한계

### GitHub 소스에서 확인된 사항 (읽기 전용)

- `cloud-sync.js`에서 실제 서비스가 참조하는 Supabase 프로젝트 호스트가 존재한다.
- `r2-config.js`, `r2-worker/wrangler.toml`에 R2 Worker 연결 설정과 Supabase 프로젝트 참조가 있다.
- `supabase/tests/app-tables.sql`은 **테스트용 테이블/RLS 대역**, 운영 적용 상태의 증거는 아니다.
- 실제 Auth·RLS·Storage 정책, 배포된 Worker와 버킷 공개 설정, 비용, 이메일 발송 설정은 이 코드만으로 증명할 수 없다.

### 연결 가능한 운영 도구로 확인한 범위

- 현재 이 대화에 연결된 Supabase 프로젝트 목록에서 **Vocalzip 소스의 프로젝트와 일치하는 항목이 확인되지 않았다**. 연결된 다른 프로젝트 두 개는 현재 비활성 상태였다.
- 따라서 **Vocalzip 운영 DB의 실제 RLS·PK·Storage 정책을 조회했다고 주장하면 안 된다.** 운영 DB에는 조회·수정 어떤 SQL도 실행하지 않았다.
- 이 대화의 도구에서는 Cloudflare R2/Workers 관리 계정 연결을 확인하지 못했다. 따라서 버킷 정책·실제 Worker 배포 버전·비밀키 설정을 확인하지 못했다.
- 코드/설정에서 알려진 사실과 **실제 운영 상태 미검증**을 명확히 구분한다.

### 운영 검증 후속 작업 (Claude/Codex가 해당 계정 연결로 실행)

1. **Supabase: 읽기 전용** — `vocal_data`·`vocal_media` PK/인덱스·RLS, Storage `vocal-recordings` 정책, 함수·트리거, Auth 가입 공개 여부, 분석 작업/cron 설정 확인. 실제 데이터·시크릿은 출력하지 않는다.
2. **Cloudflare: 읽기 전용** — 현재 Worker 버전, JWT 검증 모드·시크릿 *존재 여부만*, 버킷의 공개 접근 차단, multipart 수명 주기, 저장량·요청량 점검.
3. **GitHub Actions** — 분석 워커와 R2 Worker 최근 빌드·실패·배포 경로, 시크릿 **이름의 존재만** 확인.
4. **실기기** — 본인 계정 말고 **테스트 계정 2개**, 실제 iPhone으로 로그인·계정 전환·녹음·업로드·재생·복구를 확인.
5. 결과를 경로·환경·검증 시각·증거와 함께 `docs/audit/`에 기록. 운영 수정은 별도 승인 절차.

**확인 못 한 운영 항목을 완료로 표시하지 말 것.**

## 13. Claude·Codex 개발 작업 유의

- 개발 중인 **계정 전환 보호 PR**의 자동 병합 방지·계정별 미디어 격리·미업로드 녹음 보존을 최우선으로 유지한다.
- 이전 계정의 기기 데이터는 새 계정에 자동 병합하지 않는다. 클라우드는 계정별 기준 원천, 기기는 오프라인·임시 저장·복구 역할이다.
- 새 정책에 따른 휴지통, 선생님 전체 공유, AI 비용 한도, 이메일 삭제 고지를 **기존 운영 코드에 승인 없이 즉시 반영하지 않는다**. PRD·DB 설계·테스트를 준비한 뒤 순차 반영한다.
- 선생님 공유/수정 제안은 **Release 2.0**, 서버 정밀 분석 과금과 상품화는 **Release 1.0** 범위로 취급한다.
