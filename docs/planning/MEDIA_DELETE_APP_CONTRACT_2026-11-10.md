# 불변 원본 삭제 앱 계약 — 2026-11-10

Phase 03/05·06/08의 P0 저장 정합성 후속. #248의 메타데이터 수정 연결 뒤, 기존 삭제 journal과 #232의 서버 prepare/commit을 연결한다. 새 서버나 두 번째 삭제 대기열을 만들지 않는다.

## 순서와 보존

1. 기존 최종 영구 삭제 확인 이후 호출되는 삭제 API를 사용한다. 새 UI·휴지통·일괄 삭제를 추가하지 않는다.
2. 새 앱 플래그 ON이면 서버의 mediaMode를 새로 확인한다. legacy만 기존 삭제 경로를 사용한다. paused/알 수 없음/연결 실패는 진행하지 않는다.
3. 기존 계정/로그인/파일 journal에 원본 key·6자리 UTC 수정 버전·크기·형식·ETag·요청 ID를 root 저장 전에 보존한다. 이름·후기·원본 바이트·토큰·서명 ticket은 보관하지 않는다.
4. root revision CAS로 파일 삭제 표식과 연결 해제를 확인한다. 레슨·연습 기록 본문 및 실제 연습 시간은 보존한다.
5. 정확히 같은 요청으로 Worker prepare ticket을 받아 계정/세션/원본/크기/형식/ETag/마이크로초 버전까지 검사한다. 서버 commit이 원본과 vocal_media를 처리한다. 클라이언트 raw DELETE/직접 vocal_media 삭제로 우회하지 않는다.
6. 성공 확인 뒤 인식 텍스트·목록 캐시를 정리한다. 이후 기기 파일을 조건부 삭제하고 기존 journal을 해제한다. 기기 파일 삭제 뒤 journal 해제만 실패했다면 원본을 다시 만지지 않고 해제만 재시도한다.

prepare/commit의 응답 유실은 같은 요청 ID로 다시 확인한다. 서버 행이 이미 없어도 journal의 원본을 재사용한다. 서버 삭제 이후 텍스트 정리가 실패해도 같은 요청으로 이어간다. 409를 최신 원본에 자동 재적용하지 않는다. 모드/전송 요청은 15초 제한이며 불명확한 결과는 미완료로 남는다.

## 경합과 호환

- 파일 수정과 삭제는 같은 Web Lock을 공유한다. 잠금 안에서 미완료 수정 여부를 다시 검사한다. 일반 root 쓰기는 기존 snapshot 잠금을 사용한다.
- 최초 삭제에서도 기기 파일 토큰을 먼저 보관하고 IDB 삭제 시 다시 확인한다. cloud cleanup 중 같은 ID의 새 파일이 생기면 보존하고 중단한다.
- object 필드가 있는 journal을 구형 어댑터/legacy 모드로 처리하지 않는다. 잘못된/다른 계정의 원본은 쓰기 전에 거부한다.
- object 없는 기존 삭제를 revision으로 조용히 전환하지 않는다. 기존 명시적 비교/재승인 절차가 필요하다.
- 이전 로그인에서 서버 원본 삭제 요청이 이미 만들어진 경우 root만 재승인해 이어가지 않는다. 원본 HEAD가 사라진 상태의 요청 소유권 이전/상태 조회 정책은 후속이며 현재는 보존·차단한다. legacy의 기존 재로그인 확인 절차는 유지한다.
- 새 플래그 OFF이고 미완료 작업이 없으면 기존 서비스 경로를 유지한다. 미완료 작업이 있으면 OFF를 이유로 raw 삭제로 우회하지 않는다.

## 검증 및 남은 관문

단위 검사: 정확한 target 보존, quota/응답 유실/행 없음/구형 우회 차단/손상 및 다른 계정 journal/이전 로그인 재승인 차단, 정밀 ticket/commit 응답과 계정 전환 검증.
브라우저 검사: 기존 앱 remove/resume 경로, prepare·commit 응답 유실 후 reload, root 이후 metadata 변경, 삭제 뒤 텍스트 정리 실패, 최초 삭제 도중 기기 파일 교체, legacy 회귀. 자동 검사 SHA/실제 결과는 PR에 기록한다.

운영 SQL/Worker 설치·계정 전환·실제 사용자 파일 변경은 하지 않는다. 새 동기화·서버 가드·이어올리기 플래그 OFF 유지. 악보·필기·스와이프 UI는 수정하지 않는다.
기존 고정 key/Supabase/PDF/영상/공연 자료 인수, 전체 writer 및 오래된 클라이언트, 원격 삭제 후 metadata 수정 초안 정리, 이전 세션의 원본 삭제 상태/재승인, 실제 PostgREST/R2·두 기기·iPhone/iPad 인수가 남았다. 이 작업만으로 Phase 전체 완료나 운영 활성화로 판단하지 않는다.
