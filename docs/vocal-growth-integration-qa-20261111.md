# VOCAL.zip 월별 성장 기능 통합 QA 게이트 — 2026-11-11

## 범위
이번 릴리스 후보는 기존 PR #270, #271, #272, #274, #275, #277, #280, #281을 순서대로 포함합니다.
이 문서는 **배포 승인서가 아닙니다.** 현재 운영 사이트 / Supabase Edge Function에는 미반영 상태입니다.

## 통합 중 발견하고 수정한 사항
- 이미 존재하던 `#/growth` 통계 화면이 새 성장 화면에서 덮어써지는 충돌: 새 보컬 성장 화면을 `#/vocal-growth`에 독립 등록하고, 하단 성장 탭만 새 화면을 가리키도록 수정. 기존 통계 라우트는 유지.
- 트레이닝, 연습실 과제, 곡이 없는 녹음이 월별 성장 통계에 섞이는 문제: 실제 곡으로 지정되었고 연습실 훈련 과제가 아닌 녹음만 그룹화. 계획 후보 및 전후 비교에도 **같은 필터** 적용.
- 신규 라우트, 로드 순서, 저장 컬렉션, 명시적 AI 호출 여부를 검사하는 통합 테스트 추가.
- Node 22를 사용하는 GitHub Actions의 JS 구문/모델 테스트 워크플로 추가.

## 현재까지 확인된 범위
- JavaScript 파일 파싱 및 모델 입력 기반 샘플 점검 통과.
- 25개 테스트를 별도 자바스크립트 검증 환경에서 실행하여 모두 통과(자동 CI 결과 아님).
- 실제 GitHub Actions 실행, 실계정 데이터와 Supabase 동기화, 브라우저 렌더링, iPhone Safari/PWA는 아직 미검증.
- AI 월간 종합 코치는 명시 버튼 사용 시 비용이 발생할 수 있으며 Edge Function은 운영에 별도 적용해야 함.

## 배포 전 반드시 확인
1. 각 PR 선후관계/충돌 및 스택 전체 변경사항 검토 후 통합 PR의 GitHub Actions 성공을 확인할 것.
2. iPhone Safari 및 홈 화면 PWA에서 로그인 후 홈 → 성장 → 이전 통계(#/growth), 월 선택, 계획 등록/종료, A/B 재생, 리포트 저장, 앱 재실행 후 복원을 확인할 것.
3. 실제 곡 녹음과 훈련 녹음이 통계에서 분리되는지 확인하고 동일 곡 비교가 전후 시점·곡 ID를 준수하는지 확인할 것.
4. 네트워크 끊김/복구, 다른 기기와 동기화, 계정 전환 중 분석, 파일 이동·삭제, 0건/대량 녹음, 15분 초과 파일을 확인할 것.
5. `vzip-nvidia-coach` Edge Function 코드를 별도 검토하고 **사용자 승인 후** 배포할 것. Secret/접근 통제/사용량 제한 및 HTTP 오류 확인.
6. API 요청은 버튼을 눌렀을 때만 발생해야 하고, 의료적 판단이나 악보 정답 음정으로 표현되지 않아야 함.
7. 운영 배포와 기존 데이터 마이그레이션은 사용자 배포 승인 이후에만 실시할 것.

## 통계 해석 가드
- 가까운 반음과의 cent 편차는 **악보의 정답 음정 오차가 아닙니다**.
- 전체 녹음 단위 지표가 특정 구간의 개선을 증명하지는 않습니다.
- MR/마이크 조건, 노래 및 가창 방식, 음원 길이가 달라지면 비교 신뢰도가 낮습니다.
- 목의 통증, 발성 건강, 성대 상태를 녹음만으로 판정하지 않습니다.

## 추가 수정: iPhone 녹음 및 재생 자원 회수
- 월 선택/연습 계획 화면 다시 그리기 시 음원 재생 및 임시 Object URL을 종료하도록 수정. 이전 화면의 음원이 계속 재생되는 문제 방지.
- 선택한 녹음 ID는 현재 로드한 계정의 곡 녹음 목록에 있는지 검사. 캐시된 다른 목록에 의존하지 않음.
- 기기 내 분석과 A/B 비교 대상에서 영상 파일 제외, 60MB 초과 파일은 선택 목록에서 제외해 지원되지 않는 디코딩 및 메모리 부담을 줄임.
- 재생·분석 안정성 검증 항목 1개 추가하여 총 25개 항목 코드 수준 확인 통과.

## 추가 점검: 월간 AI 결과 및 빈 달 접근
- 사용자가 성장 화면에서 월을 변경하는 동안 이전 달 AI 응답이 도착해도 현재 화면에 잘못 표시되지 않도록 렌더링 순번을 확인하게 수정.
- 과거 달에 분석된 곡 녹음이 없어도 현재 월과 이미 등록된 연습 계획의 해당 월을 선택할 수 있도록 수정.
- 월간 종합 코치 응답 완료 후 버튼의 이벤트 핸들러가 불필요하게 이전 화면 상태를 재구성해 호출을 반복하는 경로 제거.
- 테스트 총 25개를 JS 실행 환경에서 통과. GitHub Actions 실행 결과가 없으므로 CI 통과로 표기하지 않음.

## 추가 점검: 리포트·연습 목표와 파일 삭제/클라우드 병합
- 동기화 병합 시 `vocalPlanReports`, `monthlyGrowthReports`, `monthlyAiReports`, `practicePlans`, `dailyGoals` 컬렉션이 보존되고 같은 ID의 데이터는 `updatedAt`으로 충돌 해결되는지 확인.
- 녹음 파일을 삭제할 때 신규 계획의 `reviewRecordingId`가 남아 깨진 오디오를 참조하지 않도록 정리.
- 보관된 성장 리포트의 `beforeIds`/`afterIds`에서 삭제된 녹음 ID만 제거. 결과 측정값, 완료율, 원래 레슨·연습 기록은 변경하지 않음.
- 분리된 기기/클라우드 스냅샷의 결합, 동기화 충돌, tombstone에 의한 녹음 참조 부활 방지, 중복 보고서 병합 등의 **회귀 검증 5개 추가**. 총 **25개** 코드 수준 검증 통과.
- 운영 Supabase의 실제 저장 데이터나 사용자의 녹음을 수정하지 않았음. 실제 클라우드와 iOS 동기화 검증은 아직 미완료.
