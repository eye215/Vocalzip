# 대용량 영상: 음성 원본 보존 · 영상만 압축 (Issue #14)

## 확정 요구사항
- 1인 사용, Supabase 무료 플랜 유지.
- **오디오 스트림은 재인코딩하지 않는다**. 원본 오디오 코덱·샘플·채널·타이밍 보존이 최우선.
- 영상 스트림만 필요할 때 재인코딩한다. 원본은 압축 성공과 업로드 검증 전까지 삭제하거나 덮어쓰지 않는다.
- 목표 업로드 크기는 **45MB 이하** (50MB 서버 제한에 여유 확보).
- 45MB에 도달할 수 없거나 오디오 복사·호환 컨테이너 생성에 실패하면 품질을 강제로 낮추지 않고 실패를 명시한다. 분할 저장은 별도 후속 기능이다.

## 반드시 선행할 기술 검증
1. iPhone Safari 브라우저는 일반적으로 FFmpeg의 `-c:a copy`와 동등한 오디오 스트림 복사 + 영상만 재인코딩을 기본 API로 제공하지 않는다. MediaRecorder 재녹화는 음질 무손실을 보장하지 않는다.
2. 브라우저 FFmpeg WASM은 iOS 메모리·실행 시간·백그라운드 종료 위험이 크므로 200MB 실기기 성능을 검증하기 전 기본 경로로 채택하지 않는다.
3. 서버 변환을 선택한다면 Supabase Edge Functions의 실행 시간·메모리·요청 크기·임시 저장·비용 제한을 확인한다. 무료 플랜에서 200MB 처리 가능하다고 가정하지 않는다.
4. 원본 MOV/MP4의 비디오·오디오 코덱, 재생 길이, 오디오 바이트 수, 컨테이너 호환성을 확인한다. 오디오가 이미 45MB 이상이면 영상만 압축해도 목표 달성 불가.
5. 출력은 iPhone Safari 재생 가능 컨테이너와 코덱이어야 한다. 오디오 복사 불가 시 **오디오 재인코딩 없이 중단**한다.

## 구현할 UX
- 영상 선택 → 원본 크기/길이 표시 → '음질 유지하며 영상 압축' 선택 → 예상 가능 여부와 작업 진행률 표시.
- 영상만 압축하고 오디오를 그대로 복사했다는 검증 결과를 저장한다. 압축 결과 45MB 이하일 때만 기존 업로드 경로에 연결한다.
- 실패 시 '원본 오디오는 변경하지 않았고 원본 파일도 그대로 남아 있습니다'를 표시한다.
- 기존 50MB 이하 업로드, 기존 보관함, 녹음·레슨·숙제 데이터는 변경하지 않는다.

## 테스트/배포 기준
- 오디오 스트림의 패킷/디코딩 동등성 검증(가능한 코덱별), 출력 영상 재생/seek, 영상-음성 싱크 검증.
- iPhone Safari 200MB MOV/MP4 실기기 테스트, 메모리/발열/중단/저장 공간 부족 테스트.
- 45MB 미달 실패·오디오 호환성 실패·네트워크 중단 시 원본 보존 확인.
- **기술 검증과 실제 변환 코드가 없으면 업로드 제한을 해제하지 않는다.**
- 테스트 완료 전 main 병합·배포 금지.

## 현황
이 문서는 요구사항과 검증 계획이며 압축 기능 구현 완료를 뜻하지 않는다.
