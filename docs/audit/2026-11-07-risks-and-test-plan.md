## 1. 우선순위별 위험

### P0: 출시 전 반드시 해결 (데이터 노출 또는 유실)

**P0-1. 한 기기에서 계정을 바꾸면 이전 사용자 데이터가 새 계정에 합쳐집니다** (코드 확인)
- 로그아웃은 `signOut`과 `vzip_cloud_linked_user` 삭제만 합니다(`cloud-sync.js:510`). 기록, IndexedDB 녹음, 스냅샷은 그대로 남습니다.
- 다음 로그인 때 `showUser()`가 어떤 사용자든 `sync()`를 부릅니다(`cloud-sync.js:503`). `sync()`는 기기 기록을 그 계정의 원격 기록과 병합해 업로드합니다(`:48-72`).
- `ready`(연결 여부)는 자동 업로드 디바운스만 막습니다. 계정 단위로 걸러지는 것은 `performances`와 `songs[].repertoire`뿐입니다(`app/repertoire-model.js:42-47`).
- 녹음도 같습니다. `vzip:auth-changed` → `M.backupLocal()`(`app/media.js:360`)이 소유자 필드가 없는 기기 녹음을 **현재 계정**에 올립니다.
- 스냅샷에서 곡을 되살리는 `VZ.recoverSongs`(`app/core.js:294-316`, `app/app.js:12`)도 계정 구분 없이 동작합니다.
- 시나리오: 가족 공용 iPad에서 A가 로그아웃하고 B가 로그인합니다. A의 레슨, 숙제, 기기 전용 녹음이 B의 클라우드로 들어갑니다. B의 기록은 다음에 A가 로그인할 때 A 계정으로 갑니다.
- 운영 `vocal_media` PK가 전역 `id`(CI 대역과 같음)라면 이미 백업된 파일은 충돌 후 고아가 되고, 아니면 B 계정에 복제됩니다(미검증).

**P0-2. 녹음 중이거나 25MB 초과 녹음은 쉽게 잃습니다** (코드 확인)
- 녹음 데이터는 저장을 누를 때까지 메모리에만 있습니다(`app/media.js:467, 484`). 녹음 화면에 `beforeunload` 보호가 없습니다.
- iOS에서 탭이 다시 로드되거나 메모리 때문에 종료되면 녹음 전체가 사라집니다.
- 25MB 초과는 기기에 저장할 수 없습니다(`app/media.js:132-133`). 오프라인이거나 로그아웃 상태에서 긴 레슨을 녹음하면 내려받기 말고는 방법이 없습니다.
- `navigator.storage.persist()`를 호출하지 않습니다. Safari가 기기 전용 기록과 녹음을 지울 수 있습니다(Safari 정책은 미검증).

**P0-3. 운영 앱 테이블과 Storage 보안 설정이 저장소에 없습니다** (미검증)
- `vocal_data`, `vocal_media`, Storage 버킷 `vocal-recordings`의 DDL, PK, RLS, Storage 정책이 어떤 마이그레이션에도 없습니다. CI 대역만 있습니다(`supabase/tests/app-tables.sql:1-8`).
- Storage SELECT/DELETE 정책을 확인한 기록도 없습니다(`docs/후속개발_검증_2026-11-03.md:58-61`).
- 정책이 폴더 접두사를 검사하지 않으면 다른 사용자 객체에 접근할 수 있습니다.
- **운영에서 읽기 전용으로 확인하기 전에는 1.0 보안을 판정할 수 없습니다.**

### P2: 기술 부채 (확장성)

- **스키마 버전이 없습니다.** 엔터티 필드가 시간이 지나며 늘었고, 마이그레이션 코드가 없습니다(`app/core.js:10-15`).
- **전역 결합과 중복 코드가 많습니다.**
  - `window.vzip*`가 79곳에서 참조됩니다.
  - IndexedDB 열기 코드가 6곳 이상, MIME 표가 2곳, anon 키와 URL이 4곳에 중복돼 있습니다.
- **캐시 무효화 번호를 손으로 관리합니다.** `?v=`가 어긋나 있습니다(`audio-extract-worker.js:13`은 `media-date.js?v=3`, `index.html:44`는 `?v=4`).
- **런타임 CDN에 의존합니다.** supabase-js, tus, mediabunny를 받아오고 SRI가 없습니다. 오프라인이나 CDN 장애 시 로그인과 영상 가져오기가 막힙니다. 이번 감사 환경에서 13개 테스트가 바로 이 이유로 실패했습니다.
- **iOS 네이티브 포장을 가로막는 요소**
  - CDN 의존
  - 서비스 워커 의존(WKWebView 기본 미지원은 미검증)
  - CORS가 웹 출처로 고정됨(`r2-worker/wrangler.toml:12`, `vzip-song-stt/index.ts:9`)
  - SVG 아이콘만 있음
  - share_target은 iOS 미지원
- **R2 고아가 생기고 서버 정리가 없습니다.** 확정 실패 객체는 한 기기의 `vzip_r2_orphans_v1`에만 기록됩니다. 중단된 multipart 정리는 R2 수명 주기 규칙에 기대는데, 이 규칙은 미검증입니다.
- **서버 쪽 소소한 설정**
  - 분석 워커가 TLS `rejectUnauthorized:false`로 DB에 접속합니다(`worker/analysis-worker.mjs:362`).
  - `vzip_wake_worker`가 `search_path=public`입니다.
  - Worker JWT 검증에서 `aud`를 확인하지 않습니다.
- **이력 저장 증가**: `vocal_history`가 0.9초 자동 동기화마다 전체 payload를 저장합니다. 3일 이내 증가량을 확인하지 않았습니다.
- **오래된 파일**: 쓰이지 않는 파일(`library-growth-ux.js`, `ux-layout.js`, `glass.css`)과 legacy 전용 스크립트 18개가 남아 있습니다.
- **정산 화면 HTML 오류**: `billing/index.html:14`의 `<option>` 태그가 잘못돼 있습니다.

## 3. 운영 검증 전제 조건 (소유자 권한 필요, 모두 읽기 전용)

1. **Supabase SQL Editor에서 읽기 전용으로 조회합니다.** 결과에는 개인 데이터가 없고 구조만 나옵니다.
   - `vocal_data`, `vocal_media`의 PK, 인덱스, RLS 정책: `pg_indexes`, `pg_policies`
   - `storage.objects`의 `vocal-recordings` 정책
   - 적용된 함수와 트리거 목록, `cron.job` 목록
   - Auth 설정: 가입 공개 여부, 익명 로그인 여부
2. **Cloudflare를 확인합니다.**
   - 배포된 Worker 버전과 저장소 `r2-worker/src/index.js`가 같은지
   - `SIGNING_SECRET`, JWT 모드가 설정됐는지(값은 보지 않음)
   - R2 버킷 공개 접근이 꺼져 있는지
   - 미완료 multipart 수명 주기 규칙이 있는지
3. **GitHub를 확인합니다.**
   - Actions Secrets에 이름만 있는지(값은 보지 않음)
   - `analysis-worker` 최근 실행 기록과 비용
4. **OpenAI 사용량 대시보드**에서 서버 STT 지출 추이를 봅니다.
5. **테스트 전용 Supabase 계정 2개와 실제 iPhone 1대**를 준비합니다. 실사용 계정이나 개인 녹음은 쓰지 않습니다.
