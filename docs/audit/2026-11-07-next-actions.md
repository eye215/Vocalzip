# Phase 01 다음 작업 제안 (2026-11-07)

> 이 문서는 **제안**입니다. 기간 추정은 넣지 않았습니다. 운영 데이터, DB, 미디어를 바꾸는 작업은 모두 소유자 승인 후에만 합니다. 근거는 [위험과 테스트 계획](2026-11-07-risks-and-test-plan.md)에 있습니다.

## 0. 원칙
- 각 PR은 하나의 위험만 고치고, 회귀 테스트를 함께 넣습니다.
- 기존 저장 형식(`vocal-zip_mvp_v1`, `vocalzip_media_v1/recordings`, `vocal_data.payload`, `billing/`)은 **추가만** 하고 바꾸거나 지우지 않습니다.
- 지우기는 막기보다 되돌릴 수 있게 만듭니다. 기존 데이터를 일괄 수정하는 마이그레이션은 하지 않습니다.
- 운영 확인은 읽기 전용 조회로 먼저 합니다(§1).

## 2. 가장 작은 안전한 PR 순서

### PR-1 (P0) 계정 전환 보호
- **상태**: 구현과 자동 테스트 완료(브랜치 `claude/clever-cerf-7yevge`), main 미병합, 실기기 미확인.
- **변경**
  - 로그인 시 `vzip_cloud_linked_user`가 **다른 계정**을 가리키면 자동 병합과 `backupLocal`을 멈춥니다. 대신 "이 기기에 다른 계정의 기록이 있어요"라는 선택 화면을 띄웁니다: 이 계정에 합치기 / 이 기기 기록은 그대로 두고 클라우드만 보기.
  - 기기 녹음에 `ownerId`를 **추가로** 기록합니다(새 저장분부터). 기존 레코드는 지우지도 바꾸지도 않습니다.
  - `recoverSongs`는 같은 계정 스냅샷만 씁니다.
- **완료 조건(자동 테스트)**
  - A 기록·녹음 → 로그아웃 → B 로그인 → B의 `vocal_data` upsert payload와 업로드 요청에 A의 ID가 0개입니다.
  - A 재로그인 시 A 데이터가 그대로 있습니다.
  - 처음 로그인(연결 기록 없음)은 지금처럼 병합됩니다.
  - 기존 테스트가 모두 통과합니다.
- **완료 조건(실기기)**: 공용 기기 시나리오(테스트 계정 2개).

### PR-2 (P0) 녹음 유실 막기
- **변경**
  - 녹음 중 이탈 경고(`beforeunload`, 라우트 가드 확인)를 넣습니다.
  - `navigator.storage.persist()`를 요청합니다.
  - 녹음 조각을 IndexedDB에 임시로 쌓아 탭이 죽어도 복구할 수 있게 합니다(새 저장소를 **추가**합니다).
  - 25MB 초과·로그아웃 상태 정책은 O-3(e) 결정에 따릅니다.
- **완료 조건**
  - 녹음 중 새로고침 → 재방문 시 "복구할 녹음이 있어요"가 뜨고 저장하면 원본 길이와 같습니다(Chromium 가상 마이크).
  - iPhone에서 녹음 중 화면 잠금과 탭 종료를 실기기로 확인합니다.

### PR-3 (P0/P1) 운영 스키마를 저장소에 기록
- **변경**: O-1 결과로 `supabase/schema/` 아래에 **현재 운영과 똑같은** `vocal_data`, `vocal_media`, Storage 정책 DDL을 문서로 기록합니다. 운영에 실행하지 않습니다.
  - 차이가 있으면 별도 승인 후 고치는 마이그레이션을 제안합니다.
  - CI 대역(`supabase/tests/app-tables.sql`)을 운영과 맞춥니다.
- **완료 조건**: 기록한 DDL로 만든 일회용 DB에서 다른 사용자 행과 객체에 접근할 수 없음을 SQL 테스트로 증명합니다.

### PR-4 (P1) 삭제와 동기화 정합성
- **변경**
  - `M.list`가 `deleted.media`를 거릅니다.
  - `deleteCloudMedia`는 행을 먼저 표시(또는 삭제)하고 바이트를 나중에 지우며, 실패하면 다시 시도합니다.
  - legacy 삭제와 편집은 `VZ.change` 규칙을 따르게 하거나, `legacy.html`을 읽기 전용으로 바꿉니다(제품 결정).
- **완료 조건**: §2.2의 해당 회귀 테스트가 통과하고, 기존 미디어 삭제 테스트가 통과합니다.

### PR-5 (P1) 비용과 용량 상한 (서버)
- **변경**
  - 서버 STT 계정별 하루 상한을 둡니다(기존 `vzip_song_stt_*` 재사용). 아니면 허용 목록을 워커에도 적용합니다.
  - R2 Worker `complete`에서 실제 크기를 확인하고 사용자별 총량 상한을 둡니다(값은 O-3, Phase 20에서 결정).
- **완료 조건**: 상한을 넘는 작업은 비용 없이 `review`나 `skipped`로 남는다는 것을 워커 테스트로, 413을 Miniflare 테스트로 확인합니다. 운영 적용은 별도 승인 후 합니다.

### PR-6 (P1) 문구와 문서 바로잡기 (코드 동작 변경 없음)

- **완료 조건**: 문서마다 코드 경로 근거를 달고, UI 문구 테스트를 갱신합니다.
