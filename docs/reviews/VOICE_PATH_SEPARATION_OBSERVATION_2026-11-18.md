# 소리 길 원본의 읽기 전용 AI 분리 관찰

진단 11의 정확한 원본에서 page/Worker 10 및 MR 7의 실패를 서버에서도 재현했다. 개별 채널·48kHz/8kHz decode·기존 음정 가이드·100Hz high-pass로 해결되지 않았다. 가이드의 무성 구간 110개에서도 기존 0.2 PHAT 기준을 통과하는 MR 파형은 없었다. 음정 가이드의 jumps/min은 약 71로 비교용 기준 15를 초과했다. 0.879의 검출 일관성만 보고 0.88 기준을 낮춰 해결할 수 있는 문제가 아니다.

기존 Demucs 4.0.1 / htdemucs / CPU 구성을 동일 원본에 읽기 전용으로 실행해 분리 후 실제 음정 검출 상태와 처리 비용을 관찰한다. 기존 분리 Worker나 분석 결과를 수정하지 않고 독립된 수동 도구를 사용한다. 운영 DB는 읽기 전용 트랜잭션이며 원본·분석·큐·스키마를 쓰지 않는다. 파일 선택은 기존 바이트 수·월·단일 소유자/곡·중복 바이트 동일성 검사를 재사용한다.

원본 읽기와 파생 WAV 처리에는 격리된 runner의 임시 디렉터리만 사용하며 성공·실패 후 삭제한다. 실제 미디어·소유자·곡 이름·원본 경로·곡선·분리 음원·오류 상세는 로그·GitHub 파일·아티팩트로 남기지 않는다. 보고는 모델/입력 크기/초/측정 신뢰도/처리 시간만 허용한다. 자동 테스트에는 가짜 데이터와 separator stand-in만 사용한다. 이 자동 테스트는 실제 Demucs 품질 검증을 의미하지 않는다.

이 도구는 비교 화면의 기능 수정이 아니며 실제 관찰이 끝나기 전에는 AI 분리로 해결됐다고 판단하지 않는다. 이후 앱 연결이 필요할 경우 MR 제거와 AI 분리를 구분하고 분리 흔적에 따른 제약을 표시해야 한다. 실제 iPhone Safari는 미검증이다.
