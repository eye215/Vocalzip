# #139 플로팅 녹음 홈 — 원본 HTML 직접 연결

## 원본

사용자 지정 파일: design-handoff-20261108-lavender-home/Vocalzip_Floating_Record_Home.html.
원본 blob: b4ad1520615f1cae216393239679657779389d06. 별도 배포 폴더에 같은 blob을 넣으며 원본 전달 브랜치는 수정하지 않는다.
#139 업로드 진행 중 최신 head도 확인했고 지정 HTML blob은 같았다.

## 구현

배포용 HTML을 fetch하고 DOMParser로 읽는다. 원본 루트 노드를 그대로 복제하고 원본 스타일10개를 순서대로 적용한다.
원본 미리보기 스크립트·모의 녹음 dialog·toast는 실행하거나 앱에 넣지 않는다.
홈을 Shadow DOM으로 격리하여 기존 전역 CSS에 의해 HTML 모양이 바뀌지 않게 한다.
외부 폰트 CDN import만 기존 번들 Pretendard 폰트로 대체한다.
이전 approved-home.css와 별도 홈 토큰은 실제 홈 엔트리에서 로드하지 않는다. 과거 파일은 이력으로 남긴다.

정상 상태의 HTML 구조·클래스·SVG·색·그라데이션·4개 내비·고정 플로팅 버튼을 다시 작성하지 않는다.
동작 연결은 텍스트·체크 상태·ARIA·이벤트를 바인딩하는 방식이다.

## 기존 기능 매핑

| 원본 영역 | 실제 연결 |
| --- | --- |
| 녹음 시작 | 기존 #/record |
| 홈/내 곡/보관함/일정 | 기존 #/home, #/songs, #/library, #/calendar |
| 레슨·무대 | 선택한 기존 레슨/공연 ID의 상세 |
| 주간 제목 | 기존 성장 화면 |
| 최근 곡 | 기존 곡 상세 및 songId를 미리 선택한 VZ.practiceSheet |
| 레슨노트·연습기록 | 기존 레슨 목록·연습 기록 |
| 목표 | 기존 M.setGoal / VZ.change, 실패 복원 |
| 목표 설정 | 기존 목표·주간 계획 레이어 |
| 알림·프로필 | 기존 기능 |

미디어 메타데이터로 최근 곡을 보완할 때 곡 영역만 갱신해 목표 목록·스크롤을 재생성하지 않는다.
HTML 로드 실패 시 기록을 건드리지 않고 재시도를 제공한다.
홈 밖의 기존 전역 내비와 화면은 유지한다. 새4개 메뉴는 홈 HTML에 적용한다.

## 데이터

주간 수치·달성률·분·D-day·연속일·목표 완료 개수는 기존 모델과 날짜 유틸리티를 재사용한다.
0분/100% 미만/100~120%/120% 초과/미래를 구분하며 현재 요일명과 링을 유지한다.
일일 목표 미설정은 미설정으로 설명하고0으로 나누지 않는다.
순수 디자인 예시의 합계가 맞지 않는 원본 수치를 실제 데이터에 복제하지 않는다.

## 기능상 보완만 적용

- 원본의 시각38px 공연 행은 기존 검수 기준에 따라 실제44px 이상으로 유지한다.
- 키보드·접근성 이름·포커스 표시와 동일44px 조작 영역.
- 긴 텍스트·큰 글자에서 겹침·잘림을 막는 최소 크기·줄바꿈·상대 행간.
-900개 등 많은 목표만 내부 스크롤. 일반3개 목표는 원본 일반 흐름 유지.
- 오늘 실적이 있으면 해당 원의 색 위에 오늘 링을 함께 표시한다.
- 실제 앱 외곽의 기존 헤더/네비를 홈에서 숨겨 원본 네비와 겹치지 않게 한다.

## 자동 검증

원본 배포 파일의 Git blob hash 및 원본 스타일10개·SVG를 비교한다.
320/390/430px, 스크롤 전후 플로팅 고정 위치·내비와12px 분리·44px 터치·마지막 목표 가림을 검사한다.
실제 데이터 보존, 체크 저장/새로고침/실패 복원/900개, 날짜·달성률 경계·요일·미래, 빈 상태, 긴 내용·200% 글자, 기존 각 화면·선택된 곡 연습 진입을 검증한다.
원본 HTML과 같은 모듈의 데이터 연결 화면을390px로 나란히 캡처한다.
구버전 JPEG·구버전 레이아웃을 새 시안의 증거로 사용하지 않는다.

결과는 PR #135 최신 커밋과 CI에 기록한다. 검증 전 완료로 표시하지 않는다.
