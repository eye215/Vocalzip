# Phase 10-1 구조 점검 (v0.6)

점검 방법: 실제 앱을 iPhone 크기(390×844, 터치)로 띄워 17개 화면을 차례로 열고, 화면마다 아래 항목을 자동으로 측정했어요.
- 44pt 미만 터치 대상
- 가로 넘침
- 글자 크기 종류
- 기본 select 사용

## 화면 구성 (17)

| 탭 | 화면 |
|---|---|
| 홈 | 홈 |
| 내 곡 | 내 곡, 곡 상세 (전체·가사·악보·레슨·연습·공연), 녹음 비교 |
| 녹음 | 녹음, 음원 보관함, 기존 자료 가져오기, 저장 공간 관리, 업로드 확인, AI 곡 추천 |
| 캘린더 | 캘린더, 레슨 목록·상세, 숙제 |
| 성장 | 성장, 보컬 분석 |
| 설정 | 설정 (홈 오른쪽 위) |

레이어는 공통 바텀시트(`VZ.sheet`) 하나로 통일돼 있어요. 확인 창도 `VZ.confirm`으로 시트예요.

## 발견한 문제

| # | 문제 | 측정 | 조치 |
|---|---|---|---|
| 1 | 44pt 미만 터치 대상 | 세그먼트 버튼 40px, 칩 36px, 캘린더 정렬 28px, 숙제 버튼 34~36px, 설정 접기·로그아웃 36px | 10-1 PR: 44px로 키우거나, 보이는 크기는 그대로 두고 터치 영역만 44px로 |
| 2 | 시트가 열려도 뒤 화면이 스크롤됨 (iOS) | `body{overflow:hidden}`은 iOS Safari에서 효과가 없음 | 10-1 PR: body 고정 잠금, 닫으면 원래 위치 복원 |
| 3 | 키보드가 시트 입력칸을 가림 | visualViewport 높이를 쓰지 않음 | 10-1 PR: 키보드 높이(`--kb`)만큼 시트를 올림 |
| 4 | 브라우저 기본 확인창 2곳 | 화면 나가기 경고, 예전 사본 삭제 | 10-1 PR: 앱 팝업(`VZ.confirm`)으로 교체 |
| 5 | 곡 선택이 기본 휠 | 곡 200개면 휠로 찾기 어려움. 곡 select가 7곳 | 10-1 PR: 검색 가능한 곡 선택 시트 (`app/picker.js`) |
| 6 | 작은 글자 | 11px 설명 글자 3곳 (분석 카드·업로드 집계·평가 추이) | 12px로 통일. 탭바(11px)와 차트 눈금은 iOS 관례대로 둠 |
| 7 | 보관함 일괄 작업 없음 | 파일 여러 개를 한 번에 곡 지정할 수 없음 | 10-3 다음 PR: 선택 모드 + 하단 작업 바 |
| 8 | 측정값 설명 부족 | 성장·분석 화면의 cent·비브라토 수치 설명이 없음 | 10-3 다음 PR: 지표 설명 시트 |

- 가로 넘침은 17개 화면 모두 없음(scrollWidth 390).
- 콘솔 오류도 없음.
