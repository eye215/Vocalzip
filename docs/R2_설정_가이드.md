# VOCAL.zip 미디어 저장소 (Cloudflare R2) 설정 가이드

이 문서는 직접 하셔야 하는 설정만 순서대로 정리했어요. 코드(`r2-worker/`)는 이미 준비돼 있어요.
설정이 끝나기 전에는 앱이 **지금처럼 기존 저장소(기기 + Supabase)** 를 그대로 써요. 아무것도 자동으로 옮기지 않아요.

## 구조 한눈에 보기

```
브라우저(VOCAL.zip) ──(Supabase 로그인 토큰)──▶ Cloudflare Worker ──▶ R2 버킷
```

- R2 비밀 키는 어디에도 쓰지 않아요. Worker가 버킷에 직접 연결(바인딩)돼서 키가 필요 없어요.
- 브라우저는 Worker 주소만 알아요. Worker는 Supabase 토큰을 확인하고, 사용자마다 자기 폴더(`u/<사용자 id>/…`)에만 접근하게 해요.
- 재생할 때는 Worker가 1시간짜리 서명 링크를 만들어 줘요. 구간 재생(Range)을 지원해서 긴 파일도 처음부터 다 받지 않아요.

## 0. 비용 확인 (먼저 결정해 주세요)

R2를 켜려면 Cloudflare 계정에 **결제 수단 등록**이 필요해요. 아래 무료 한도 안에서는 요금이 나오지 않아요.

| 항목 | 월 무료 한도 | 초과 시 |
|---|---|---|
| 저장 용량 | 10GB | GB당 약 $0.015 |
| 업로드·목록 요청 (Class A) | 100만 회 | 100만 회당 $4.50 |
| 다운로드 요청 (Class B) | 1,000만 회 | 100만 회당 $0.36 |
| 데이터 전송 (egress) | 무료 | 무료 |
| Worker 요청 (무료 플랜) | 하루 10만 회 | 유료 플랜 필요 |

> 요금은 바뀔 수 있어요. 켜기 전에 Cloudflare R2 가격 페이지에서 한 번 더 확인해 주세요.

## 1. Cloudflare 계정과 R2 켜기

1. https://dash.cloudflare.com 에 가입하거나 로그인해요.
2. 왼쪽 메뉴 **R2 Object Storage** → **Purchase R2 / Get started**. 결제 수단을 등록하면 무료 한도로 시작돼요.

## 2. 버킷 만들기

1. **R2 Object Storage → Create bucket**
2. 이름: `vocalzip-media` (다른 이름을 쓰면 `r2-worker/wrangler.toml`의 `bucket_name`도 같이 바꿔 주세요)
3. Location: Automatic, Storage class: Standard → **Create bucket**
4. 버킷의 **Public access는 켜지 마세요.** 공개 주소가 없어도 Worker가 대신 전달해요.

## 3. Worker 배포 준비 (컴퓨터 터미널에서)

Node.js 20 이상이 필요해요.

```bash
cd Vocalzip/r2-worker
npm install
npx wrangler login
```

브라우저가 열리면 Cloudflare 계정으로 허용해 주세요.

## 4. 비밀 값 넣기

### 4-1. 재생 링크 서명용 값 (필수)

아무도 모르는 긴 임의 문자열이면 돼요. 아래 명령으로 만들 수 있어요.

```bash
openssl rand -base64 48
```

```bash
npx wrangler secret put SIGNING_SECRET
```

물어보면 방금 만든 문자열을 붙여 넣어요. 이 값은 Cloudflare 안에만 저장되고, 코드나 앱에는 들어가지 않아요.

### 4-2. Supabase 토큰 방식 확인

Supabase 대시보드 → 프로젝트 `chxnbtiyuyhiywzeshis` → **Project Settings → JWT Keys** 를 열어요.

- **현재 키가 ECC (P-256) / RSA 같은 "JWT Signing Keys"** 라면 할 일이 없어요. Worker가 공개 키(JWKS)를 알아서 받아요.
- **"Legacy JWT Secret"을 쓰고 있다면** (현재 키가 HS256) 그 비밀 값을 Worker에 넣어 주세요.

  ```bash
  npx wrangler secret put SUPABASE_JWT_SECRET
  ```

## 5. 배포

```bash
npx wrangler deploy
```

끝나면 `https://vocalzip-media.<내 서브도메인>.workers.dev` 같은 주소가 나와요.

확인:

```bash
curl https://vocalzip-media.<내 서브도메인>.workers.dev/health
```

`{"ok":true,"bucket":true}` 가 나오면 성공이에요.

## 6. 앱에 연결 (저에게 주소만 알려 주세요)

5번에서 나온 **Worker 주소**만 알려 주시면 앱 설정(`r2-config.js`)에 넣어 배포할게요.
Worker 주소는 비밀 값이 아니에요. 공개돼도 로그인 토큰 없이는 아무것도 할 수 없어요.

연결 후 달라지는 점:

- **새로 가져오거나 녹음한 파일**은 R2에 저장돼요. 기록(이름·날짜·곡·레슨·연습 연결)은 지금처럼 Supabase에 남아요.
- **기존 파일은 그대로** 있어요. **설정 → 저장 공간 관리 → "R2로 옮기기"** 를 누를 때만 옮겨져요. 파일 id가 그대로라서 레슨·연습·곡 연결이 끊기지 않아요.
- 옮긴 뒤에도 예전 클라우드 사본은 남아 있어요. 재생을 확인한 다음 **"예전 클라우드 사본 정리…"** 를 눌러 승인해야만 지워져요. 지우기 직전에 R2 사본의 크기를 다시 확인해요. 이 기기에 저장된 사본은 지우지 않아요.

## 앱 주소를 바꾸거나 추가할 때

`r2-worker/wrangler.toml` 의 `ALLOWED_ORIGINS` 에 쉼표로 추가하고 다시 `npx wrangler deploy` 해요.
여기에 없는 사이트에서 오는 요청은 Worker가 거절해요.

## 되돌리기

- 앱 설정의 Worker 주소를 비우면 즉시 기존 저장소 방식으로 돌아가요.
- R2에 이미 올라간 파일은 지워지지 않아요. 필요하면 R2 대시보드에서 직접 확인할 수 있어요.

## 로컬 테스트 (선택)

Cloudflare 계정 없이 컴퓨터에서 Worker를 검증할 수 있어요.

```bash
cd r2-worker && npm install && npm test
```

메모리 안의 가짜 R2로 업로드·구간 재생·권한·서명 링크를 확인해요.
