# 파일 정보 수정 앱 브리지 — 2026-11-10

기존 #245 서버 CAS 계약을 기존 메타데이터 수정 API에 연결한다. 악보/스와이프/필기 인식 UI 및 다른 개발자의 함수를 유지한다. 운영 SQL/Worker 적용·계정 전환·새 플래그 활성화는 하지 않는다.

## 연결 범위

- 새 동기화 앱 플래그가 OFF이고 미완료 수정이 없으면 기존 경로를 유지한다. ON에서는 서버 모드를 매 작업마다 확인한다. 확인된 legacy만 기존 DML을 사용하고 revision은 새 CAS로 보낸다. 모드 불명·paused·전송 실패·충돌·중단된 기존 요청에는 DML로 우회하지 않는다.
- 보관함 목록은 계정/세션·서버 원문 버전에 묶인 메모리 참조를 붙인다. 메타데이터 원본을 폼의 로컬 병합본으로 교체하지 않는다. 목록/캐시의 시간대를 UTC로 정규화하되 6자리 마이크로초를 보존한다. 계정 변경 시 참조를 지우며 현재 목록 전체의 기준을 유지하고, 메모리에는 목록 크기+500개(최소 2,000개)까지만 보관한다. 큰 목록의 앞쪽 항목이 목록 작성 중 바로 만료되지 않게 한다. 오래되거나 누락된 참조는 새 목록 확인을 요구한다.
- 기존 일반 편집과 곡 지정에 연결한다. 표시 당시 버전 하나로 저장하며 충돌 뒤 최신 값에 자동 재적용하지 않는다. 폼에서 실제 바꾸지 않은 로컬 값은 cloud patch에 넣지 않는다. 자동 제목은 기존 media-naming 규칙과 이전 제목 메모를 재사용한다.
- 새 저장 방식의 수정에는 이름/자동 제목 상태·곡/날짜/실제 기록 시각·별점·후기만 허용한다. 원본 키·바이트·형식·크기·ETag는 변경할 수 없다. created는 R2 업로드 시각이 아닌 기존 사용자가 편집하는 녹음 시각이며 recordedDate와 함께 바꾼다.
- 목록에서 읽은 기준이 없는 기기 전용 변경은 새 모드에서 클라우드에 자동 덮어쓰지 않는다. 기기의 입력은 기존 로컬 파일에 남고 사용자에게 실패를 표시한다. 저장소 이동·구 저장소 정리는 새 원본 인수 계약까지 물리 작업 전에 거부한다.

## 미완료 요청

`media-metadata-edits.js`는 계정/파일별 localStorage 원장에 정확한 요청 ID·원본 키·기대 버전·patch·입력 의도를 POST 전에 보관한다. 토큰·서명 URL·원본 파일은 보관하지 않는다. 공유 Web Lock으로 같은 파일의 탭 작업을 직렬화하며 지원되지 않는 브라우저에서는 revision 쓰기를 거부한다. 계정당 100건/1MiB 및 항목당 64KiB를 넘으면 전송 전에 멈춘다.

같은 폼에서 같은 입력으로 저장을 다시 누르면 기존 요청을 확인한다. 다른 입력이 이미 미완료 요청을 덮어쓸 수 없다. POST 응답 대기는 15초로 제한하며 불명확하면 입력을 유지한다. 새로고침 뒤에는 명시적인 결과 확인 API로 같은 요청을 재사용한다. 성공 응답이 검증되어야 원장을 제거하고 로컬 완료를 반영한다. 원장 제거 실패도 미완료로 남겨 같은 요청을 재확인한다.

- `vzipPendingMediaEdits()`: 현재 계정/로그인의 보관된 작업 조회.
- `vzipCloudMediaRetryEdit(id)`: 같은 로그인에서만 원래 요청 재확인.
- `vzipCloudMediaDiscardEdit(id,{confirmed:true,requestId})`: 충돌/이후 수정이 확인된 입력을 사용자가 확인하고 폐기. 응답 불명 pending은 먼저 결과 확인을 요구한다.

409는 충돌 상태, superseded는 이후 수정 상태로 남긴다. 이때 원래 입력과 최신 서버값을 조용히 교체하거나 성공으로 표시하지 않는다. 다른 로그인은 예전 세션의 요청을 자동으로 다시 보내지 않는다. 미완료 수정이 있는 파일의 로컬 삭제는 먼저 결과 확인을 요구한다.

## 남은 활성화 조건

복구 API는 개발 연결이며 새 복구 UI를 추가하지 않았다. 이전 로그인의 저장 결과 조회/명시적 재승인, 충돌 검토 화면, 원격 삭제 이후 복구 입력 정리, 삭제 prepare/commit 브리지·전체 writer/기존 원본/오프라인 인수는 후속이다. 이 조건 전에는 기능을 켜지 않는다.

브라우저·VM·격리 PostgreSQL/Miniflare 자동 검사는 실제 Supabase PostgREST/Vault·Cloudflare R2·두 실기기·iPhone 인수를 대신하지 않는다. 검증 SHA/결과와 기존 회귀 실패는 PR에 기록한다.
