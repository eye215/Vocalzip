# 노래 연습실 첫 버전 검증

기준 소스: `eye215/Vocalzip` main `3fb876b8401df3675bf12c429cc3da0944d8d74c`.

## 구현과 연결

- 홈의 오늘 목표 위에서 `#/practice-room`으로 진입한다. 기존 네 개 하단 메뉴는 유지한다.
- 공통 토큰·번들 Pretendard·R20 카드·52px 주 버튼을 재사용한다.
- 녹음 1개, A/B 녹음과 비교 회고, 짧은 답변 제출을 공유한다.
- 전체 로드맵, 기준음/선율/리듬/구절 연결, 제출·결과·복습/응용 추천, 제출 이력을 제공한다.
- 실제 제출의 타이머 시간과 명시적으로 고른 다음 목표만 기존 practices/dailyGoals에 연결한다. 기존 데이터는 수정하지 않는다.
- 예시 자료는 실제 연습 시간·목표·클라우드에 쓰지 않는다. 실제 녹음은 기기에 먼저 저장하고 R2 업로드 후 `vocal_media`에 등록한다. 회고·답변·결과는 기존 `practices`의 `practiceRoom` 필드로 저장해 로그인 시 Supabase `vocal_data` 동기화에 포함한다. 업로드 실패 시 기기 녹음을 남기고 재시도한다.

## 실행한 검증

- `npm run test:syntax`: 통과. practice-room/app.js도 기존 검사 범위에 추가했다.
- `node --test tests/practice-room-model.test.cjs`: 4개 통과. 초 단위 보존, 중복 방지, 예시 자료 제외, 기존 데이터 보존, 잘못된 입력 차단.
- 앱 브라우저의 로컬 전용 fixture에서 홈 → 연습실 → 녹음 파일 제출 → 기준음 분석 → 다음 목표 저장 → 기존 홈에서 해당 목표 확인.
- 합성 C4 WAV를 실제 파일 선택으로 제출해 기준 음정 차이 0 cent와 응용 추천을 확인. 이는 알고리즘 연결 검사이며 사람 노래에 대한 정확도 검증이 아니다.
- 예시 녹음의 복습 분기, 실제 기록 제외, 두 녹음과 회고 제출, 텍스트 제출, 새로고침 후 녹음·답변 복원 확인.
- 390px 화면 시각 확인, 320px에서 본문 scrollWidth/clientWidth 동일(281px) 확인. 기본 데스크톱에서도 기존 560px 셸 유지.
- 검사 중 보인 한 건의 초기 MutationObserver 오류는 위치를 특정하지 못했다. 핵심 흐름은 동작했지만 콘솔 오류 없는 상태로 검증 완료했다고 주장하지 않는다.

## 범위와 미검증

- 기기 내 기본 음정 추정·단순 시간 정렬·리듬 시작 간격 비교이며 AI 모델/전문 보컬 채점이 아니다. 추천은 규칙 기반이다.
- 비교 과제의 자동 분석은 B 녹음에만 적용한다. A/B는 사용자가 직접 듣고 비교한다.
- 표현·발성·공연은 제출·회고만 확인한다. 영상·동작·발성 안전성은 평가하지 않는다.
- 실제 마이크/iPhone Safari/PWA, 사람의 다양한 음색·배음·장식음·반주와 잡음, 로그인 계정 전환 실기기, 기존 전체 UI 회귀 검사는 미검증이다.
- 기존 인증 정책·클라우드 서버·DB 스키마·과금은 변경하지 않았다. R2 Worker 설정과 로그인 계정이 있어야 원본이 클라우드에 저장된다. Supabase 쓰기 응답을 받는 실제 운영 계정 검증은 별도로 필요하다. 로컬 fixture는 저장소 밖의 실행 도구이며 배포 파일에 포함하지 않는다.
- 운영 배포·main 병합은 하지 않았다.

후속 정리: 최신 main `77f570b0ea7d92e19deeaf497daa8c36e7f334f3`의 악보 선택·이동 변경을 보존하고, 가이드 양쪽 추가 절을 합쳐 버전 3.41로 갱신했다.
