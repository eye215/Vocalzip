## PDF·MusicXML·분석의 정확한 배치

- **07-A / S16:** 기존 PDF 보관 기능 재사용·검증, 악보 ID와 곡 연결·권한 보존. MusicXML 변환 완료와 무관하다.
- **07-B / S17 / 옛8E:** 실행환경·원가·라이선스 확인→직접 MusicXML 입력→PDF OMR 실제 XML 생성→구문·음표·성부·박자 검수/수정→사용자 확정. PDF 원본은 보존한다.
- **16-A / S18:** 확정 MusicXML 성부·키·템포·반복 지도→기준 멜로디/온셋→녹음 F0/온셋·보컬 유효구간→시간 정렬.
- **16-B / S18:** 검증된 음정 일치·박자 편차·신뢰도 표시. 기준 없이 '반음 근접도'를 정확도 점수로 표시하는 경로는 수정한다.
- **17 / S10·19:** 무료 규칙 추천→개인 목표 복사, 고급 해석은 사용자 유료 요청. 검증되지 않은 OMR 출력을 추천 근거로 확정하지 않는다.

PDF→XML은 실험 목표이고 현재 완료 상태가 아니다. PoC 실패 시 확정 기능을 조용히 제외하지 않고 비용/지원 범위/출시 영향 결정을 다시 받아 계획을 갱신한다.

## 의존성 규칙

- 단일 활성 세션은 지연 응답·재시도·오프라인 작업 충돌을 없애지 않는다. S04 revision/멱등성을 생략하지 않는다.
- 영상 서버 권한·실제 조건 가드는 P0, 압축·보관 UX는 P2다.
- 구독 상품은 P3이나 유료 요청 권한·예산 차단은 P0부터 서버에 존재해야 한다. 정식 결제 전에는 승인된 테스트 entitlement를 테스트 환경에서만 쓴다.
- 삭제는 S06 원장·권한 뒤 구현한다. 선택 대상의 실제 영구 삭제를 현재 승인한 것으로 해석하지 않는다.
- 초기 iOS 실험 결과가 파일 저장/업로드 어댑터 선택을 결정한다. Phase22까지 기다리지 않는다.
- 2.0 역할/그룹/수강권 확장은 이번 실행 단계에 넣지 않는다. 개인 레슨·소유권·출처 계약만 확장 가능하게 유지한다.

## 협업 및 릴리스 관리

[백로그의 진행 PR 표](STUDENT_1_0_PRIORITY_BACKLOG.md)를 작업 배정 원장으로 사용한다. Claude의 로컬 진행 작업은 원격 목록만으로 알 수 없으므로 S01/02·UI·워커 착수 전 최신 head/점유 파일을 인계받는다. 브랜치별 도메인 인터페이스와 테스트 fixture를 고정한 뒤 병렬화한다.

PR #111은 삭제하지 않는다. 30일 직접삭제 복구 권고는 v1.2로 대체하되 비용·분석·미디어 정합성 권고는 반영했다. 기존 PR 자동 병합은 없다. 각 구현 PR은 최신 main 대조·제한된 테스트·실기기 필요 항목을 기록하고 운영 변경은 별도 승인한다.

이번 계획은 존재하지 않는 감사 문서 3개를 대신 채우지 않았다. Phase01의 완전한 상태 매핑은 해당 결과를 받은 뒤 작업별 상태만 갱신한다.
