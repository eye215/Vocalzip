# VOCAL.zip 제품 정책 v1.2 — 사용자 확정 사항 (2026-11-07)

> **추가 정책 D14~D24 (2026-11-07):** D14~D19 악보 개인/공유 필기·학생별 MusicXML 변형·PWA 우선 방향에 이어, **D20~D24 다중 기기 동시 로그인·자동 초안 저장·기기 간 편집 이어받기·충돌 방지·태블릿 필기 연속성**을 반영했다. 기존 D01~D13과 즉시 영구 삭제·구독 만료 유예의 구분은 유지한다. **이 변경은 기존 R01 단일 활성 세션 정책을 대체한다.**
>
> **최신 정책: 기존 v1.1을 대체하는 변경 사항.** [기존 정책 v1.1](PRODUCT_DECISIONS_2026-11-07.md)의 변경되지 않은 조항(AI 요금제·원가 *가안*, 선생님 2.0 범위·구독 알림)은 유지한다. 단, **30일 휴지통 및 복구 관련 모든 문구는 즉시 삭제 정책으로 대체**한다.
>
> 제품 의사결정 기록이며 실제 운영 데이터 삭제·DB 변경·코드 배포를 허가한 문서가 아니다. Claude의 개발 브랜치 및 Codex Draft PR #111을 무단 수정·병합하지 않는다.

### 1-1. 삭제 UX 상세 규칙 — 반드시 구현 전 검증

**레슨에서 삭제**
1. 삭제 영향 미리보기: 연결된 녹음, 숙제/연습/곡 참조, 연동 정산 기록이 있는지 확인.
2. 체크 선택 **[연결된 녹음도 삭제]**(기본 꺼짐), **[연결된 정산 항목도 삭제/차감 취소]**(기본 꺼짐). 사용자는 대상을 개별 선택·해제할 수 있다.
3. 다른 레슨·연습·트레이닝·곡·공연에서도 사용 중인 미디어는 공유 참조 경고 + 개별 재확인.
4. **최종 확인:** “선택한 레슨·녹음·정산 항목을 영구 삭제하시겠습니까? 복구할 수 없습니다.” [취소] [영구 삭제].
5. 서버에서 실제 R2/Supabase 미디어 및 메타데이터 삭제를 처리하되, 중간 실패 시 **삭제 작업 상태를 명시·재시도**하고 유령 참조를 남기지 않는다.
6. 법적·정산 정확성에 필요한 결제/차감 감사 이력은 사용자 보관함에서 지우더라도 별도의 최소 기록 또는 반대 거래로 보존할 수 있다. **돈이 결제/환불된 사실을 조용히 지우면 안 된다.**

**정산에서 삭제**
1. 삭제할 정산 항목/수강권·금액/차감 및 연결 레슨을 미리 표시.
2. **[연결 레슨도 함께 영구 삭제]**(기본 꺼짐) 선택 제공.
3. 같은 최종 영구 삭제 확인. 체크하지 않은 레슨 및 녹음은 보존.
4. 잔액·차감·취소 거래를 재계산하고 **중복 환급·이중 차감 방지**를 테스트한다.

- **중요:** 사용자가 직접 삭제하는 자료에는 30일 복구 기간이 없지만, **구독 해지·요금제 만료 시 초과 용량 유예 29일과 여러 차례 이메일 알림** 정책은 계속 유지한다. 두 이유는 서로 다른 처리 경로.
- 파괴적 삭제 기능을 일괄 켜거나 **기존 삭제된 데이터의 배치 정리 작업을 실행하지 않는다**. 직접 삭제 UX·서버 계약·권한·실기기/DB 테스트를 갖춘 뒤 배포 승인한다.

### 2-1. 다중 기기·초안 동기화 기술 제약 (기존 단일 세션 조항 대체)

- **인증과 문서 편집 권한은 별개다.** 복수 로그인은 허용하되 한 텍스트 필드의 편집권은 서버에서 lease/epoch와 revision으로 조정한다. 화면에서만 잠그거나 브라우저의 로컬 상태만 검사하는 것으로 충분하지 않다.
- Supabase Auth 설정·요금제·세션 취소 동작·JWT 만료 전 권한 문제를 실제 서비스 환경에서 조사한다. **기기별 세션 관리/최대 2세션 제한은 기본 제공이라고 가정하지 않는다.** Safari와 설치형 PWA의 기기 구분 및 비정상 종료도 실기기로 검증한다.
- 각 입력은 **로컬 보존 → 서버 ack → 다른 기기 이어받기** 순서다. UI에 '기기에서만 저장됨'과 '클라우드 저장됨'을 구별한다. 오프라인 로컬 초안을 원기기 외 다른 기기에서 불러올 수 있다고 약속하지 않는다.
- 서버 확정 전에 기존 작성 기기를 내보내거나, 새 기기에 stale 값을 적용해 최신 노트를 덮어쓰면 안 된다. lease 소유자 변경은 원자적으로 처리하며 분쟁 시 버전별 사본을 보존한다.
- 악보는 **원본 PDF / 검수 MusicXML / 필기 스트로크**를 분리한다. 필기는 작성자·레이어·스트로크 ID 기반으로 중복 없이 병합하고 같은 stroke의 수정·삭제가 충돌하면 서버 버전 검증/복구 경로를 사용한다. 실시간 커서 동기화는 후순위다.
- 선생님 공유 자료는 기존 PRIVATE/DIRECT/GROUP/LESSON 권한 경계를 지킨다. 같은 계정의 다른 기기가 아니라 **다른 사용자 계정**의 데이터는 동의 없이 가져오지 않는다.
- **출시 차단 QA:** 휴대폰/태블릿 동시 로그인, 노트 초안 불러오기/이어받기, 편집 중 끊김·절전·재접속, 동일 필드 경합, 악보 동일/서로 다른 stroke 동시 수정, 학생 간 권한 분리, 원격 로그아웃 후 서버 쓰기 차단, 기존 녹음 복구.


## 3. 음악 악보 인식·정밀 비교 — 이전 계획과 연결

**기존 마스터 로드맵의 Phase 8E**에는 “PDF→MusicXML OMR·음표/박자 분석”이 이미 적혀 있었다. 이는 실행 완료된 기능이 아니라 **향후 기술 검증·개발 계획**이었다. 기존 Phase 8A는 PDF 보관이었으며 MusicXML 변환을 포함하지 않는다.

### 제안 하위 단계

1. **Phase 07-A**: 기존 PDF 악보 업로드·보관, 곡/성부 선택, 직접 MusicXML 파일 입력도 지원.
2. **Phase 07-B / 기존 8E**: 인쇄 악보 PDF를 OMR로 인식해 **MusicXML 생성**, 원본 PDF 보존, 오류 검토·수동 수정·조옮김.
3. **Phase 16-A**: 확인된 MusicXML의 기준 멜로디·박자와 실제 녹음의 음높이(F0)·온셋을 시간 정렬.
4. **Phase 16-B**: 가창 음정 일치도, 박자 편차 등을 **신뢰도와 유효 구간 조건부**로 표시하고 실제 목소리로 평가.
5. **Phase 17**: 검증된 편차를 기반으로 무료 규칙 기반 연습 추천 및 유료 요청형 AI 연습 계획에 활용.

PDF 자체는 이미지·벡터 악보일 수 있으므로 MusicXML로 확장자 변경하는 수준이 아니다. **OMR 인식 오류가 음정 점수에 전파**될 수 있어서 사용자 확인 후 비교한다. 화음·피아노 반주·복수 성부의 경우 학생이 부르는 멜로디 파트를 골라야 하며, 박자 루바토·조옮김·옥타브 이동·반주 간섭을 고려해 녹음과 정렬한다. 사용자의 음성과 선생님 자료는 동의/저작권 관리 대상이다.

### 원본 보호 및 비용

- 업로드한 PDF와 사용자가 수정·확정한 MusicXML은 별도 저장한다. 변환 실패 시 PDF 그대로 열람 가능.
- OMR을 서버에서 실행하면 CPU/메모리/실행 환경 비용이 들 수 있다. 우선 1곡으로 실험 후 전환.
- 기존 Stage 8E는 더 이상 독립된 옛 번호로 관리하지 않고, **새 07/16 단계의 명확한 하위 태스크**로 추적한다.

### 3-1. 악보 필기·변형 버전 및 공개 범위 계약 (D14~D17)

- **저장 분리:** `score_asset`(원본 PDF/소유자/R2 key/기준 페이지 크기/버전), `score_transcription`(OMR 생성 XML/검수 상태/버전), `score_variant`(학생·그룹·성부·키·조옮김·수정본), `annotation_layer` 및 `annotation_item`(작성자·페이지·상대 좌표·순서·공유 범위·컨텍스트)을 개념적으로 구분한다. 테이블명은 Phase 03에서 확정하며 현재 운영 구조라고 주장하지 않는다.
- **권한 스코프:** PRIVATE는 작성자만; DIRECT는 유효한 선생님–학생 관계의 지정 당사자만; GROUP은 해당 그룹에 대한 명시적 접근 허가가 있는 구성원/담당 강사만; LESSON은 실제 해당 회차에 권한 있는 강사/참여 학생만. **교사 개인 메모는 학생 지도 컨텍스트에도 비공개**, **학생 개인 필기는 교사에게도 비공개**다.
- **N:M 격리:** 같은 선생님이 같은 곡을 학생 A/B에게 가르쳐도 개인·개별 공유 필기를 섞지 않는다. 학생이 여러 선생님/그룹에 속해도 공유 범위는 `link_id / group_id / lesson_id`의 해당 컨텍스트에 한정한다. GROUP(장기 공유)과 LESSON(특정 회차 공유)은 다른 범위다.
- **작성·열람 분리:** 작성자는 자신의 스트로크만 수정/삭제한다. 공용 열람권이 있더라도 다른 작성자의 스트로크나 원본 PDF를 덮어쓸 수 없다. 개인→공용은 **범위 선택 후 복사**(새 ID·감사 정보), 자동 공개하지 않는다.
- **앵커/편집 안전:** PDF 페이지 번호·정규화 좌표·원본 `score_version`을 저장하고 확대/회전/모바일에서도 위치를 유지한다. PDF 교체·페이지 순서 변경 시 필기 재매핑을 자동 확정하지 않는다. 비공개/공용 데이터는 서버 권한 검사 후 개별 fetch, 숨김 UI만으로 보호하지 않는다.
- **이탈·삭제:** 연결 해제/그룹 탈퇴/수업 접근 만료 시 새 조회를 차단하되 원소유자 개인 기록을 강제 삭제하지 않는다. 이미 다운로드한 파일은 회수 불가하므로 내보내기 시 대상·레이어를 명시한다. 원본 PDF 삭제는 공유·필기·XML 참조 영향 미리보기 및 확정된 삭제 정책을 따른다.
- **검증 시나리오:** 학생 A/B 및 그룹 1/2 자료 분리, 동일 학생의 다중 강사, 그룹 미출석자 레슨 필기 차단, 강사 배정 해제, 공개 범위 변경·권한 회수, 오프라인 필기 충돌, PDF 교체, MusicXML 실패/재실행, 내보내기 포함 레이어만 노출, iPad Pencil 실기기 점검.

## 4. 연습 계획·숙제·트레이닝 데이터 계약

- 추천 연습/숙제는 **계획의 출처**이며, 학생이 이를 복사·연결해 **개인 연습 목표**를 생성한다.
- 권장 엔터티: `practice_goal` (출처 recommendation/teacher_homework/self, 목표 이름, 시작일/마감일, 목표 시간·횟수, 반복 요일, 상태), `practice_check` (목표·일자·완료 여부·실제 수행 시간·메모), `practice_session` (training/song/mixed, 입력 분, 곡 ID 선택, 트레이닝 유형, mediaIds).
- 학생은 **날짜/시간 예약**, **목표 N분·N회**, **수행 체크**, **실제 연습 시간 직접 입력** 가능.
- 녹음은 곡 연습·발성 트레이닝·레슨·공연에 여러 번 연결될 수 있으나, **한 녹음 바이트나 시간은 중복 집계하지 않는다**.
- 수행 체크는 실제 훈련/수강 완료 증거를 대체하지 않으며 선생님 숙제 완료 처리에는 수업별 정책을 적용한다.
- 현재 앱의 `practices`, `assignments`, `mediaIds` 등을 재사용할 수 있는지 코드를 확인한 뒤 최소 추가 필드로 설계한다. 불필요하게 전체 DB를 갈아엎지 않는다.

## 5. 우선순위 요약

- **P0 / 즉시 위험 차단:** 운영 서버 STT 무제한 자동 실행 및 공개 가입 설정 검토, 다중 기기 인증·세션 회수·계정 격리, 실제 사용자 데이터 보존, 녹음 복구, 업로드·R2 메타데이터 정합성, 소유자 영상 서버 권한 검사.

## 6. 운영환경의 확인된 사실 (2026-11-07 감사 결과)

- GitHub PR #114 운영 감사 결과에 따르면 운영 DB의 public 8개 테이블에 RLS 활성, Storage 비공개, 방문자 시도 차단, Worker의 미인증 접근 차단은 확인됐다. 이는 모든 동작/버킷 설정이 검증됐다는 뜻은 아니다.
- **공개 회원가입 + 이메일 자동 확인**, **5분 간격 분석 워커 깨우기 + 서버 STT 자동 실행 및 무제한**이 감사 당시 확인됐다. 이후 **PR #116(자동 유료 STT 차단·곡 자동 확정 승인)**이 2026-11-07 `main`에 병합됐다. **코드 병합 ≠ 운영 Worker 배포·과금 차단 실증**이므로 실제 운영 상태는 별도 재검증해야 한다.
- R2의 외부 공개 도메인 및 수명 주기/실제 청구, 실제 iOS 시나리오는 아직 검증되지 않았다.
- 기존 운영 DB의 정책을 읽기 전용으로 점검한 것과 실제 변경 승인은 별개다.
