# VOCAL.zip 개발 마스터 로드맵 v4.1

> 기준: 2026-11-06 · 저장소: `eye215/Vocalzip` · 이 문서는 **기획·우선순위 기준 문서**이며, 실제 배포/운영 테스트의 증거는 별도 확인한다.

## 0. 제품 방향

개인 보컬 레슨 → 연습 → 녹음 → 정량 분석 → 맞춤 연습 → 재녹음 → 성장 확인을 연결하는 **뮤지컬 중심 보컬 성장 아카이브**.

- iPhone Safari 및 홈 화면 PWA **모바일 퍼스트**, PC 반응형 유지
- **라이트 모드 전용**, 보라색 포인트·절제된 글라스모피즘
- 짧은 수정/선택은 레이어 팝업·바텀시트; 상세 분석/큰 차트는 독립 화면
- 기존 Supabase/R2, 곡·녹음·레슨·연습 데이터 재사용
- 오디션 관련 기능은 개발하지 않음
- 완료 상태는 사용자 확인/구현 보고를 구분해 표기. 운영 품질은 Phase 10에서 계속 검증

## 2. 기존 기능(Phase 1~7, 9)

### Phase 1 — 기록·보관함
레슨 일정·피드백, 연습 유형·시간·만족도·메모, 숙제, 캘린더, 녹음/영상 보관함, 곡별 연결. 추가 개선: 빠른 기록, 재생/저장 흐름, 팝업 입력, 숙제→연습 연결.

### Phase 2 — 업로드·클라우드
R2 원본 저장, 대량 업로드(250개 단위 자동 처리로 보고됨), 이어 올리기·중복 제외·다기기 변경 보호·Supabase 버전 이력. Phase 10에서 실제 재시도/충돌/삭제/권한/복원을 검증한다.

### Phase 3 — AI 곡 자동 분류
약 30초 STT → 가사 비교 → 확실한 곡 자동 지정, 불확실하면 TOP 3 제시, 비용 표시. 과제: 자동 지정 기준 0.40 검증, '확인 필요' 약 430개 정리, 사용자 교정 결과 활용, 필요시 복수 곡 구간 감지.

### Phase 4 — 날짜 보존
파일 메타데이터/파일명 날짜 추출, 기존 파일 일괄 수정, 직접 수정. 날짜 추정 근거/충돌 시 사용자 확인 유지.

### Phase 5 — 곡별 성장 아카이브
곡 타임라인, 두 녹음 비교, 비교 메모/리포트, 만족도. 향후 베스트 테이크·구간 북마크·중요 성장 시점 추가.

### Phase 6 — 보컬 정량 분석
MR 혼합 녹음에서 보컬 음정·오차·안정성·비브라토·음역·프레이즈 추적, 서버 비동기 처리. 약 1,800개 잔여 분석은 과거 보고값으로서 현재 큐 재확인 필요. 신뢰도, 보컬/MR 분리 한계, 분석 버전 기록, 실패 재시도 강화.

### Phase 7 — 성장 그래프·비교
날짜별 측정 그래프, 최초/최근 비교, 저장된 비교 리포트. 향후 음역 지도, 동일 구간 비교, 월간/연간 리포트.

### Phase 9 — 레슨비 정산
시간제 계산·자동 차감·클라우드 동기화·CSV 매칭. **2026-11-06 사용자 본인이 노션 데이터와 결과값을 대조해 맞음을 확인**. 이번 개발에서는 수정하지 않고 회귀 보호.

## 3. 현재 개발 스프린트 — Phase 8A/8B + 8C + 10

### 담당/순서/충돌 방지
1. **Codex: Phase 8C** 레퍼토리·공연 기록을 독립 브랜치/PR로 우선 개발.
2. PR을 검토·병합한 뒤 **Claude: 최신 main**에서 8A·8B 및 Phase 10을 진행.
3. 동시 작업이면 공통 CSS·곡 상세·내 곡의 동일 파일 수정 회피. 기존 기능을 통째로 재작성하지 않음.

### Claude 토큰 배분
- **남은 주간 토큰의 최대 10%: Phase 8A + 8B 합산.**
- **나머지 약 90%: Phase 10 모바일 UX/안정화.**
- 도구가 실제 잔여 토큰을 측정할 수 없으면 임의 추정 금지. 작업 범위/중단 기준으로 제한.
- Phase 8이 길어지면 미완료를 정직하게 기록하고 Phase 10 우선 전환.

### Phase 8A — 악보 PDF 보관 MVP
- 기존 곡 상세에 악보 영역, PDF 업로드 → **기존 R2 원본 저장**, Supabase 메타데이터/소유자/곡 ID 연결.
- 한 곡에 다중 악보, 모바일 열람·다운로드, 제목 수정, 안전한 삭제·재시도.
- 원키·연습키는 선택 메타데이터.
- 향후 MusicXML 변환 시 원본을 재업로드하지 않도록 안정적인 PDF 파일 ID/R2 경로 기록.
- **이번에 OMR, MusicXML 생성, 음표 판정·편집기는 개발하지 않음.**

### Phase 8B — 맞춤 연습 추천 MVP
- 기존 분석 결과에서 **실재하고 신뢰 가능한 지표만** 읽어 음정 정확도·안정성·비브라토·음역·프레이즈 연습을 규칙 기반으로 추천.
- 추천 이유·목표·방법·권장 시간·관련 곡 표시.
- 홈/곡 상세에 카드, '연습 시작' 클릭 시 기존 연습 기록 흐름에 연결.
- 레슨 선생님 숙제와 AI 제안 구분, 데이터 없으면 일반 루틴 또는 '분석 부족' 안내.
- 유료 LLM 반복 호출/신규 학습 모델/자동 의료·성대 진단 제외.

### Phase 8C — 뮤지컬 레퍼토리 + 공연 이력 (Codex)
**A. 레퍼토리**
- 상태: 관심곡 / 연습 예정 / 연습 중 / 공연 가능 / 보류. 기존 곡 ID와 일대일 연결.
- 작품·배역·넘버명·솔로/듀엣/앙상블·원어·메모.
- 사용자 자기평가 1~5: 가사 암보, 멜로디, 호흡/프레이징, 표현/감정, 전체 완성도. AI 점수와 별도.
- 원키/연습키/공연키, 조옮김 메모.
- 대표 테이크는 기존 녹음 ID 참조(원본 복제 X), 삭제 시 참조 보호.
- '내 곡' 검색(곡·작품·배역), 상태 필터, 최근 연습/곡명/등록/숙련도 정렬.

**B. 공연 출연 아카이브**
- 작품명·공연 기간·공연장·단체·배역·팀·캐스팅 구분·준비중/완료/취소·후기.
- **한 공연에 여러 회차**: 날짜·시간·실제 출연 여부·해당 회차 배역·메모.
- 공연↔기존 곡 다대다 연결(솔로/듀엣/앙상블, 공연키). 곡 복제 없이 양방향 탐색.
- 공연 목록/상세, 연도별 타임라인, 등록 데이터 기반 작품·출연 회차 집계.
- 여유 시 포스터·사진·영상·프로그램북 첨부: 기존 R2 재사용, 대규모 갤러리 신규 구축 금지.
- 공연/링크 삭제 시 원본 곡·녹음·레슨·연습·분석 기록은 보존.
- 예시 **사용자가 공유한 이력**: 2026-01-24~25 <맘마미아> 도나(더블), 2026-07-25~26 <잭 더 리퍼>(4회, 배역 확인 필요), 2026-10-17~18 <그리스> B팀 리조(서교스퀘어). **실제 DB에 자동 삽입하지 말고 사용자 확인을 거쳐 등록.**
- 2026-02-19 <레베카> 킥오프 기록만으로 공연 완료 처리 금지.

**Codex 단계별 우선순위**: P0 레퍼토리 상태/작품·배역/공연 CRUD·회차·곡 연결·조회·보존 → P1 숙련도/키/대표테이크/검색·필터/타임라인/기본 첨부 → P2 통계·세부 장식. 토큰 부족 시 완성된 P0 단위만 제출.

## 4. 향후 페이즈 상세

### Phase 8D — 뮤지컬 넘버 맞춤 추천
보컬 분석의 안정 음역·강점, 선호 작품/장르, 기존 레퍼토리·관심곡, 연습 목표를 바탕으로 편안한 곡/현재 적합곡/도전곡/기술 연습곡 추천. 작품·넘버·배역·요구 음역·난도는 **검증된 데이터만** 표시. 추천 이유, 관심곡 등록→연습 시작 연결. 오디션 기능 제외.

### Phase 8E — OMR 및 악보 기반 정밀 평가
기존 PDF 원본 → 서버 OMR(Audiveris 등 **현재 실행 환경 확인 후 선정**) → MusicXML 생성/검증·R2 보관 → 사용자 멜로디 파트 선택·오인식 확인·수정 → 녹음 정렬 → 음표/박자/프레이즈 비교. PDF 이미지화나 확장자 변경을 MusicXML 변환으로 간주 금지. 스캔 악보 품질·MR 간섭·조옮김에 따른 신뢰도 표시. 신규 OMR 실행 환경 검증 전 구현 확약 금지.

### Phase 11 — 실시간 연습 도구
11A 마이크 기반 음정 튜너(음명·옥타브·목표음 차이), 11B MR 키 변경/속도·A-B 구간 반복, 11C 안정 음역 맞춤 발성·저음/패사지오 루틴, 11D 가사 암기/빈칸, 11E 듀엣·앙상블 파트 연습. **우선 11A/11B.**

### Phase 12 — 심화 분석
12A 녹음 잡음·클리핑·레벨·MR 간섭 감지와 분석 신뢰도(우선), 12B 가사 줄별 시간 정렬·음정, 12C 딕션, 12D 호흡 위치/프레이즈 추정, 12E 셈여림·다이내믹, 12F 선생님/기준 테이크와 동일 구간 비교. 추정값을 진단처럼 단정하지 않기.

### Phase 13 — 레슨·컨디션·습관

### Phase 16 — 뮤지컬 캐릭터·표현 연구

## 6. 모든 개발 작업의 공통 원칙

1. **원본 보호**: 기존 곡·녹음·영상·가사·레슨·연습·정량 분석·정산 기록과 R2 객체를 삭제/초기화하지 않음.
2. **운영 보호**: AI 곡 분류/보컬 분석 작업 큐와 백그라운드 실행을 중단하지 않음. 서버 설정이 확인되지 않으면 가정하지 않음.
3. **데이터 정합성**: 곡·공연·악보 참조는 ID로 연결. 삭제 시 독립 기록/미디어 보존과 고아 참조 처리.
4. **보안**: 사용자별 RLS/스토리지 권한, 서버 비밀키 보호. 실제 접속 권한을 검증하지 않았다면 '검증 필요' 보고.
5. **디자인**: iPhone 우선·라이트 모드·바텀시트/레이어 적극 사용, 팝업 중첩 방지 및 미저장 입력 보호.
6. **토큰 절약**: 변경 대상만 탐색, 중복 리팩터링·새 라이브러리·신규 서버 지양, 기존 구성요소 재사용, 필요 검증 생략 금지.
7. **PR 분리**: Codex 8C와 Claude 8A/8B/10을 분리; 파일 충돌 확인 후 병합.
8. **증거 기반 완료**: '구현됨', '모의 테스트 통과', '실기기 검증됨', '실제 서비스 확인됨'을 구분. 검증 없이 완료 선언 금지.
9. **범위 관리**: 다음 단계 기능을 현재 단계에 몰래 추가하지 않음. 안정화·배포 가능 상태를 먼저 확보.
