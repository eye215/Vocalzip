# 대용량·다중 업로드와 공통 녹음기

## 동작
- 보관함/연습의 다중 파일 선택, 파일별 곡 지정(기존/신규/미지정), 순차 업로드.
- 실패/취소한 항목만 다시 시도. 성공한 File 참조는 해제하고 성공 항목을 재전송하지 않음.
- 원본 최대 1GiB. 50MiB 초과 파일은 24MiB 이하 독립 Storage 객체로 원본 바이트를 보존.
- 기존 vocal_media.metadata에 storageVersion:2, size, parts[{path,size}] 저장. 조각은 사용자 ID/파일 ID 경로. DB 스키마 변경 없음.
- 단일 파일당 metadata는 모든 조각 전송 후 한 번 등록. 미완료 경로를 로컬 저널에 남겨 다음 업로드 때 완료 여부를 확인하고 정리.
- 50MiB 이하 기존 단일 객체와 공존. v2 삭제는 모든 조각을 삭제하고 마지막에 metadata 삭제.
- 서명 URL을 가진 서비스 워커가 Range 요청을 원본의 조각 구간으로 변환해 스트리밍. 전체 원본 ArrayBuffer/Blob 조립/영상 압축 없음.
- 재생 주소는 55분 유효. 계정 변경/로그아웃 때 워커 세션 폐기. 새로고침 후 워커 재시작에도 세션 정보는 IndexedDB에서 조회.
- 레슨/연습은 동일 캡처 컴포넌트(음성/영상, 실시간 파형, 타이머, 마크, 일시정지/재개, 저장 실패 재시도/다운로드). 레슨은 녹음별 메모와 기존 recordings에 연결.

## 검사
GitHub Actions: Node 구문, node --test tests/chunk-media.test.cjs, Playwright.
- 201MiB 스트림 전체 해시, 경계 seek/HEAD/suffix/416, 중단·짧은 응답·잘못된 Content-Range.
- 실제 201MiB File fixture를 9개 객체로 전송하는 경로 및 단일 metadata commit. Supabase/TUS는 대역.
- 다중 선택의 파일별 곡, 한 파일 실패 후 그 파일만 재시도, 원래 연습 연결 보존.
- 실제 서비스 워커를 통한 구간 요청/재접속/네이티브 WAV 재생/로그아웃 폐기. 네트워크는 대역.
- 레슨 캡처→일시정지→마크→녹음별 메모→레슨 저장. 가상 장치.

## 운영 한계/검증 잔여
- 실제 iPhone 사진 선택기·MOV/HEVC 재생·화면 잠금·브라우저 종료, 운영 계정의 200MB 이상 업로드는 별도 실기기 확인 필요.
- 무료 프로젝트의 총 저장 공간/egress quota는 그대로 적용. 조각 분할은 파일당 50MB 제한만 해결하며 무료 총량을 늘리지 않음.
- 업로드 중 화면을 유지해야 함. 새로고침 후 이어올리기 없음. 다음 업로드 때 실패 조각을 정리하고 원본 파일 재선택.
- TUS 미완료 세션의 서버 만료 정책은 서비스 설정을 따름.
- v2는 전체 원본을 기기로 일괄 다운로드하는 기존 버튼에서 제외. 클라우드 스트리밍으로 재생.
- 서비스 워커가 필요. HTTPS/localhost에서 실행하고 최신 Safari/Chrome 사용.
- Safari가 지원하지 않는 원본 코덱을 변환하지 않음.
