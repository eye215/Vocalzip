# Phase 07-C — PDF 악보 개인 필기

2026-11-10, PR [#235](https://github.com/eye215/Vocalzip/pull/235). 사용자 요청으로 편집/삭제 저장 계약과 파일 공유보다 개인 필기를 먼저 진행한다.

## 제공하는 기능

곡 상세 → 악보 탭 → PDF 행의 **필기** 버튼으로 연다. 기존 PDF 올리기/열기/정보 수정도 유지한다.

- 페이지별 펜·형광펜·획 지우개, 현재 페이지 필기 삭제 확인.
- 되돌리기/다시 실행. 삭제 표시가 있는 획 ID를 되살리지 않고 새 ID로 복원한다.
- 이전/다음 페이지, 화면 맞춤·150%·200% 확대. 이동 모드에서 스크롤한다.
- 손가락/마우스/Pen Pointer 입력. ‘펜만’ 선택 시 손가락/마우스 입력은 무시한다.
- 획 종료·취소/화면 숨김 시 저장을 시도한다. 실패한 입력은 현재 화면/가능한 복구 기록에 남기고 다시 저장을 제공한다. 미저장 상태로 일반 닫기/Escape를 조용히 통과하지 않는다.
- PDF 삭제 확인에는 연결된 개인 필기도 명시한다. 삭제 후 해당 획과 로컬 복구 벡터를 정리하며 레슨·연습·곡/녹음은 유지한다.

공통 작업 페이지·Pretendard·최신 토큰·44px 도구·52px 완료·Safe Area를 재사용한다. 화면 디자인 기준은 공통 디자인 가이드에 기록한다.

## 데이터와 원본 보호

PDF.js **4.10.38 legacy build**를 고정해서 브라우저에서 PDF를 렌더링한다([Apache 2.0 원본](https://github.com/mozilla/pdf.js/blob/v4.10.38/LICENSE)). 모듈·worker·필요 폰트/CMap만 jsDelivr에서 받으며 PDF/필기를 분석 서버나 CDN에 업로드하지 않는다. 동적 코드 평가/XFA는 비활성화한다. 새 서버와 DB 마이그레이션은 만들지 않는다.

원본 PDF는 기존 비공개 R2 키/서명 접근을 재사용한다. 필기 작업은 PDF 원본을 재업로드/수정하지 않는다. 별도 `scoreAnnotations[]`에 획을 저장하고 기존 계정별 `vocal_data.payload` 동기화를 사용한다.

| 필드 | 의미 |
|---|---|
| id/version | 획의 독립 ID / 형식 버전 |
| ownerId | 개인 작성 계정. 선생님 이름/곡 소유와 자동 공유하지 않음 |
| songId/scoreId/r2Key | 기존 곡/PDF ID·자산 경로 참조 |
| pdfHash | 읽은 원본 전체 SHA-256. 같은 키의 PDF가 바뀌어도 이전 필기를 잘못 겹치지 않음 |
| page | PDF 페이지(1부터) |
| tool/color/width | 펜/형광펜, 색, PDF 폭 기준 굵기 |
| points | 페이지 좌상단을 기준으로 0~1 좌표/압력 샘플. 확대/회전된 기본 viewport 비율과 독립 저장 |
| createdAt/updatedAt | 획 생성 시각 / 기존 root 변경 추적 시각 |

획은 불변이며 수정 대신 새 획 추가·기존 ID 삭제 표시를 쓴다. core의 추적 배열과 data-merge의 항목 병합 목록에만 컬렉션을 추가했다. 곡 정보 수정이 별도 획 목록을 교체하지 않으며, 두 기기의 서로 다른 획을 ID별 합친다. 삭제 ID 합집합은 오래된 기록에서 획을 복구하지 못하게 한다.

계정별 `vzip_score_ink_v1:<owner>` 복구 원장에는 벡터/최소 삭제 ID만 저장하고 PDF bytes·서명 URL·세션 토큰은 저장하지 않는다. root 쓰기 전에 기록하여 공간 부족/응답 불명확 시 다음 열기에서 복구한다. 삭제 표시가 도착하면 복구 벡터도 정리한다. 기존 계정별 storage namespace와 현재 로그인 세션을 모두 확인하며 전환/회수 시 편집기를 닫는다.

## 용량·오프라인·호환 범위

- 기존 PDF 업로드 상한 50MB, 최대 2000쪽. 한 번에 한 페이지, canvas 최대 400만 픽셀을 렌더링한다.
- 복구 원장 2MiB(UTF-16 추산), 최대 4000획·삭제 ID 10000개. 획당 최대 2048점. 한도 초과 시 기존 기록을 버리지 않고 오류를 표시한다. 긴 획은 점 한도에서 추가 수집을 멈추므로 여러 획으로 나눠 쓴다.
- 이미 열린 PDF에는 오프라인으로 필기하고 기기에 보존할 수 있다. 새로 연 PDF 원본/렌더러의 완전 오프라인 캐시는 제공하지 않는다.
- 상태의 ‘이 기기에 저장됨’은 클라우드 전송 완료 표시가 아니다. 기존 동기화 성공/오류를 별도로 확인한다.
- 새 버전 클라이언트의 획 병합을 검사한다. 구 클라이언트 전체 writer 통제·새 revision 서버 계약 활성화는 기존 P0 작업으로 남는다. 새 동기화/이어올리기/서버 원본 가드를 켜지 않는다.
- PDF 바이트 변경 시 이전 해시의 필기는 보관하되 현재 PDF에 표시하지 않는다. 구 버전 PDF 전환 UI와 필기 포함 PDF 내보내기는 후속이다.
- 실제 계정의 기존 PDF/녹음/레슨 데이터 일괄 변경이나 운영 DB 변경은 수행하지 않는다.

## 검사 기준

단위: 좌표/지우개 hit-test, 검증·한도, 새로고침 복구, root 쓰기/복구 공간 실패, 세션/계정 격리, 별도 PDF 해시/페이지, 두 기기 획 병합, 삭제 재생성 차단, PDF 삭제의 필기 정리.

브라우저: **실제 PDF.js와 유효한 합성 2쪽 PDF**를 사용한다. canvas 렌더링, 실제 마우스 그리기, 합성 Pen Pointer, 형광펜·지우개·undo/redo, 페이지별 저장, 확대/320px, 새로고침, 원본 bytes/기존 기록 보존, 실패 재시도/계정 전환, 명시적 PDF 삭제를 검사한다. 기존 PDF 업로더와 날짜 이동 회귀도 실행한다. 검사 SHA·통과/실패·배포 증거는 PR에 기록한다.

자동 WebKit/합성 Pen 입력을 **실제 iPhone Safari/PWA·iPad Apple Pencil·잠금/메모리 부족 성공으로 표시하지 않는다.** 실기기 인수는 남아 있다.

## 이번 범위 이후

필기 포함 PDF 내보내기, 구 PDF 버전 전환, 장기 복구 원장/클라우드 영수증 정리 정책, Apple Pencil 압력에 따른 시각 굵기/고급 palm rejection, OMR/MusicXML 검수·수정, 선생님/그룹 공유 필기는 별도 작업이다. 이번 구현을 Phase 07 전체 완료로 표시하지 않는다.
