# 노션 레슨비 정산 구조와 가져오기 검증

2026-11-05에 연결된 Notion의 레슨비 정산 페이지, 결제·레슨내역·수강생정보·남은레슨 데이터 소스를 읽기 전용으로 확인했다. 이 문서와 테스트에는 개인 이름, 실제 날짜별 거래, 원본 페이지 ID/URL, 실제 금액을 복제하지 않는다. 테스트 데이터는 별도로 만든 예시다.

## 확인한 데이터 구조

| 데이터 소스 | 확인한 속성 | Vocalzip 처리 |
| --- | --- | --- |
| 결제 | 결제날짜(date), 금액(number), 레슨횟수충전(formula), 적용단가(formula), 수강생정보·남은레슨 관계 | 날짜·금액·내보낸 충전값을 매핑하고 등록 전 확인 |
| 레슨내역 | 레슨날짜(date), 상태(select), 레슨횟수 차감(number), 비고(text), 결제(relation), 레슨권이름(결제날짜 rollup) | 명시된 차감 숫자와 메모 보존. 결제 관계 수를 차감 배수로 사용하지 않음 |
| 수강생정보 | 회당수강비(number), 적용시작일/적용종료일(date), 결제·레슨내역 관계, 충전/차감 sum rollup, 남은레슨(formula) | 단가와 기간 구조를 참고하되 현재 계정 데이터나 기존 단가를 자동 변경하지 않음 |
| 남은레슨 | 결제·레슨내역·수강생 관계, 충전/차감 sum rollup, 남은레슨(formula) | 잔여 집계와 원본 수량 대조 기준 |

실제 구조에는 0차감 완료 기록, 2차감 완료 기록, 같은 날짜의 여러 레슨, 한 레슨에 여러 결제 관계가 있는 사례가 있다. 행 수를 사용 횟수로 간주하거나 관계 하나당 레슨을 복제하면 안 된다. 레슨권이름은 수업 날짜가 아니라 연결된 결제 날짜의 rollup이므로 다중 값이나 연결 누락을 임의로 하나의 레슨권으로 확정하면 안 된다. 상세 연결 매칭은 별도 PR #36 영역으로 유지한다.

## 재현과 수정

기존 autoMap은 `레슨횟수 차감`과 `비고`를 인식하지 못했다. 완료 상태에서는 차감 열이 매핑되지 않아 기본 1이 적용되므로, 원본의 0과 2가 모두 1로 변했다. 메모도 빠졌다.

- Notion 실제 속성 이름을 별칭으로 등록해 차감 숫자와 비고를 보존한다.
- 명시적으로 매핑된 차감 열의 빈 셀은 기본 1로 바꾸지 않는다. 미리보기 오류로 표시하고 확인 후 값을 입력해야 한다.
- 차감 열 자체가 없는 일반 CSV는 기존 완료 기본 1 정책을 유지한다.
- 0은 빈 값과 구분한다. 같은 날짜의 서로 다른 수강은 유지한다.
- 여러 결제 관계가 들어 있는 원본 셀은 raw 이력에 남지만 차감량을 곱하지 않는다.
- 새로 내보낸 CSV라도 날짜·레슨권·상태·시간·수강생·메모가 같고 차감값만 다른 기존 수강 후보가 있으면 중복 의심으로 표시하고 기본 선택에서 제외한다. 같은 원본 참조로 이미 등록된 경우에는 기존/원본 차감값 차이를 안내하고 재등록을 차단한다.
- 날짜가 같다는 이유만으로 중복 처리하지 않으며, 메모·시간 등 다른 값이 있는 별도 수강은 유지한다.
- 레슨권 연결/수강 확인 흐름은 유지한다.

실제 조회한 수강 행 전체를 도구 메모리에서 변환해 오류 0행, 원본 차감 합계와 변환 합계 일치를 확인했다. 이 대조는 원본 숫자의 보존 검증이며 Notion 수식 계산 결과를 읽어 비교한 검증은 아니다. 실제 행은 GitHub, Supabase 또는 앱 저장소에 등록하지 않았다.

## 수식 검증의 한계

도구는 formula/rollup 원문과 계산 결과 대신 `formulaCode://`, `formulaResult://`, `rollupResult://` 참조를 반환했다. 해당 formulaCode 참조의 fetch는 INVALID_ARGUMENT로 거절됐다. 따라서 적용단가의 날짜 분기, 반올림, 과거 단가 변경에 대한 수식 원문을 확인했다고 보고하지 않는다.

이번 수정은 직접 확인된 속성명·차감 숫자·관계 구조를 보존한다. 미확인 수식을 추정하여 전체 계산식이나 과거 금액을 변경하지 않는다. 현재 시간당 정산 계산은 main의 기존 구현을 유지하고, 그 데이터를 백업/복원/클라우드에서 수용하는 호환 문제만 함께 고친다.

## 기존에 가져온 기록

이번 변경으로 이미 저장된 차감 이력을 자동 수정하지 않는다. 과거 잘못 매핑한 업로드는 원본 파일과 비교한 뒤, 아직 편집/외부 연결이 없는 업로드라면 기존 되돌리기 후 다시 미리보기하여 등록할 수 있다. 수정된 기록은 개별 검토가 필요하다. 원본 전체를 자동 재등록하면 중복/의도하지 않은 변경이 생길 수 있으므로 실행하지 않았다.

## 테스트와 병렬 작업 경계

- 신규 단위 테스트: 실제 속성명, 0/1/2 차감 합계, 빈 명시값, 차감 열 없는 기존 CSV, 같은 날짜·다중 결제 관계, 공백 변형.
- 신규 브라우저 테스트: Notion 형태 CSV 매핑 → 정상 행만 선택 → 저장 → 새로고침 후 차감·비고 유지.
- 기존 백업 호환 테스트: 시간당 단가와 설정 변경 이력, JSON 다운로드/복원, 클라우드 대역 전송, 시간 기준 미리보기.
- `billing/import.js`는 #36과 같은 파일이지만, 이번 별칭/빈 값 수정은 레슨권 이름/날짜 매칭 구현을 가져오거나 덮어쓰지 않는다. 병합 시 두 변경을 함께 유지해야 한다.
- Claude #44 및 후속 #46의 앱 UI·미디어·R2 파일, 공통 CI, 기존 레슨 데이터는 수정하지 않는다.
