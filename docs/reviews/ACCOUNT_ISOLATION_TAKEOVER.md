# 계정별 기기 저장·로그인 인계 연결 (v1.2)

기준 main: `696084fae8fa42db69887f86f9a62b286c7a2612`

## 구현

- account-config.js의 VZIP_SINGLE_SESSION_ENABLED는 기본 false. 검증·서버 준비 전 기존 운영 동작을 바꾸지 않는다. true일 때 서버 RPC 실패를 기존 무제한 로그인으로 우회하지 않는다.
- app/account-scope.js가 계정별 localStorage와 별도 IndexedDB를 제공한다. 이전 vocal-zip_mvp_v1/vocalzip_media_v1은 그대로 두며 자동 병합/삭제하지 않는다. 큐·스냅샷·R2 URL 캐시도 계정별 공간을 쓴다.
- 계정이 바뀌면 이전 계정 문맥을 계속 쓰지 않고 보호 콜백 완료 후 새 페이지로 전환한다. 모든 이전 비동기 클로저는 원래 공간에 묶여 있다. 다른 탭의 계정 변경도 보호 후 새로 연다.
- 녹음 중이거나 아직 저장하지 않은 미리듣기 결과는 계정 전환/인계 중 원래 계정 DB에 보호 파일로 저장한다. 저장 실패면 전환을 진행하지 않는다. 기존 파일/Blob/ArrayBuffer 호환을 유지한다.
- 새 클라이언트는 x-vzip-client-protocol: account-session-v1을 전송한다. 서버 세션 가드는 이 헤더가 없는 구버전 클라이언트의 직접 DB/Storage 접근도 거절해, 같은 브라우저에서 공유된 새 JWT만으로 이전 탭이 자동 병합하는 것을 막는다. 이 헤더는 인증 수단이 아니며 검증 JWT·활성 세션 검사와 함께 쓴다.
- cloud-sync는 vzip_claim_session을 확인하고, 다른 세션이면 로그인 화면 안의 인계 확인을 제공한다. 취소 시 기존 활성 서버 세션을 유지하고 이 기기만 로그아웃한다. 승인 시 expected_previous 조건부 인계 후 자료를 연다.
- 활성 세션 확인/토큰 발급은 실패를 보수적으로 처리한다. 서버에서 비활성으로 확인되면 자동 업로드를 멈추고 기기 녹음을 보호하며 로그인 화면을 잠근다. DB의 즉시 차단과 화면의 20초 점검은 별개다.
- 클라우드 자료를 먼저 읽으며 기기의 수정 의도가 있는 경우만 기존 병합으로 동기화한다. 저장 완료 전 임시 파일을 지우지 않는다.
- 이전 자료는 '이 기기의 이전 자료 확인·가져오기'에서 소유 계정 명시 확인 후 복사한다. 기존 원본은 보존하고 같은 ID는 덮어쓰지 않으며 충돌을 보고한다. Web Locks로 계정 소유자 선택·복사를 직렬화한다. 일부 실패는 같은 계정에서 재시도한다.
- legacy 화면은 활성 모드에서 v6로 이동한다. 비활성 기본 모드의 기존 계약과 테스트는 유지한다.

## 검증/완료 범위

자동 브라우저 검사는 서버/Auth 대역을 사용해 계정 A/B 공간·큐·파일 분리, 인계 승인/취소·RPC 실패 잠금, 원본 보존·중복 복사·충돌, 진행 녹음/미리듣기 보호를 검사한다. DB 테스트는 별도 실제 임시 PostgreSQL에서 기존 서버 계약 6개를 실행한다. 모의 로그인 또는 Linux WebKit은 물리 iPhone이나 운영 JWT/DB 검증이 아니다.

## 운영 활성화 전 남은 필수 항목

1. 기존 SECURITY DEFINER 사용자 RPC·Edge Function의 service-role 경로를 목록화하고 현재 세션 검사를 연결해야 한다. 직접 DB RLS 검증만으로 모든 우회가 차단됐다고 주장하지 않는다.
2. R2 Worker의 활성 세션·클라이언트 프로토콜 검사와 CORS, 기발급 PUT 완료 검증 및 signed GET 권한 철회 계약이 필요하다. RLS는 R2에 적용되지 않는다.
3. 실제 Supabase auth.sessions·JWT session_id·OAuth/계정 재인증·동일 계정 두 기기 인계·물리 iPhone 중단/저용량/오프라인을 검증해야 한다.
4. 명시적 운영 승인 후 서버·클라이언트의 일치하는 버전과 캐시 버전을 제한된 환경에서 활성화한다. SQL만 먼저 운영에 적용하면 기존 앱 접근이 차단되므로 금지한다.
5. 현재 구현은 오프라인 복구용 기기 자료를 보존하며, 서버 확인 후 자동 캐시 정리/공간 상한은 후속 작업이다. 미전송 녹음은 해당 정책 때문에 삭제하지 않는다.

운영 DB·원본 미디어·배포와 Claude의 기존 브랜치는 수정하지 않는다. 변경 소스가 겹치는 #108은 이후 통합 시 실제 diff로 조정해야 하며 자동 병합하지 않는다.
