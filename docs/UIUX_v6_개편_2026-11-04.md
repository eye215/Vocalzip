# VOCAL.zip v6 UI/UX 전면 개편 — 2026-11-04

이 문서는 최초 v6 개편 시점의 구조 설명입니다. 이후 #24(파일 길이 집계), #30(자동 미디어 백업), #31(기록 병합), #33(녹음 진입점) 변경이 있으므로 현재 동작은 최신 코드와 [운영 검증 현황](운영검증_2026-11-04.md)을 함께 확인하세요.

## 왜 다시 만들었나
v5 화면은 `index.html` 위에 24개 스크립트가 서로의 DOM을 다시 배치·덧칠하는 구조였다. 그 결과:
- 홈에 같은 진입점이 3번 반복(큰 카드 + 4개 타일 + 하단 메뉴), 정작 다음 레슨·숙제는 없음.
- 녹음하려면 연습 탭 → "연습 작성" 폼을 열어야 함(원터치 녹음 불가).
- 곡 중심 화면, 레슨 일정(시간·장소·상태) 개념이 없음.
- 기능 하나를 고치면 다른 스크립트의 DOM 가정이 깨지는 회귀가 반복됨.

v6는 데이터·클라우드·대용량 업로드·스트리밍 인프라는 그대로 쓰고 **화면 계층만 새로 작성**했다.

## 데이터 호환 (마이그레이션 없음)
기존 필드는 지우거나 이름을 바꾸지 않고 **선택 필드만 추가**한다. v5(`legacy.html`)와 클라우드 `vocal_data` payload 형식은 그대로다.
- `lessons[]`: `startTime`, `endTime`, `place`, `teacher`, `songIds[]`, `prepMemo`, `status`(`scheduled|done|cancelled`), `songFeedback{songId:text}`, `completedAt`, `created`. **`status`가 없는 기존 레슨은 완료로 표시**(v5는 레슨 후 작성 방식). `songId`는 `songIds[0]`과 동기화해 v5 화면에서도 곡이 보인다.
- `assignments[]`: `songId`, `doneAt`, `created`. `lessonIds`(이월 숙제) 유지.
- `practices[]`: 같은 형식. 녹음만 하면 연습 기록이 생기지 않으며, 연습 기록에 녹음을 연결해도 시간은 더하지 않는다(중복 집계 방지). "이번 연습에서 한 숙제"(`completed`)는 숙제 완료와 별개.
- 미디어 레코드: 같은 IndexedDB `vocalzip_media_v1/recordings`, 기존 `blob`/`bytes` 모두 읽음. 25MB 초과는 로그인 시 클라우드(50MiB 초과 분할 저장) 그대로.
- 레슨 삭제: 숙제·수행 메모·녹음 원본 보존, 레슨 연결만 해제(v5 정책 유지).
- 곡 삭제: 곡 목록에서만 제거, 연결된 기록의 `songId`는 그대로 둔다.

## 레슨비 정산 (프로젝트 B와의 경계)
레슨권·결제·횟수 차감·정산은 프로젝트 B(`billing/`, `/billing/`)가 별도 저장소로 개발한다. v6는 `billing/` 폴더를 건드리지 않고 설정 메뉴와 레슨 목록에 링크만 둔다. 레슨 완료는 `status`만 바꾼다. 정산이 읽는 `id`·`date`·`status` 규칙은 [레슨 데이터 연동 계약](레슨데이터_연동계약.md)에 있다.
