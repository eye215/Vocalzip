# VOCAL.zip 레슨비 정산 — Project B

독립 경로 `/billing/`에서 실행하는 정산 모듈입니다. 기존 홈·내비게이션·레슨·연습·곡·미디어 화면과 코드는 수정하지 않습니다. 프로젝트 A가 필요할 때 메뉴 링크만 연결할 수 있습니다.

## 구현 범위

- 레슨권 등록/수정, 단가 계산, 사용 이력 있는 레슨권의 정산 영향 확인
- 결제·분할 결제·환불, 결제 중복 의심 확인, 거래 번호, 수정 전후 이력
- 기존 Lesson ID 연결 또는 날짜만 있는 과거 수강 등록, 차감 수정/취소/복구
- **앱 레슨 정산 대기**(수강·조정 상단, 정산 현황 요약): 앱에서 완료한 레슨(`done`/`completed`)은 한 번에 1회 차감, 상태 없는 기존 레슨은 수강함(1회)/수강 안 함(0회)/직접 입력으로 확인, 차감 후 앱에서 취소·예정으로 바뀐 레슨은 차감 취소(복구) 또는 당일 취소 등으로 수정. 기본 레슨권은 잔여 1회 이상인 가장 먼저 등록한 레슨권(선택 변경 가능). 미래 레슨은 대기 목록에 넣지 않음
- 예정/취소/무료 0회, 완료 기본 1회, 당일 취소·연속 레슨 수동 횟수
- 레슨권별·전체 정산, 별도 금액/횟수 조정 거래
- CSV/XLSX/노션 CSV: 컬럼 자동 매핑, 시트 선택, 행별 수정·검증·선택, 등록 전후 정산 미리보기
- 업로드 파일명/시각/유형/성공·실패·중복·제외 건수/작업 ID/행별 원본 보존
- 업로드로 생성한 데이터만 되돌리기; 이후 수정 또는 외부 연결이 있으면 전체 되돌리기 차단

## 구조와 데이터 경계

| 파일 | 책임 |

객체: LessonPass(`passes`), Payment(`payments`), LessonDeduction(`deductions`), BalanceAdjustment(`adjustments`), ImportBatch(`imports`), ImportRow(`importRows`), AuditEvent(`history`).

기존 앱의 `vocal-zip_mvp_v1`에서 `lessons[].id/date/status`를 읽어 `lesson_id/lesson_date/lesson_status`만 제공하며 쓰지 않습니다. 앱 v6(프로젝트 A)는 완료를 `done`으로 저장하므로 `completed`와 같이 취급합니다(`docs/레슨데이터_연동계약.md`). 표시용으로 `startTime/endTime/place/teacher`도 읽기만 합니다. 상태 없는 기존 레슨은 사용자가 실제 수강 상태를 확인해야 합니다. 과거 업로드는 별도 차감 이력만 만들고 기존 Lesson을 생성하거나 수정하지 않습니다. 기존 레슨 상태를 자동 변경하거나 상태 변경을 자동 차감하는 구독 기능은 없습니다. 정산 화면에서 확인·저장합니다.

정산은 IndexedDB `vocalzip_billing_v1/documents`에 저장합니다. 현재 Supabase 세션의 사용자 ID별 문서를 사용하며 미로그인은 `device`입니다. 로그인 전 데이터의 자동 계정 이전은 하지 않습니다. 계정 전환 시 새로고침해야 합니다. 동일 계정의 다른 탭은 revision 검사로 덮어쓰기를 차단합니다.

정산은 먼저 기기에 저장하며, **백업·동기화** 화면에서 JSON 복원 및 Supabase 수동 전송을 실행할 수 있습니다. 자동 동기화는 하지 않습니다. 로그인은 기존 앱을 사용하고 정산 모듈은 인증 토큰을 읽기만 합니다. 토큰이 만료되면 기존 앱에서 다시 연결하도록 안내합니다.

JSON 복원은 기존 원본 JSON 형식을 지원하고 8MB/100,000개 기록으로 제한합니다. 형식·금액·차감·중복 ID·연결 관계를 검증한 뒤 합계를 미리 보여줍니다. 다른 계정/기기 백업은 현재 계정으로 옮긴다는 별도 확인이 필요합니다. 복원은 병합이 아닌 전체 교체입니다. 변경 전 전체 기록 한 벌을 같은 IndexedDB 트랜잭션에서 보관하며, **교체 전 기록**에서 JSON 다운로드 또는 되돌리기를 할 수 있습니다. 다음 교체 때 보관본도 갱신되므로 중요한 기록은 파일로 보관하세요. 저장 공간 부족이면 교체와 보관을 모두 취소합니다.

기기 저장소는 버전 2로 업그레이드하며 기존 documents를 보존하고 sync/recovery 저장소만 추가합니다. 다른 탭의 오래된 화면·복원 미리보기는 revision 확인으로 차단합니다. 복원은 기존 변경 이력을 보존하며 교체 작업의 시각·사유는 복구 스냅샷에 기록합니다.

### 클라우드 충돌 정책

- 신규 테이블 `public.vocal_billing_documents`와 `vocal_billing_save` RPC만 사용합니다. 기존 `vocal_data`, `vocal_media`, 인증/저장소 정책은 변경하지 않습니다.
- 읽기는 인증된 본인 행만 RLS로 허용합니다. 직접 INSERT/UPDATE/DELETE는 차단하고, 쓰기는 auth.uid()를 검사하는 전용 RPC로만 허용합니다.
- RPC는 계정별 트랜잭션 잠금 + 예상 서버 버전 비교를 사용합니다. 동시에 저장하면 한 요청만 성공하고 나머지는 충돌로 반환합니다.
- 서버는 직전 payload/revision 한 벌도 보존합니다. 사용자가 보내는 owner는 JWT의 사용자와 일치해야 합니다.
- 처음 연결한 기기에 이미 다른 클라우드 기록이 있으면 업로드를 차단합니다. 클라우드 가져오기로 비교·확정할 수 있으며 현재 기기 기록은 복구 스냅샷에 남습니다.
- 클라우드 가져오기는 확정 직전에 서버 버전을 다시 확인합니다. 미리보기 이후 변경되면 다시 비교해야 합니다.
- 업로드 응답 유실 후에는 서버 내용이 이미 같은지 재확인하여 중복 저장 없이 연결 상태를 복구합니다. JSONB 키 순서 차이는 무시하고 실제 값으로 비교합니다.
- 네트워크 오류, 만료된 로그인, 계정 변경, 동시 수정은 기록을 지우지 않습니다. API는 15초 제한을 사용합니다.
- 서버의 최종 인증/RLS는 Supabase가 담당합니다. 브라우저 자동화는 인증 API를 모의 처리하며 실제 사용자 로그인/실기기 검증으로 간주하지 않습니다.

마이그레이션 파일: `billing/migrations/20261104_billing_cloud.sql`. 이 파일은 한 번 적용하며, 테스트용 `tests/sql-setup.sql`은 운영 DB에 실행하지 않습니다. 적용/검증 현황은 PR의 최신 결과를 참조하세요.

## 정산 정책

- 원화 정수, 횟수는 0.01회 단위 정수로 보관합니다.
- 사용 금액은 레슨권별 `유효 금액 × 사용 횟수 ÷ 유효 충전 횟수`를 BigInt로 계산하여 원 단위 반올림합니다. 회당 금액을 먼저 반올림하지 않아 완전 소진 시 계약 금액과 일치합니다.
- 수동 조정은 원본 레슨권을 변경하지 않습니다. 유효 금액/횟수에 합산하여 단가와 과거 사용 금액을 재계산하므로 저장 전에 영향을 보여줍니다.
- 순결제 = 결제 합계 − 환불 합계. 미납 = 유효 레슨권 금액 − 순결제. 환불은 레슨권 금액/횟수를 자동 변경하지 않습니다.
- 음수 잔여는 명시적 확인 후 허용합니다. 과납/초과 환불은 음수 미납/순결제 등으로 그대로 표시합니다.
- 같은 Lesson ID는 활성 차감 객체 하나만 허용합니다. 완료 취소는 상태를 취소로 바꾸거나 해당 차감을 취소합니다.
- 날짜만 같다는 이유로 중복 처리하지 않습니다. 결제/수강의 전체 핵심 값, 동일 원본 행 또는 거래 번호 등으로 의심 항목을 표시하고 확인 후 등록합니다.
- 결제 행마다 새 레슨권을 만드는 모드에서는 충전 횟수가 필수입니다. 분할 결제는 기존 레슨권 연결 모드를 사용합니다.
- 노션 수강생 열은 출처 정보로만 보존합니다. 계정 간 자동 분배는 하지 않습니다.
- 업로드는 추가만 지원합니다. 기존 값을 덮어쓰는 모드는 없습니다. 전체 선택 작업은 단일 IndexedDB 트랜잭션으로 처리합니다.

## 파일 호환성

CSV는 UTF-8/BOM, UTF-16 BOM, CP949/EUC-KR, 쉼표/탭/세미콜론, 따옴표/줄바꿈을 처리합니다. XLSX는 ZIP의 stored/deflate 압축, shared strings/inline strings, 숫자, 1900/1904 날짜 체계 및 수식의 저장된 결과를 읽습니다. 수식을 실행하거나 외부 워크북을 요청하지 않습니다. 수식 결과가 저장되지 않은 셀은 사용자가 확인해야 합니다.

제한: 파일 10MB, 데이터 2,000행, 256열, ZIP 2,000항목, 전체 확장 크기 50MB, XML 하나 16MB. 암호화/ZIP64/매크로 형식은 지원하지 않습니다. XLSX 압축 해제에는 `DecompressionStream('deflate-raw')`가 필요합니다. 지원하지 않는 Safari에는 CSV 또는 Safari 업데이트를 안내합니다.

## 검증

```sh
npm ci
node --test billing/tests/*.test.cjs
npx playwright install chromium webkit
npx playwright test --config=billing/playwright.config.cjs
```

전용 GitHub Actions: `.github/workflows/billing-checks.yml`.
브라우저 검증은 Chromium 모바일/데스크톱, WebKit 모바일 뷰포트에서 수행합니다. **WebKit 자동화는 실제 iPhone Safari 검증을 대체하지 않습니다.** 실제 iPhone 파일 앱의 CSV/XLSX 선택, 앱 백그라운드 전환, 저장 공간 부족, 브라우저 데이터 삭제, 실제 계정 전환은 별도 실기기 확인이 필요합니다.

루트 앱 파일·패키지·기존 테스트 설정은 변경하지 않습니다. 기존 서비스의 로그인/클라우드/녹음 등은 이 모듈의 자동화만으로 검증 완료로 표시하지 않습니다.

## 삭제와 복구

각 목록의 삭제 버튼은 정산에서 제외하고 기본 목록에서 숨깁니다. 상단 삭제 내역 보기에서 복구할 수 있습니다. 레슨권은 연결된 활성 결제·수강·조정을 먼저 삭제해야 합니다. 업로드 이력에서는 해당 업로드로 생성한 내역을 일괄 삭제하며, 이후 수정된 항목은 개별 목록에서 삭제합니다.

백업·동기화의 이 기기의 정산 전체 삭제는 현재 계정의 기기 정산 및 복구본을 비웁니다. 앱 레슨·녹음과 클라우드 정산은 삭제하지 않습니다. revision 검사를 통해 다른 탭의 변경을 보호합니다.
