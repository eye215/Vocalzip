# 레슨·정산 연동 안전성 — Phase 10/21

DELETE-21-01 선행 보강 · 2026-11-09 · PR #187

## 이번 수정

1. 정산에서 생성된 앱 레슨을 취소·예정으로 바꾼 경우에도 실제 연결 차감을 복구 대상으로 찾는다. 완료 상태의 수강 기록만 대상이며, 의도적인 당일 취소 차감(noshow)은 자동으로 복구 대상으로 삼지 않는다.
2. 레슨 ID와 정산 차감 ID를 사용한다. 날짜가 같다는 이유로 다른 차감에 연결하지 않는다. 참조가 모순되거나 여러 활성 차감이 걸리면 임의의 항목을 선택하지 않는다.
3. 앱 레슨으로 만든 차감/취소 명령은 레슨 ID·날짜·상태·시작/종료·정산 참조·수정 시각을 메모리에 보관한다. IndexedDB 쓰기 직전 현재 계정의 앱 레슨을 다시 읽고 다르면 거래를 중단한다. 기존 원장 revision 및 행 version 검사도 유지한다.
4. 특정 레슨에 대한 명시적 차감/취소 요청으로 연 정산 화면은 다른 레슨의 자동 차감을 실행하지 않는다. 명시 요청이 실패했을 때도 마찬가지다. 일반 자동 정산 진입은 기존 설정대로 유지한다.
5. 이미 취소된 차감에 같은 요청을 재전송해도 사용 횟수를 추가로 돌려주거나 새 감사 거래를 만들지 않는다. 결제·환불 사실과 다른 레슨의 차감은 유지한다.

## 검증

- 순수 모델: 정산 가져오기 레슨의 취소/예정, 당일 취소 차감 보존, 같은 날짜의 별도 레슨 보존, 모순 참조, 중복 대상, stale 상태/날짜/시간/참조/삭제/수정시각, 반복 취소의 잔액 및 감사 이력.
- 브라우저: 모바일 Chromium/WebKit·데스크톱에서 차감 복구와 새로고침, 확인창 중 레슨 변경, 저장 트랜잭션 대기 중 레슨 삭제, 숨김 프레임의 명시 취소·재시도·실패 시 다른 레슨 보호.
- 전체 정산 단위/브라우저 및 임시 PostgreSQL 회귀 결과, 공개 배포 파일 대조는 PR #187과 Actions에 기록한다. 실계정·실제 미디어를 사용하지 않는다. 실제 iPhone 검증은 별도다.

## 보호 범위

운영 DB 마이그레이션, 사용자 원장 일괄 수정, 결제/환불 API, 미디어 삭제/이동, 기존 레슨 데이터 쓰기를 수행하지 않는다. UI 배치 및 디자인은 유지한다. guard는 입력 검증을 위한 메모리 값이며 인증 토큰이 아니다. 정산 데이터의 DB 스키마는 그대로다.

이 검증은 해당 기기가 받은 앱 레슨 상태를 IndexedDB 저장 전에 대조한다. 앱 레슨과 정산을 서버의 단일 트랜잭션으로 묶거나, 아직 수신하지 않은 다른 기기의 변경까지 확인하는 것은 아니다. 기존 서버 동기화 계약의 운영 활성화와 구분한다.

## 아직 끝나지 않은 삭제 정책

현재 레슨 삭제 화면에는 연결 녹음/정산의 선택 삭제가 없고, 정산에는 기존 삭제 내역 복구 및 이전 버전 복원이 남아 있다. 이번 수정으로 이 화면이나 영구 삭제 정책을 완료했다고 표시하지 않는다. 차감 취소(사용 횟수 반환)와 결제 환불(금전 거래)을 구분한다.

다음 단계는 다음 계약을 먼저 검증한 뒤 작은 단위로 연결한다.

- 사용자 선택 대상과 최종 영구 삭제 확인, 미선택 레슨·녹음·정산 보존.
- 계정에 묶인 작업 ID와 단계별 완료 기록, 중간 실패/타임아웃/재시도 시 결과 확인. 레슨·원장·파일 저장소 사이 원자성이 있다고 가정하지 않는다.
- 정산의 사용 횟수 반환은 중복 없이 처리하고 실제 결제·환불 감사 사실은 별도 최소 기록으로 유지한다.
- 서버 삭제 표식이 오래된 기기 데이터·백업/버전 복원으로 무효화되지 않도록 확인한다. 기존 삭제 표식 보관 상한 및 원장 복원 경로를 검토해야 한다.
- 삭제 기능을 기존 데이터에 일괄 적용하거나 과거 삭제 기록을 자동 정리하지 않는다.
