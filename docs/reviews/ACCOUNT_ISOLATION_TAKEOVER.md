# 계정별 로컬 격리와 다중 로그인 세션 (D20)

## 범위와 상태
사용자 승인으로 단일 활성 세션 초안을 다중 기기 정책 D20으로 전환했다. 이 PR은 로그인 세션 등록/조회/회수·계정별 기기 파일 격리를 구현한다. D21 자동 초안 동기화, D22 필드별 편집 인계, D23 revision 충돌 복구·악보 stroke 병합, D24 태블릿 UX는 별도 후속 개발이다. 인증 세션 수와 텍스트 편집권을 혼동하지 않는다.

`VZIP_DEVICE_SESSIONS_ENABLED` 기본값은 false다. 운영 SQL 적용·서버 설정 변경·R2 파일 변경·배포를 하지 않았다. 과거 단일 세션 마이그레이션은 미병합/미적용 초안이므로 이 브랜치에서 제거하고 `20261112_device_session_contract.sql`로 대체했다. 과거 커밋과 별도 계약 브랜치는 보존한다. 운영에 단일 세션 계약이 적용된 환경의 자동 업그레이드 스크립트로 사용하면 안 된다.

## 서버 계약
- `vzip_device_sessions`: 사용자/검증된 JWT session_id별 로그인, 표시 이름·등록 시각·revoked_at. 표시 이름은 권한이나 물리적 기기 식별자가 아니다.
- `vzip_account_session_state`: 계정별 revision과 서버 전용 한도. 초기 **Auth 세션 3개**는 기본 비활성 상태에서의 검증값이며 물리적 기기 3대 정책을 확정한 것은 아니다. 같은 기기 Safari·홈 화면 PWA가 별도 세션일 수 있고, 여러 탭은 같은 토큰을 공유할 수 있다.
- `vzip_register_session`: 여유 슬롯이면 기존 로그인을 유지하고 등록. 한도 도달 시 `device_limit`과 자기 계정 목록만 반환한다. 선택한 session_id와 확인한 revision을 보내야 한 세션을 교체한다. 계정 행 잠금과 revision 비교로 동시 진입/오래된 승인을 직렬화한다.
- `vzip_list_sessions`: 등록된 현재 세션만 자기 계정의 유효한 로그인 조회.
- `vzip_revoke_sessions`: 현재 세션을 검증하고 한 로그인 또는 전체 회수. 오래된 revision은 목록을 다시 확인하도록 반환한다.
- `vzip_release_session`: 자기 JWT의 세션만 멱등 회수. 지연된 로그아웃이 다른 기기를 종료하지 않는다.
- 회수 행은 유지하므로 오래된 JWT·Auth 콜백은 재등록 불가. 다시 인증해 새 Auth session_id를 받아야 한다. 등록 시 현재 세션은 RPC 인자가 아니라 검증 JWT 및 auth.sessions에서 확인한다.
- `vzip_session_is_active`: 새 요청의 직접 PostgREST·Storage 접근을 기존 소유자 RLS와 AND로 제한. 계정 경계는 유지한다. 회수 전에 이미 실행된 트랜잭션을 취소하는 기능은 아니다.
- SDK와 직접 TUS 전송의 `X-Client-Info: vocalzip-device-session-v2`를 맞춘다. 구버전 계정 미격리 탭이 공유 토큰을 재사용하는 실수를 막는 프로토콜 표식이며 인증 수단은 아니다.
- 레지스트리는 앱 접근을 차단하는 원장이다. Supabase Auth refresh token을 실제로 폐기하거나 모든 service_role 경로를 차단했다고 주장하지 않는다. Supabase 원격 인증 세션 회수도 운영 검증/연동 대상이다.

## 화면과 로컬 자료
- 앱은 인증 확인 전부터 inert 처리하고, 서버 계약 오류 시 잠근다. 여러 등록 세션은 함께 앱에 접근한다.
- 네 번째 진입 시 기본 취소·미선택 상태의 선택창. 선택/확인 전 기존 로그인과 데이터에 쓰지 않는다. 목록 revision이 바뀌면 다시 선택한다.
- 설정의 '로그인 기기 관리': 이름·등록 시각·현재 로그인, 개별 회수·현재 기기 로그아웃·전체 로그아웃. 한 다이얼로그 안에서 최종 확인하고 키보드 포커스·Escape·내부 스크롤·Safe Area를 처리한다.
- 현재/전체 로그아웃은 업로드를 멈추고 진행 녹음·미저장 미리듣기를 원래 계정의 IndexedDB에 보호한 후 서버 회수한다. 보호 실패면 회수하지 않는다.
- 원격 회수는 20초 주기/포커스 복귀 때 확인해 앱과 토큰 접근을 잠근다. 오프라인·API 오류는 서버 상태를 확인했다고 간주하지 않는다. 새 요청은 서버 가드를 따르고 해당 기기의 미전송 자료는 보존한다.
- localStorage/IndexedDB·업로드 큐·스냅샷·R2 URL 캐시는 계정별로 격리한다. 계정 전환은 보호 완료 후 전체 페이지를 다시 열며 이전 비동기 클로저는 원래 계정 공간에 고정한다.
- 기존 `vocal-zip_mvp_v1`/`vocalzip_media_v1`은 자동 병합·삭제하지 않는다. 소유 계정 명시 확인 후 ID/원본을 보존해 복사하고 로컬·클라우드 중복/삭제 표시는 덮어쓰지 않는다. Web Locks로 소유 계정 선택·복사를 직렬화한다.

## 검증 방법
별도 임시 PostgreSQL에서 다중 등록·4번째 거절/명시 교체·동시 요청 CAS·특정/전체/지연 로그아웃·회수 토큰 재등록 거부·계정/RLS/Storage/프로토콜 검사를 실행한다. 브라우저는 Auth/API 대역으로 슬롯 선택·취소·다중 탭·세션 관리·회수 잠금·녹음 보호·이전 원본 보존을 검사한다. Linux WebKit 가상 녹음 미지원 케이스는 건너뛰며 실제 iPhone 검증으로 간주하지 않는다. 실제 실행 결과는 PR에 기록하고 미실행 항목은 완료로 표시하지 않는다.

## 운영 활성화 차단 항목
1. 별도 billing 클라이언트의 계정 격리·프로토콜, 사용자 SECURITY DEFINER RPC·Edge Function/service_role 경로에 같은 세션 검증 필요.
2. R2 Worker의 등록/회수 세션 검사·CORS·기발급 signed PUT 완료 검증·signed GET 만료/철회가 필요. RLS는 R2에 적용되지 않는다.
3. 실제 Supabase JWT/Auth session_id·refresh token·개별/전체 원격 회수 및 Safari/PWA 세션 셈법·최대 한도 정책 확정 필요.
4. 기존 payload 병합은 필드별 초안 revision/편집 lease 계약이 아니다. D21~D23을 갖추지 않은 상태에서 다중 기기 편집의 무손실을 완료로 표시하거나 기능을 일괄 활성화하면 안 된다.
5. iPhone/iPad 실제 녹음 중단·오프라인·저용량·계정 전환·동일 계정 여러 기기·구버전 탭/캐시 조합 검증 필요.
6. 서버 확인 후 기기 캐시 정리/공간 상한은 후속 작업이다. 미전송 원본은 자동 삭제하지 않는다.
7. 클라이언트·RPC·RLS·Worker 버전을 함께 준비하고 제한된 검증 환경에서 확인해야 한다. SQL을 먼저 운영에 적용하면 기존 앱이 잠긴다.
