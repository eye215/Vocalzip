# 사진 영상 음원 추출: 원본 재읽기 감소

## 원인과 변경

기존 추출기는 영상에서 음원 패킷을 복사한 뒤, 검증할 때 원본 영상의 패킷을 다시 읽었다. 영상·음원이 교차 저장된 실제 MOV/MP4에서는 작은 음원 검증을 위해 큰 원본 전체 범위를 두 번 읽을 수 있다.

새 경로는 복사하면서 음원 바이트의 1MiB 블록 SHA-256과 패킷 길이·시각·지속시간을 기록한다. 추출된 음원에서 같은 정보를 만들어 대조한다. 코덱·샘플레이트·채널·패킷 경계·타이밍 검증은 유지한다. 재인코딩이나 음질 저하는 없다.

- 최대 4트랙, 전체 65,536패킷 이내에서만 빠른 증명을 사용한다. 블록 버퍼/숫자 배열을 제한하며 전체 영상/음원 버퍼를 만들지 않는다.
- 모듈/WebCrypto 불가·증명 예산 초과면 기존 원본 바이트 직접 비교로 돌아간다.
- 해시·패킷 길이·시각·지속시간 불일치는 업로드 전에 오류로 처리한다. null 증명은 저장 승인이 아니다.
- 원본 요청 읽기량·요청 수·복사/검증 시간·사용 경로를 기존 audioExtraction 메타데이터에 추가한다. 읽기량은 File.slice 요청 바이트이며 실제 iCloud 네트워크 사용량을 뜻하지 않는다.
- iOS 사진 선택기가 File을 앱에 넘기기 전의 다운로드/준비 시간은 앱 내부 처리와 구분한다.

## 실제 브라우저 측정

[검사 42642513406](https://github.com/eye215/Vocalzip/actions/runs/42642513406), 소스 `de0417671eb44f29ca763e9a992a88a8f6c72ee6`. 20초·약16MB 영상/음성 교차 저장 픽스처를 Chromium 데스크톱에서 같은 파일로 비교했다.

| 항목 | 기존 직접 비교 | 블록 증명 |
|---|---:|---:|
| 원본 File 요청 바이트 | 32,042,800 | 16,021,400 |
| 원본 읽기 요청 | 488 | 244 |
| 복사 시간 | 308ms | 229ms |
| 검증 시간 | 297ms | 8ms |
| 추출 음원 크기 | 386,148 | 386,148 |
| 음성 패킷 수 | 939 | 939 |

테스트는 최적화 결과의 음성 패킷을 원본과 다시 **직접 바이트 비교**하여 모두 일치하는지도 검증했다. 기존 방식은 비교 실행 때만 모듈을 비워 강제했고, 원본 직접 비교가 계속 정상 수행됨을 확인했다. 순서/캐시/환경의 영향이 있는 단일 데스크톱 비교이므로 iPhone 속도가 같은 비율로 빨라진다고 일반화하지 않는다.

## 검증 결과

단위 47 통과/1 skip(기존 비교 벤치마크의 선택적 기준 커밋 미지정). 실제 파서/영상 23 통과/4 skip, 가져오기 26 통과/1 skip, R2 브라우저 79 통과/5 skip. SHA-256은 Node 독립 구현과 대조하고, 바이트 변경·패킷 누락/순서/경계·시각 변경·상한 초과·암호 API 실패를 검사했다.

코드/시험 변경이며 운영 DB·기존 미디어·AI·공통 UI/CSS는 변경하지 않는다. 실제 iPhone 사진/iCloud 파일 전달 대기와 기기 저장 공간 부족은 아직 별도 실기기 검증 대상이다. #207의 일반 업로드 개선과 함께 배포 결과를 PR에 기록한다.
