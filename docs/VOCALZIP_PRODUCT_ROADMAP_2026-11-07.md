## 1. 출시 전략

- **Release 1.0: 학생용 전체 기능 PWA 우선 출시.** 학생이 선생님 계정 없이도 곡·녹음·연습·개인 레슨 기록·숙제·성장·공연·개인 악보 필기·유효성이 검증된 AI 기능을 사용할 수 있도록 한다. iPhone Safari/홈 화면 설치 PWA에서 실기기 검증한다. 스토어용 네이티브 앱은 추후 별도 결정한다.
- **Release 2.0: 선생님 기능 출시.** 학생과 선생님의 N:M 연결, 1:1 개인 레슨, 1:N 그룹 레슨, 복수 강사, 예약·출석·피드백·숙제·수강권 및 레슨비 관리를 추가한다.
- 학생 기능을 미완성 MVP로 급하게 출시하지 않는다. 학생용 1.0을 하나의 **완성된 상품**으로 검증한 후 선생님 기능을 확장한다.
- 개발 단위는 **30개 Phase 초안**이다. 30이라는 숫자는 고정되지 않으며, 실제 코드 조사 결과에 따라 병합·분리한다.
- 과거 Phase와 PR 번호를 이 문서 기준으로 소급 변경하거나, 문서만 보고 완료 처리하지 않는다.

- **우선 실행:** Phase 03에서 추후 공유 권한을 설계하고, Phase 07-A 보관 안정화 후 **07-C 개인 필기부터 착수**한다. 07-C는 OMR 성공과 독립적이다. 07-B와 16의 정밀 평가는 별도 검증·비용 관문을 통과해야 한다.
- **원본 원칙:** 업로드한 PDF는 변경하지 않는다. PDF→MusicXML 변환은 원본 PDF를 입력으로 사용하고 필기 포함 PDF 내보내기 파일을 자동 입력으로 쓰지 않는다. 필기는 PDF 페이지·좌표·기준 PDF 버전에 연결한다. 악보 교체 시 기존 필기를 임의로 다른 페이지에 재배치하지 않는다.
- **학생별 차이:** 기본 MusicXML이 재사용 가능해도 성부·조옮김·교정본은 **학생/그룹/회차별 변형 버전**을 별도 저장한다. 학생별 필기 역시 독립이며 같은 원본 PDF를 참조한다고 자동 공유하지 않는다. 타 계정 파일 dedup/공유는 소유권·저작권과 서버 권한을 검증한 경우에만 허용한다.
- **PWA-first:** 설치 아이콘·독립 실행·모바일 UI는 목표지만 **iOS에서 잠금 화면/타 앱 전환 후 백그라운드 녹음은 보장하지 않는다**. 화면 깨움 시도·중간 저장·중단 복구를 우선 적용하고, 지속 녹음이 출시 필수 조건으로 확정되면 네이티브 PoC와 별도 앱 Phase를 다시 결정한다. Pencil 필압·손바닥 방지는 실기기 평가가 필요하다.
- **하위 Phase 추가만 적용:** 01~30 상위 번호와 1.0/2.0 범위를 유지한다. 향후 스토어 앱은 기존 22·23을 병행 완료로 간주하지 않으며 별도 승인·일정이 필요하다.

## 3. 학생용 1.0 정보구조(IA)

## 4. 개념 데이터 구조(운영 DB 스키마 아님)

- **사용자:** 인증 사용자 → 프로필, 사용자 역할.
- **관계:** 선생님·학생 연결(N:M), 그룹·그룹 구성원.
- **레슨:** 레슨 회차, 담당 강사, 참여 학생(개별 출석·정산 상태).
- **학습:** 곡·곡 별칭·가사·원본 악보(PDF)·확정 MusicXML/변형 버전·개인/공유 필기 레이어, 연습·연습 미디어, 숙제·학생별 수행, 피드백·공개 범위.
- **미디어:** 소유자, 원본·파생본, 실제 저장 객체(청크), 접근 허용 대상·만료. **공유는 소유권 이전이나 사용량 중복 차감이 아니다.**
- **AI:** 전사·곡 추천·분석·작업 상태·사용량.
- **정산:** 선생님 레슨 상품·학생별 수강권·차감 원장·결제 기록과, 앱 구독 상품·사용량 기록을 별도 관리한다.
- **공연:** 공연·출연진·공연곡·미디어 연결.

실제 PK·FK·제약·RLS·감사 이력은 Phase 03에서 확정한다. **미래 기능 테이블을 1.0 시점에 전부 미리 만들 필요는 없다.**

## 5. 반드시 지킬 정책

1. 리팩터링을 이유로 기존 사용자 기록을 초기화하거나 원본 파일을 덮어쓰고 삭제하지 않는다.
2. 기존 계약을 확인한다: localStorage `vocal-zip_mvp_v1`, IndexedDB `vocalzip_media_v1/recordings`, Supabase `vocal_data.payload`, 별도 정산 프로젝트 `billing/`.
3. **녹음 파일과 연습 기록은 별개**다. 녹음을 연습에 연결해도 연습 시간을 추가하지 않는다. 레슨 삭제 시 **녹음도 영구 삭제할지, 연결된 정산 기록도 삭제/취소할지 각각 확인**한다. 기본값은 레슨만 삭제(나머지는 보존). **모든 사용자가 직접 삭제하는 레슨·선택 녹음은 즉시 영구 삭제/복구 불가**이며, 공유 참조 파일은 영향 확인을 추가한다. 정산에서 삭제할 때에도 연결 레슨 삭제 여부를 묻는다. 실제 운영 삭제 적용은 데이터 무결성·보안 테스트 후 별도 승인한다.
4. 학생이 직접 입력한 **선생님 이름 문자열**은 인증된 선생님 계정이 아니다. 나중에 가입했다는 이유로 권한을 자동 부여하지 않는다.
5. 그룹의 공통 수업 정보만 참여 학생에게 공유한다. 개인 피드백·녹음·결제는 기본 비공개다. **그룹 가입 ≠ 해당 회차 출석**, **수업 완료 ≠ 모든 학생 일괄 차감**.
6. Supabase는 구조화된 데이터·인증, R2는 **계획된** 미디어 저장소다. 실제 연동 여부는 조사 후 판단한다.
7. 원본 미디어의 식별자·촬영/녹음 날짜·출처를 보존한다. 음질이 최우선이며 영상 압축본을 만들 때도 원본 보존 여부를 명확히 안내한다.
8. 개인 데이터 이전은 명시적으로 허용한 사용자 1개 계정에만 제공한다. 영상 후보: **2025-12-31~2026-09-13**, 음성 메모 후보: **2025-07-24~가져오기 실행일**, 길이 **30초~8분**. 검토·승인 후 가져온다. 웹앱은 아이폰 음성 메모 전체를 몰래 읽을 수 없다.
9. **학생 요금제 가격·용량은 가안**이다: Free 1GB, Plus 20GB/월 4,900원, Pro 100GB/월 9,900원. 선생님 요금제 미확정.
10. 구독 만료 후 **29일 유예, 30일 차 초과 미디어 정리**는 논의된 정책일 뿐이다. 법률·고지·동의·내보내기·복구 검토 전 자동 삭제를 구현하지 않는다.
11. AI 음정·호흡·발성 진단이 이미 완성됐다고 표시하지 않는다. 지표·모델·불확실성을 검증한다.
12. GitHub에 비밀키·토큰·개인 녹음·민감한 사용자 데이터를 올리지 않는다.

### 영상 업로드·보관 정책 (2026-11-07 확정)

- **학생용 1.0 공개 서비스에서는 영상 파일의 업로드·가져오기를 제공하지 않는다.** 일반 계정은 음성 파일 업로드·녹음만 사용한다.
- **영상 파일 가져오기·업로드는 서비스 소유자 계정 1개에만 임시 허용**한다. 계정 ID를 서버 측 허용 목록으로 검증한다. 버튼 숨김만으로 접근 제어하지 않는다.
- 소유자 계정의 영상은 **최대 10분(600초)**까지 허용한다. 순수 음성 파일에는 이 영상 전용 시간 제한을 그대로 적용하지 않는다.
- 소유자는 영상마다 **① 원본 영상 저장 ② 압축 영상 저장(720p 목표) ③ 음성파일로 변환하여 저장** 중 하나를 선택한다.
- **영상으로 저장한 자료는 영상 보관함 항목**, **음성으로 변환한 자료는 음원 보관함 항목**으로 각각 표시한다. 영상과 추출 음원을 하나의 자료 화면으로 강제 묶지 않는다.
- 음성 변환 선택 시 영상 트랙을 저장하지 않으며, 원본 영상 저장/압축 영상 저장을 선택하면 사용자 승인 없이 음원을 별도 보관함 파일로 중복 생성하지 않는다. 분석용 임시 음원은 사용자 보관함과 구분한다.
- 압축·변환은 가능한 한 **기기에서 수행**하여 변환 서비스 비용을 줄인다. 기기 미지원 형식이나 처리 한계가 있다면 **서버 변환의 별도 비용을 검토한 뒤 안내**하고, 무단으로 서버 변환 작업을 실행하지 않는다.
- 기존 사용자 데이터·기존 미디어는 이 정책을 도입한다는 이유로 소급 삭제하거나 변형하지 않는다.
- 이 정책은 **기획 확정 / 개발 미반영**이며, Phase 01 분석·기술 검증·승인 이후 구현한다.

### 다중 기기·작업 이어받기 정책 (2026-11-07 D20~D24 추가)

- **기존 '단일 활성 세션' 결정을 대체한다.** 휴대폰·태블릿·PC 동시 로그인, 선택 기기 종료, 다중 편집 안전성을 지원한다. 초기 **3기기 목표는 구현/검증 조건부**이며 PWA·브라우저를 하나의 물리적 기기로 셀 수 있는지는 별도 검증한다.
- 노트·레슨 내용의 **로컬 자동 초안 → 클라우드 확인 → 다른 기기 [이어서 작성하기]**를 지원한다. 서버 전송 안 된 오프라인 작성 내용은 다른 기기에서 임의로 불러오지 않는다.
- **동일 텍스트 필드:** 한 기기가 활성 편집, 안전 인계/서버 revision 검사, 두 기기 수정 충돌 발생 시 사본 보존 및 명시적 해결. **다른 필드:** 동시 수정 가능.
- **악보 필기:** PDF 원본 보존, 작성자/레이어/스트로크 단위 변경 병합·버전 확인, 중복/삭제 충돌·권한 분리 테스트. 실시간 공동 드로잉 표시까지 필수로 요구하지 않는다.
- Phase **04-A/05-A/05-B/07-C-1/25-A**와 정책서 [D20~D24](product/PRODUCT_DECISIONS_V1_2_2026-11-07.md) 참조. 이 사항은 개발 명세/일정 업데이트일 뿐 **구현 완료가 아니다**.
