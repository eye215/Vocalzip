## 3. 요구되는 신규 분석 (제품 계약 제안)

### 3.1 전체 음역 시계열

- 저장된 **곡 지정 녹음**과 **곡 미지정 음성 파일**은 커버리지/유효성을 별도로 표시하고, 사용자가 원하는 '전체 녹음' 정의를 최종 결정한다. 악기·MR·무음 등 음성으로 검증되지 않은 구간은 음역 집계 제외.
- 기간별 **관측 최저음 / 관측 최고음 / 주 가창 음역 / 안정 최고음·가능하면 안정 최저음**을 구분. 현재 분석 v2 스키마에서 하한·지속시간·신뢰도 추출 가능 여부를 먼저 감사한다.
- 월별 곡 구성 차이에 따른 왜곡을 방지: (a) 각 월에서 **관측한 범위**와 (b) 두 기간에 모두 존재하는 **동일 곡·비교 가능한 프레이즈** 기반 변화 추정을 분리.
- 데이터 포인트마다 분석된 녹음 수, 곡 수, 유효 발성 시간, 버전 및 불확실성을 표시.
- 상한과 하한을 그래프/피아노 건반에 함께 표시하되 누락값을 0으로 대체하지 않는다.
- 상·하향 이동을 곧 실력 향상/악화로 판정하지 않는다.

### 3.2 파사지오 변화

- 기존 `passaggioOf`는 pitch band 내 음높이 흔들림이 커지는 음역을 찾아 **참고** 표시하는 기능일 뿐이다.
- 매월 충분한 표본·비슷한 발성 조건이 있을 때만 참고 구간의 반복 출현/흔들림 크기를 비교한다.
- 성구 전환의 실제 위치, 성대 긴장, 믹스 보이스 여부는 자동 판정하지 않는다.
- 표본 부족/분석 버전 불일치/기준 불충족 시 '판정 보류'로 표시하고 필요 시 반복 측정 훈련으로 연결한다.

### 3.3 데이터와 AI 해석

- 수치 해석과 AI 자연어 요약을 분리한다. AI는 실측 지표·신뢰도·비교 조건만 설명하며, 음역이나 파사지오의 '성장 확정' 표현을 생성하지 않도록 한다.
- 서버는 현재 음역·파사지오 지표를 입력받지 않는 것으로 보이므로 **서버 계약/프롬프트/검증**을 별도 PR로 진행한다.
- 모델 없이도 근거 지표를 조회할 수 있어야 하며 AI 실패는 화면을 막지 않는다.
- 가짜 테스트 데이터로만 단위·UI 검사를 수행한다.

## 4. 라우팅·UI 이전 계획 (승인 이후)

1. `#/vocal-growth`를 성장 기본 진입으로 유지. 최상위 탭 **결과 리포트 / 보컬 분석 / 보컬 트레이닝** 추가.
2. 기존 `#/vocal-lab/:songId`, `#/vocal-lab?selection=1`, `#/lab-reports`, `#/compare`, `#/practice-room` 딥링크와 곡 상세 링크를 보존한다.
3. 보컬 분석은 기존 연구소의 곡별 UI를 재사용하되, 최상위 보컬 분석 탭에서 곡/녹음 선택으로 진입하도록 제공한다.
4. 보컬 트레이닝은 기존 연습실의 입력·녹음·제출·계정 이동 가드를 유지하며 진입점만 추가한다. 제출 중 뒤로 가기/탭 이동 시 경고 및 미저장 데이터 보존 정책 검증.
5. 디자인은 `design-system/tokens.css` 공통 토큰, 다크 집중 화면 예외, iPhone Safe Area 규칙을 따른다.
6. 구현 파일의 동시 작업을 확인하고 변경 PR 단위를 분리한다. 특히 `app/vocal-lab.js`, `app/core.js`, `cloud-sync.js`는 충돌/데이터 위험 최소화.

- **자료 손실(P0)**: localStorage `vocal-zip_mvp_v1`, IndexedDB `vocalzip_media_v1/recordings`, Supabase `vocal_data.payload`, 별도 `billing/` 불변. UI 개편으로 실제 미디어/기록을 이동·삭제하지 않는다.
- **현재 측정 해석(P0)**: 음역 데이터와 파사지오 추정치에 실제 분석이 아닌 임의 결과를 넣지 않는다.
- **경로 호환(P0)**: 과거 비교·연구소·성장·연습실 링크 및 뒤로 가기.
- **병행 작업(P0)**: 사용 중인 파일과 PR이 겹치면 PR 분리·리베이스.
- **테스트 미실행**: 본 문서는 GitHub 파일 열람으로만 확인. 브라우저·Node 테스트 실행, iPhone Safari/PWA 사용성 검증, 운영 상태 확인은 **미완료**.
