# P0 서버 자동 STT 비용·자동 곡 확정 차단

기준 main: `6dd838934b4b27731c12d06f9ef3dd0530d4596e` · 정책 v1.2 · S03/S15의 첫 안전 조치

## 변경

- 예약/업로드/수동 workflow 실행 모두 새 유료 전사를 하지 않는다. OPENAI_API_KEY 존재나 kinds=song 입력도 사용자의 승인·상품 권한·예산 예약을 대신하지 못한다.
- 저장된 전사가 없는 곡 작업은 review/requiresRequest로 남긴다. 분석용 파일 다운로드·디코딩이나 STT API 호출을 하지 않는다. 기존 무료 vocal 작업은 계속 처리한다.
- 이미 있는 개인 전사는 API 키 없이 재사용한다. 가사가 바뀐 뒤 재확인도 후보만 저장하며 곡 필드를 자동 수정하지 않는다. 사용자 지정곡은 보존한다.
- Analysis worker workflow에서 OPENAI_API_KEY 주입을 제거한다. 기존 시크릿 값·운영 cron·DB·파일은 변경하지 않는다.

## 미완료·적용 경계

유료 요청·Plus/Pro 권한·일간/월간 파일·분·동시성·서비스 전체 예산·멱등 예약이 갖춰질 때까지 이 워커의 새 유료 전사는 닫혀 있다. 이 PR은 정식 유료 분석을 구현하지 않는다.

기존 브라우저 요청형 Supabase Edge Function vzip-song-stt는 별도 경로다. 현재 allowlist/예약 RPC가 있지만 최신 한도·요금제·전체예산 정책 충족 여부는 후속 검증이 필요하다. 이번 PR로 서비스의 모든 유료 호출이 통제됐다고 주장하지 않는다.

PR 병합 전 운영 main 워커에는 반영되지 않는다. 운영 cron 변경이나 긴급 중단은 실행하지 않았다. 배포/기존 PR 병합도 실행하지 않는다. main 반영 전 이미 시작한 구버전 워커를 이 코드로 소급 중지할 수는 없다.

## 검증

실제 임시 PostgreSQL·ffmpeg 및 로컬 R2/STT 대역으로 기존 작업 큐 회귀 검사를 갱신했다. 100파일·두 워커 동시 처리에서 무료 측정 유지/유료 호출0/자동확정0, 기존 전사 재사용·키 없음·가사 변경·직접 지정 보존·삭제·실패 재시도를 검사한다. CI 실행 결과는 PR에서 확인한다. 실물 iPhone·운영 DB/R2 검증은 이 변경에서 수행하지 않는다.
