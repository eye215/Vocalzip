## P0/P1

- 업로드 파일 형식·빈 파일·500MB·로그인 검사를 곡 선택 전에 수행한다. 곡 선택 취소는 파일 참조와 입력 잠금을 해제한다.
- 기존 곡 선택 / 새 곡 등록 / 나중에 지정, 곡 목록 저장 실패와 재시도, 새로고침 후 유지 검증을 추가했다.
- 그룹 기준은 songId. 같은 제목의 다른 ID는 분리한다. ID 없는 이전 파일은 legacy 그룹, 제목도 없는 파일은 미지정 그룹으로 표시하며 기존 데이터는 변경하지 않는다.
- 보관함·비교 화면에서 저장한 데이터가 이후 레슨/연습 저장으로 덮어써지는 메모리 상태 불일치를 수정했다.
- 클라우드 백업 메타데이터에 파일별 rating/review를 보존한다. 바이너리를 메타데이터로 보내지 않는다.
- 기존 6MiB TUS 청크, 전체 파일 읽기/디코딩 회피, 업로드 잠금·취소·재선택 흐름은 유지한다.

- 변화 메모와 다음 연습 목표 저장/재열람. 저장 실패 시 입력 유지, 중복 생성 방지.
- 곡별 전체 연습 횟수/기록된 시간, 날짜순 녹음 만족도, 이전/최근 녹음 비교 진입.
- 같은 곡의 비교 리포트에 직접 작성한 개선점과 목표를 줄별 동일 문구 빈도로 집계. 음성 분석이나 의미 분석을 수행하지 않는다.

## P5 및 남은 검증

실제 iPhone은 미검증이다. 아래 항목은 실제 기기/테스트 계정에서 수행해야 한다.

- 사진 앱의 MOV/MP4(HEVC 포함), 파일 앱 M4A/MP3 가져오기 및 Safari 재생.
- 25MB 전후, 100MB, 500MB 파일의 실제 메모리 최고 사용량과 탭 종료 여부.
- 진행률, 취소, 네트워크 끊김 후 원본 재선택, 백그라운드/화면 잠금 복귀.
- 키보드가 열린 곡 선택/감상/레슨 편집 화면과 실제 날짜 입력 UI.
- 운영 Supabase 인증·RLS·스토리지 등록, 다른 기기에서의 데이터 일치.

서버와 IndexedDB 사이의 완전한 원자적 트랜잭션, 여러 기기의 동시 수정 충돌 해결, 새로고침 뒤 대용량 전송 이어받기, 미완료 스토리지 객체 정리는 이번 변경 범위에 포함하지 않는다. 클라우드 수정 성공 뒤 로컬 저장이 실패하면 오류를 표시하고 재시도가 필요하다.

기존 데이터 삭제/초기화/마이그레이션 및 서비스 배포는 수행하지 않았다.

## P5 후속 확인 — 운영 설정과 업로드 생명주기

- Supabase 대시보드에서 운영 프로젝트 `chxnbtiyuyhiywzeshis` / vocalzip / 서울 리전을 확인했다.
- 버킷 `vocal-recordings`는 500MB·MIME Any로 표시되지만, Storage Settings의 Global file size limit는 **Free Plan 고정 50MB**다. 앞선 500MB 안내는 실제 운영 제한과 달랐다.
- 앱 보관함/연습/클라우드 가져오기 검사를 50MB로 일치시켰다. 25MB 초과 원본 TUS 전송 방식은 유지한다. 요금제나 서버 설정은 바꾸지 않았다.
- Storage의 authenticated SELECT/INSERT/UPDATE/DELETE 정책 4개 존재를 확인했다. INSERT의 WITH CHECK와 UPDATE의 USING/WITH CHECK는 버킷 ID와 첫 경로 폴더=auth.uid()를 검사한다. SELECT/DELETE 조건 및 public 테이블 RLS 전체는 아직 확인하지 않았다. 실제 계정 간 접근 차단 테스트 완료를 의미하지 않는다.
- 진행률 50% 표시, 합성 pagehide 취소, 취소 이후 지연된 성공/실패/진행률 콜백 무시, 다음 업로드 가능 여부를 자동 검사한다. 실제 iOS 백그라운드 이벤트나 메모리 측정이 아니다.
- metadata 저장 도중 계정이 바뀌면 이전 계정의 파일을 현재 연습에 붙이지 않도록 업로드 완료 후 계정을 다시 확인한다. 저장된 원본은 원래 계정에 남는다.
- Supabase 커넥터에는 여전히 다른 조직만 노출돼 대시보드를 읽기 전용으로 확인했다. 운영 데이터 쓰기/삭제, RLS 변경, 요금제 변경 없음.
