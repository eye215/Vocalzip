# MR 시작점 탐색의 구간 누락 수정

기존 첫 단계는 녹음 처음·중간·끝의 15초 onset 구간만 사용한다. 별도 파형 탐색의 5개 anchor도 정답을 놓칠 수 있다. 기존 첨부를 읽기 전용으로 디코딩해 끝에 무음 1.792초를 추가한 파생 입력에서, 기존 엔진이 정렬을 거절하는 현상을 재현했다. 전체 구간의 onset을 살펴보면 실제 시작점이 수십 개 창에서 반복 검출된다. 길이가 조금 달라졌다는 이유만으로 이 증거를 놓쳐서는 안 된다.

## 구현

- 기존 onset·파형·local 검증이 모두 실패할 때만 전체 구간 onset 재탐색을 수행한다. 기존 성공 경로를 재실행하지 않는다.
- 15초 창을 기본 5초 간격으로 배치한다. 긴 입력은 간격을 늘려 최대 64개 격자 창과 기존 3개 창 이내로 제한한다. 서로 다른 창에서 반복된 위치를 우선하고 최대 12개 후보만 재검증한다. 겹치는 창의 검출 횟수는 신뢰도 확률이 아니다.
- 기존 8kHz anchor·local coverage·held-out 예측 검사를 유지한다. 새 경로에는 **직접 유효한 local 창의 비율 85% 이상**을 추가로 요구한다. 보간으로 채운 coverage만으로 승인하지 않으며 음정 신뢰도 기준도 변경하지 않는다.
- 실패 시 후보 수·최대 반복 횟수·anchor 통과 수·최대 직접 일치 비율·최대 coverage를 숫자로 진단에 남긴다. 파일명·ID·URL·음원은 포함하지 않는다. 두 최대 비율은 서로 다른 후보에서 나올 수 있으며 하나의 후보를 의미하지 않는다.
- MR 모듈 v7 / 비교 page·Worker v10 / 모델 파일 v8(측정 모델 `vp-0.2` 유지) / 일반 분석 Worker v13 / 캐시 `cancel-v7`. 원본과 기존 녹음 분석·DB 구조는 변경하지 않는다.

## 검증

합성 MR의 여러 위치에 고립된 15초 반복 구절을 넣어 기존 3개 창의 후보 목록에서 실제 위치가 빠지는 실패 테스트를 먼저 작성·확인했다. 수정 후 전체 창의 반복 일치가 실제 위치를 최상위에 올리는지, 후보·창 개수 제한과 단조 진행률을 검증한다. 기존 잘못된 MR·다른 편곡·무반주·무음 거절 및 정렬·시계 오차·메모리·취소·Worker 회귀도 실행한다. 최종 결과와 처리 비용은 PR 본문/Checks에 기록한다. 자동 테스트에는 합성 데이터만 사용한다.

기존 첨부로 만든 끝 무음 파생 입력은 수정 후 약 1.640초에 정렬되고 전체 길이를 보존한다. 이 수동 검증은 저장소 밖에서만 수행하며 실제 파일·진단 원본은 GitHub/CI에 올리지 않는다. 저장 메타데이터의 파일 크기·형식·길이도 읽기 전용으로 확인했으며 운영 데이터에 쓰지 않았다.

화면 배치 변경은 없다. 기존 합성 화면은 [자동 정렬 검토](MR_AUTO_START_2026-11-17.md)에 있다. 실제 iPhone의 실패 입력이 위 무음 파생 입력과 동일한 파형이라는 증거는 없으므로 해당 iPhone 문제의 해결을 확정하지 않는다. 내부 편집이나 다른 속도의 입력은 이번 재현으로 검증하지 않았다. 실패할 경우 측정을 보류하며 원본을 유지한다.
