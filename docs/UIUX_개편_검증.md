# VOCAL.zip v5.7 UI·UX 구조 개편

기준 main: 320e6b66050b4cfea2682be2c9d223cc72f2ceae.
docs/VOCALzip_Codex_인수인계_2026-11-03.md를 전체 확인한 뒤 기존 데이터 흐름과 화면 조립 순서를 분석했습니다.

## 화면 구조

- 홈: 연습 시작/레슨 기록 진입점, 기존 기록 수, 실제 저장된 연습 데이터의 이번 주 시간, 최근 기록.
- 레슨: 기록 목록과 4단계 작성 화면. 기존 레슨·숙제·녹음 메모 입력을 유지합니다.
- 연습: 기록 목록과 작성 화면. 트레이닝/곡 연습, 만족도·메모, 폼 내부 녹음·녹화·파일 가져오기.
- 보관함: 파일 가져오기, 유형·출처 필터, 파일별 재생·수정·삭제, 기존 비교 진입.
- 성장: 비교 시작, 곡별 아카이브와 타임라인, 저장된 비교 리포트.
- 설정: 계정·클라우드/곡/항목/백업으로 구분. 패널을 이동해도 폼을 제거하지 않습니다.

모바일은 하단 5개 메뉴와 상단 설정, 넓은 화면은 왼쪽 메뉴를 사용합니다.
퍼플 계열을 유지하고 장식·그라데이션·중복 제목을 줄였습니다. 입력 16px, 터치 영역 44px 이상, safe-area, 키보드 초점과 동작 줄이기 설정을 반영했습니다.

## 코드 구조와 보존 범위

- ui.js: 탭 이동, 접근성 상태, 작성 내용 유지, 미디어 저장 중 연습 제출 잠금, 저장 완료 안내.
- ia-v3.js: 홈·기록 목록/작성·설정·성장 화면 구조. library-growth-ux.js의 중복 조립을 통합했습니다.
- ui-refresh.css: 공통 시각 스타일. glass.css와 library-growth-ux.js는 파일을 보존하고 활성 로드만 제거했습니다.
- 기존 폼 id/name, 레슨 녹음기, 보관함, 비교/리포트, 인증·동기화 구현은 유지합니다.
- localStorage 키 vocal-zip_mvp_v1, IndexedDB vocalzip_media_v1/recordings를 유지합니다.
- practiceMode/technique를 연습 기록에 추가합니다. 기존 레코드 일괄 변환·삭제는 하지 않습니다.

## 확인하고 수정한 문제

1. 전역 section 숨김 규칙과 탭 이동이 내부 작성 패널까지 처리했습니다. 내부 패널을 div로 바꾸고 이동 범위를 최상위 화면으로 제한했습니다.
2. 연습 만족도·메모를 form 밖으로 이동하던 DOM 조립을 수정했습니다.
3. 설정 목록 뒤에 모든 설정 카드가 노출되던 구조를 숨김 패널로 정리했습니다.
4. 제출 시도만으로 작성 화면을 닫거나 레슨 임시 저장을 지우던 흐름을 저장 성공 이벤트로 변경했습니다.
5. localStorage 저장 실패 시 작성 내용을 유지하고 방금 추가한 연습/레슨·숙제 변경을 되돌립니다.
6. 연습 미디어 저장 중 제출을 막고 가져온 파일·직접 녹음 길이를 id별 한 번만 합산합니다.
7. 파일을 메모리 Blob으로 옮겨 저장하고, WebKit이 Blob 저장을 거부하면 ArrayBuffer bytes로 대체합니다. 연결 파일 재생은 두 형식을 모두 읽습니다.
8. 연습 파일이 레슨 녹음 메모에 혼합되지 않도록 source를 확인합니다.
9. 저장한 연습 기록에 연결 파일 펼치기와 재생 컨트롤을 추가했습니다.
10. 트레이닝 초기 시간을 0분으로 두어 입력하지 않은 시간이 저장되는 것을 방지합니다.
11. 탭 이동 시 다른 화면의 재생을 멈추고 비교 플레이어 URL을 해제합니다.

## 실행 및 검증

정적 앱이므로 개발 서버 외 런타임 빌드가 필요 없습니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

자동 검사:

```sh
npm install --ignore-scripts
npx playwright install chromium webkit
npm run test:syntax
npm run test:ui
```

GitHub Actions UI browser checks는 Node 22에서 구문 검사와 Playwright 테스트를 실행하고 HTML 리포트·화면 캡처를 아티팩트로 보관합니다.

| 항목 | 현재 상태 |
|---|---|
| 수정 JS/CJS 및 index.html 인라인 구문 검사 | 오케스트레이션 V8에서 통과 |
| 구조 규칙 정적 검사 | 통과 |
| Playwright 첫 실행 | 13 통과·1 실패·1 제외. WebKit 파일 저장 실패 수정 후 재검사 결과는 PR Checks 참조 |
| 시각적 화면 검토 | 현재 세션에 브라우저 실행 환경이 없어 미검증 |
| 실제 iPhone Safari 녹음·녹화·저장·재생 | 미검증 |
| 실제 로그인·클라우드 동기화 | 미검증 |
| 영상 .mov, 음성 .m4a, 권한 거부·저장 공간 부족 | 미검증 |

Playwright는 인증 SDK를 테스트 대역으로 대체하고 실제 Supabase 요청을 막습니다. 재접속 후에도 인증 대역을 일관되게 적용하도록 테스트 컨텍스트의 Service Worker를 차단하며 공유 수신 기능은 이 테스트의 검증 범위가 아닙니다. 따라서 로그인/클라우드 검증 근거가 아닙니다. Chromium 녹음 테스트는 가상 장치를 사용하며 실제 아이폰 마이크·카메라 검증이 아닙니다. WebKit 데스크톱 실행도 실제 iPhone Safari와 구분해야 합니다.

## 남은 작업과 우선순위

1. PR의 브라우저 테스트·화면 캡처 확인 및 발견한 회귀 수정.
2. 실제 iPhone에서 음성/영상 각각 작성 → 저장 → 연습 상세/보관함 재생 → 새로고침·재접속 반복.
3. .m4a/.mov 가져오기, 권한 거부, 저장 용량 부족, 파일 저장 중 제출·탭 이동 확인.
4. 기존 레슨 데이터와 숙제 이력, 녹음 메모·리포트 저장/재열기 검증.
5. P1 클라우드 업로드/재시도·기기 변경·백업 복원 검증 후 Phase 4~7 미완료 항목 진행.

P0 및 실기기 필수 검증을 완료로 표시하지 않습니다. 이 문서는 구현 내역과 검증 한계를 설명합니다.


## 후속 녹음·저장 안정화

- 권한 요청/녹음/저장/실패 복구 상태를 구분하고 녹음별 청크를 독립적으로 관리합니다.
- 종료 직후 카메라·마이크 트랙을 해제합니다. 저장 중에는 새 녹음이나 종류 변경을 막습니다.
- 저장 실패 시 원본 Blob을 메모리에 유지하고 재시도·다운로드·파일 연결 없이 계속을 제공합니다.
- 기존 bytes 파일의 수동 클라우드 백업을 지원하고 출처·길이 메타데이터를 보존합니다.
- 추가 검사: 가상 카메라 영상 저장·재접속 후 디코딩, 권한 거부, 녹음 저장 실패·재시도, 기록 저장 공간 부족 시 입력 유지, 파일 저장 중 키보드 제출 방지, 기존 bytes 복원·백업 어댑터.
- 백업 검사는 Storage/DB 대역으로 업로드 입력과 메타데이터를 확인합니다. 실제 서버·계정 동기화 검증은 아닙니다.
- 최신 검증 결과는 PR Checks에 연결된 실행 기록을 기준으로 확인합니다. 실제 아이폰과 .m4a/.mov 검증은 남아 있습니다.


## 보관함·연습 연결 후속 수정

- 연습의 보관함 선택 목록에 클라우드 파일을 포함하고 ID로 기기 중복을 합칩니다. 클라우드 오류 시 기기 파일과 오류 안내를 표시합니다.
- 보관함 재생의 비동기 요청 순서를 확인하고, 필터/화면 이동 때 재생과 객체 URL을 정리합니다. 미디어 컨트롤 클릭은 비교 열기로 전파하지 않습니다.
- 필터 결과 없음 안내, 필터 선택 접근성 상태, 명시적 비교 버튼, 정보 수정 대화상자의 초기 초점·Tab 순환·Escape 닫기·초점 복원을 추가했습니다.
- 클라우드 정보 수정에서 Blob/ArrayBuffer와 기기 전용 표시를 제외합니다. 백업 확장자를 MIME에 맞추며, 빈 MIME의 클라우드 가져오기는 파일명으로 추론합니다.
- 보관함 기기 가져오기·클라우드 파일 다운로드에서도 기존 WebKit 저장 공통 함수를 사용합니다. 중복 저장 함수를 제거했습니다.
- README에 실제 화면 흐름, 데이터 위치, JSON 백업과 원본 백업의 차이, 개발·검사·배포 방법을 정리했습니다.

추가 자동 검사: 클라우드 전용 연결과 중복 제거/새로고침 후 재생, 필터 빈 상태와 재생 정리, 늦은 재생 요청 취소, 대화상자 키보드 이동, 클라우드 metadata의 binary 제외, 빈 MIME의 m4a 업로드 인자, 연습 삭제 후 원본 보존. 클라우드·m4a 검사는 대역/업로드 인자 검사이며 실서버·실제 m4a 디코딩 검증이 아닙니다. 최종 실행 결과는 PR에 기록합니다.
