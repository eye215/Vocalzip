레슨 피드백·숙제와 개인 연습, 음원 파일을 연결해 기록하는 모바일 우선 웹앱입니다.

## 화면과 사용 흐름 (v6)

하단 메뉴는 **홈 · 내 곡 · 녹음 · 캘린더 · 성장** 5개입니다. 보관함·레슨 기록·숙제·레슨비 정산·설정은 설정 화면의 메뉴에서 엽니다.

- 홈: 빠른 실행(녹음·연습 기록·레슨 일정·가져오기), 다음 레슨, 해야 할 숙제, 최근 연습한 곡.
- 녹음: 음성만 녹음합니다. 버튼 한 번으로 시작/종료 → 미리 듣기 → 저장. 곡 선택·메모는 선택 사항. 저장 실패 시 원본을 화면에 보관하고 다시 저장하거나 내려받을 수 있습니다(페이지를 닫으면 사라질 수 있음).
- 가져오기: 여러 파일, 파일별/일괄 곡 지정. 영상 파일은 원본 음성 패킷만 추출해 음원으로 저장합니다(영상 녹화·압축 없음). 날짜는 파일 내부 촬영·녹음 날짜 → 파일 수정일 순으로 자동 정리하고, 직접 고르면 그 날짜를 씁니다.
- 내 곡: 곡별로 녹음·연습·레슨 피드백·숙제·타임라인을 모아 봅니다.
- 캘린더: 월간 레슨 일정과 날짜별 레슨·연습·녹음.
- 성장: 기간별 연습 시간·일수·녹음 수·숙제 완료·만족도, 곡별 연습량, 녹음 비교. AI는 작성한 메모 정리만 하며 음정·호흡·발성을 측정하지 않습니다.
- 레슨: 일정(날짜·시간·장소·선생님·곡·준비 메모)과 상태(예정/완료/취소). 날짜가 지나도 자동 완료하지 않습니다.
- 레슨비 정산은 별도 프로젝트(`billing/`, 진입 경로 `/billing/`)이며 이 UI는 링크만 제공합니다.

녹음 파일과 연습 기록은 따로 관리합니다. 연습 기록에 녹음을 연결해도 연습 시간은 더하지 않습니다. 레슨을 삭제해도 숙제·수행 메모·파일 원본은 유지합니다. 이전 화면은 `legacy.html`에서 열 수 있으며 같은 데이터를 사용합니다.

자세한 구조와 데이터 호환: [UI/UX v6 개편](docs/UIUX_v6_개편_2026-11-04.md) · 레슨 데이터 연동 규약: [레슨 데이터 계약](docs/레슨데이터_연동계약.md) · 음원 추출: [음원 추출과 날짜 분류](docs/음원추출_날짜자동분류_2026-11-04.md).

## 저장과 클라우드

- 기록: localStorage의 `vocal-zip_mvp_v1`.
- 미디어: IndexedDB의 `vocalzip_media_v1` / `recordings`.
- 연습의 `mediaIds`가 파일 ID를 참조합니다. 기존 Blob과 ArrayBuffer 형식 모두 읽습니다.
- 로그인하면 기기와 클라우드 기록을 ID 기준으로 병합하고 연결합니다. 이후 기록 변경 시 자동 동기화를 시도합니다. 같은 ID의 충돌은 더 큰 updatedAt 값이 우선하고, 시각이 같거나 없으면 현재 기기 값이 우선합니다. 삭제 표식은 병합에 반영합니다. 서버의 동시 쓰기를 버전 비교로 보호하는 방식은 아니므로 여러 기기의 동시 수정은 별도 검증이 필요합니다.
- 계정 전환 보호: 로그아웃해도 기기 기록은 지우지 않고, 그 기록이 어느 계정 것인지 기억합니다(`vzip_device_owner_v1`). 다른 계정이 같은 기기에서 로그인하면 병합·업로드를 멈추고 "따로 보관하고 이 계정으로 쓰기 / 이 계정에 합치기 / 로그아웃" 중에서 고르게 합니다. 따로 보관한 기록과 녹음은 기기에 남고(IndexedDB `vzip_device_accounts_v1`), 그 계정으로 다시 로그인하면 돌아옵니다. 기존 저장 형식은 바꾸지 않습니다(`device-accounts.js`).
- 로그인 상태에서 기기에만 있는 파일도 자동 클라우드 백업을 시도합니다. 설정에서 수동 백업할 수도 있으며, 실패 시 원본은 기기에 남습니다. 클라우드에만 있는 파일은 스트리밍으로 재생하며 연습에 연결할 수 있습니다. 분할 저장된 대용량 파일은 기기로 일괄 가져오기에서 제외하고 스트리밍으로 재생합니다.
- 보관함과 연습의 가져오기는 여러 파일 선택과 파일별 곡 지정을 지원합니다. 최대 1GiB/파일이며 25MB 초과 파일은 로그인이 필요합니다. 50MiB 초과 파일은 원본 바이트를 24MiB 이하 독립 객체로 저장하고 보관함에는 한 파일로 표시합니다. TUS의 6MiB 전송 청크와 독립 저장 객체는 별개입니다. 원본을 압축하거나 통째로 ArrayBuffer로 읽지 않습니다. 재생 시 서비스 워커가 필요한 바이트 구간을 스트리밍하며, 실패한 업로드만 다시 시도할 수 있습니다. 업로드 취소와 실패 후 재선택을 지원합니다. 열린 페이지에서의 네트워크 재시도이며, 새로고침 후 이어 올리기를 보장하지 않습니다.
- JSON 내보내기는 기록 백업입니다. 음원 원본이 포함되지 않습니다. 브라우저 데이터 삭제 전에 미디어 클라우드 백업 성공 여부를 별도로 확인하세요.

정산은 별도 IndexedDB와 수동 클라우드 전송을 사용합니다. 앱 기록의 자동 병합과 다르며 운영 DB 적용 확인은 [운영 검증 현황](docs/운영검증_2026-11-04.md)을 참고하세요.

자세한 저장 형식과 검증 범위: [대용량·다중 업로드](docs/대용량_다중업로드_2026-11-04.md).

## 개발과 검사

빌드 과정이 없는 정적 HTML/CSS/JavaScript 앱입니다. HTTPS 또는 localhost에서 실행해야 녹음 권한을 사용할 수 있습니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

별도 터미널에서 검사를 실행합니다.

```sh
npm install --ignore-scripts
npx playwright install --with-deps chromium webkit
npm run test:syntax
npm run test:ui
```

GitHub Actions의 UI checks도 같은 검사를 실행하고 HTML 보고서·화면 캡처를 보관합니다. Playwright는 인증·클라우드 SDK를 대역으로 바꾸고 실제 Supabase 요청을 차단합니다. Chromium 녹음·녹화는 가상 장치를 사용합니다. Linux WebKit에서는 MediaRecorder 미지원 검사를 제외합니다. 이 결과는 실제 iPhone Safari나 실제 계정 동기화 검증을 대신하지 않습니다.

실기기에서는 로그인 → 연습 음성 녹음 → 저장 → 기록 상세/보관함 재생 → 재접속을 반복하고, 실제 .m4a/.mov 가져오기, 권한 거부, 저장 공간 부족, 업로드 실패 재시도, 다른 기기 동기화를 별도 확인해야 합니다.

## 배포

GitHub Pages에서 `main` 브랜치 루트를 배포하는 저장소입니다. PR의 변경은 main 병합 전까지 서비스에 반영되지 않습니다. 병합 후 Pages 배포 결과와 실제 사이트의 버전·스크립트 로드를 확인하세요. 공개 프런트엔드에는 Supabase service-role 키나 외부 AI 비밀키를 넣지 않습니다. AI 서버 설정은 Edge Function에서 관리합니다.
