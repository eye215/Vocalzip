# 단일 활성 세션 서버 계약 — S02 1단계

기준 main: `6dd838934b4b27731c12d06f9ef3dd0530d4596e` · 정책 v1.2 · 별도 브랜치 개발

## 구현 범위

- 계정당 활성 session_id 1개. 검증된 JWT의 session_id와 auth.sessions의 소유자 일치가 필요하다.
- vzip_claim_session(null): 첫 접속 또는 현재 활성 세션은 active. 다른 기기는 confirmation_required와 기존 식별자를 반환하며 기존 활성 세션은 보존한다.
- 사용자 확인 뒤 정확한 expected_previous로 재호출한다. 행 잠금으로 동시 인계를 직렬화하고 오래된 확인은 다시 확인을 요구한다.
- vzip_release_session(): 현재 활성 기기만 해제. 이전 기기의 늦은 로그아웃은 새 기기를 해제하지 못한다.
- 기존 소유자 RLS에 restrictive AND 정책을 추가한다. 권한을 새로 부여하지 않으며 비활성 JWT의 직접 DB 읽기/쓰기와 vocal-recordings Storage 접근을 차단한다.
- auth.sessions를 삭제하거나 Supabase refresh token을 직접 수정하지 않는다. 활성 레지스트리 가드가 구 JWT 접근을 차단하는 계약이다.

## 아직 완료하지 않은 범위 — 운영 적용 금지

이 PR은 **서버 계약·임시 DB 검증 단계**다. 계정 격리·단일 로그인 전체 기능 완료가 아니다. 클라이언트 RPC 연결 전에 적용하면 기존 앱의 읽기/쓰기가 막힌다. 다음 통합이 모두 준비된 뒤 별도 운영 승인해야 한다.

1. S01 계정별 최소 임시 저장·기존 로컬 원본 안전 이전·오프라인 복구. 새 계정에 기존 자료 자동 병합 금지.
2. 새 로그인은 인계 대기 화면으로 보내고 기존 기기 종료 확인 전 자료 접근·자동 업로드를 시작하지 않는다. 동의 취소는 기존 세션 유지. 로그인 공급자/재인증·여러 탭·세션 만료 UX를 검증한다.
3. Worker의 매 요청 active-session 확인과 발급된 PUT의 완료 재검증/quarantine. DB RLS는 R2에 자동 전파되지 않는다. 기존 서명 미디어 URL의 만료/회수 계약은 별도다.
4. SECURITY DEFINER RPC, service-role Edge Function, 관리 워커 경로는 RLS를 우회할 수 있다. 사용자 발신 쓰기 RPC의 진입 검사와 내부 서버 작업의 권한 경계를 별도로 대조·보완한다. 이 PR만으로 모든 서버 쓰기 차단 완료를 선언하지 않는다.
5. 로그아웃/인계 중 녹음은 이전 소유 계정 임시 파일로 지속 저장. 같은 계정 재인증 뒤만 업로드한다. 세션 변경이 원본 파일 삭제로 이어져서는 안 된다.
6. 실제 Supabase auth.sessions/JWT 설정·API/RPC·사용 중 앱 버전·권한/뷰와 정책 호환, 재로그인 인계, 물리 iPhone을 검증한다.

기존 클라이언트를 변경하거나 운영 마이그레이션을 실행하지 않았다. 새 RPC/정책 SQL은 검토 가능한 소스 파일일 뿐이다. 기존 데이터·파일·배포·Claude UI 브랜치는 변경하지 않는다.

## 테스트

실제 임시 PostgreSQL에서 JWT/auth.sessions 대역으로 최초 활성화·동의 전 보존·승인 인계·이전 토큰 CRUD 차단·Storage 차단·위조/누락·경합·구 로그아웃·소유자 정책 유지·재적용을 검사한다. 외부 계정·운영 시크릿은 사용하지 않는다. 운영 Supabase 또는 실기기 성공의 증거로 사용하지 않는다.
