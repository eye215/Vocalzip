# MR 정렬 후보를 전체 구간으로 비교

## 문제와 수정

기존 local fallback은 여러 후보의 짧은 파형 anchor를 검증한 다음, 평균 phase peak가 가장 높은 후보 하나만 local track과 held-out 상쇄로 검증했다. 그 후보가 실패하면 다른 후보를 시도하지 않았고, 일부 반복 구절이 강하게 일치하면 전체 녹음에 더 잘 맞는 후보를 놓칠 수도 있었다.

이제 기존 anchor 기준을 통과한 후보마다 local coverage와 기존 held-out 상쇄 검사를 적용하고, 녹음 전체의 예측 오차가 가장 줄어든 결과를 선택한다. anchor·coverage·최소 감소량·음정 신뢰도 기준은 낮추지 않는다. `removedDb`는 전체 혼합음의 에너지 변화이며 MR만의 제거량이나 음질 점수가 아니다.

local track이 읽는 정수 검색 창이 전부 동일한 후보는 한 번만 계산한다. 후보는 기존 제안 개수 이내이며 모든 후보의 음원을 배열에 보관하지 않는다. 현재 검사 결과와 최선의 residual만 보관하므로 여러 후보가 유효할 때 기존보다 전체 8kHz residual 버퍼 하나를 더 보유할 수 있다. 재탐색 비용은 모호한 후보 수에 따라 증가한다. 진행률은 모든 후보를 통틀어 단조 증가하며 취소는 기존 Worker 종료 방식이다.

## 실패 재현과 회귀

가짜 MR의 다른 구간에 9개의 짧은 반복 구절을 만든다. 반복 구간의 anchor peak는 실제 위치보다 강하지만, 그 사이에는 일치하는 음원이 없다. 기존 엔진은 65.001초의 일부 반복 위치를 선택했고 새 실패 테스트가 이를 검출했다. 수정 후 실제 합성 위치인 약 5초를 선택하고, 알려진 합성 목소리 대비 MR 억제가 10dB 이상인지 확인한다. 원본 배열·길이·단조 진행률도 검증한다.

기존 잘못된 MR/다른 편곡/무반주/무음 거절, 비선형 지연, 기존 상쇄 출력, 메모리 제한, Worker 연결과 중단 회귀를 함께 실행한다. 테스트에는 합성 데이터만 쓴다. 최종 실행 수와 결과는 PR Checks에 기록한다.

MR 모듈 v6, 비교 Worker/page v9, 일반 분석 Worker v12로 갱신한다. MR 비교 결과 캐시 서명은 `cancel-v6`이며 이전 엔진 결과를 새 결과로 재사용하지 않는다. 예전 결과를 원본 저장소에서 삭제하지 않고, 사용자가 측정을 실행하면 새 결과를 만든다. 원본 음원·기존 녹음 분석·운영 DB 구조는 변경하지 않는다. 화면 변경이 없어 전후 시각적 차이는 없으며 기존 합성 화면은 [자동 정렬 검토](MR_AUTO_START_2026-11-17.md)에 있다.

## 실제 자료와 남은 제약

기존에 첨부된 녹음과 MR은 저장소 밖에서 읽기 전용 수동 회귀로만 확인한다. 기존 엔진에서도 정렬됐던 파일이므로, 수정 후 정렬 성공을 사용자 iPhone 실패의 해결 증거로 취급하지 않는다. 최신 iPhone 진단은 최신 엔진의 새 측정에서도 기준 녹음 정렬이 실패함을 보여 준다. 그 입력과 첨부된 녹음은 바이트 수·길이가 다르지만, 차이만으로 사용자 과실이나 음정 검출 문제의 유무를 단정하지 않는다.

이 PR은 실제 코드에서 별도로 재현한 후보 선택 오류를 수정한다. 실제 iPhone Safari/PWA의 해당 기준 녹음 성공, 음질 청취, 목소리 보존 검증은 미완료다. 사용자 파일·파일명·식별자·진단 원본은 GitHub/CI에 올리지 않는다.
