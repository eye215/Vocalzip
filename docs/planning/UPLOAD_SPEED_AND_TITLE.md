# 업로드 전송 대기·자동 제목 수정

2026-11-08. UI 구조/디자인·운영 DB·미디어 원본 변경 없음.

- R2 전송을 최대 2개 part로 제한 병렬화한다. part당 8MiB, 전송 payload 복사본 합계 최대 16MiB이며 전체 파일을 한 번에 읽지 않는다.
- 한 part의 인증 실패/취소 시 다른 요청을 취소하고 모두 종료된 뒤 MPU를 정리한다. 모든 part 성공 전 complete하지 않으며 전송 진행률은 완료된 바이트 기준이다.
- 압축·샘플레이트·비트레이트를 바꾸지 않는다. 순차 전송 baseline과 같은 바이트를 같은 순서의 manifest로 확정한다.
- 비교용 가상 네트워크(32MiB/4 part, 요청당 80ms) 첫 측정은 순차 367ms → 2개 병렬 193ms였다. 실제 휴대폰 회선의 개선 비율로 확대하지 않는다. 최종 측정/브라우저 결과는 PR/Actions에 기록한다.
- native WAV 준비/무손실 검증·전송/metadata 저장을 별도 시간으로 측정한다. 실제 사용자 파일이나 개인 정보는 테스트에 사용하지 않는다.

## 자동 제목

신규 가져오기에 nameMode(auto/manual), autoName(마지막 자동 제목), originalFilename을 저장한다.
곡 지정/날짜 변경 시 최신 metadata의 자동 제목만 곡+녹음 날짜로 갱신한다. 직접 바꾼 제목은 manual로 표시하며 다른 기기의 더 최신 제목을 보존한다.
이전 데이터는 원본 파일명 또는 기존 자동 제목 패턴이 확실한 경우에만 자동 제목으로 판별한다. 기존 파일을 일괄 변경하지 않는다.
같은 이름의 번호를 유지하며, 자동 곡 지정 되돌리기는 원본 파일명을 남겨 둘 수 있다.
보관함 metadata는 기존 CAS로 갱신하고 곡/녹음 ID·R2 key·원본 bytes는 변경하지 않는다.

## 별도 진행

전송 중단 후 part 재개·완료 응답 유실·시도별 독립 R2 key는 별도 06-B 브랜치다.
이번 속도/제목 수정에 06-B Worker를 섞어 활성화하지 않는다. 실제 iPhone 속도/백그라운드 지속성은 별도 검증이다.
