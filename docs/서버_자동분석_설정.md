# 서버 자동 분석 켜기 (한 번만)

업로드만 하면 앱을 닫아도 서버(GitHub Actions)가 새 녹음을 분석하고 (5분 안에 시작), 확실한 곡은 자동으로 지정해요.
추가 요금 없음: 이 저장소는 공개라 GitHub Actions 사용이 무료예요. STT는 지금처럼 30초당 약 $0.0015.

> 비밀값(비밀번호, 키)은 **채팅에 붙여넣지 말고** 아래 화면에 직접 넣어 주세요.

## 1. Supabase SQL 실행
Supabase → **SQL Editor** → New query → 아래 파일 내용을 붙여넣고 **Run**.

1. `supabase/migrations/20261108_vzip_song_stt_no_limit_usage.sql` (아직 안 했다면)
2. `supabase/migrations/20261109_server_analysis_jobs.sql`

기존 데이터는 바뀌거나 지워지지 않아요(표·함수 추가만). 다시 실행해도 안전해요.

## 2. 비밀값 4가지 준비
| 이름 | 어디서 |
|---|---|
| `SUPABASE_DB_URL` | Supabase → 상단 **Connect** → **Session pooler** 의 URI. `[YOUR-PASSWORD]` 자리에 DB 비밀번호. 잊었으면 Project Settings → Database → **Reset database password** (앱 로그인에는 영향 없음) |
| `R2_ACCOUNT_ID` | Cloudflare → R2 → 오른쪽 **Account ID** |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | Cloudflare → R2 → **Manage R2 API Tokens** → Create API token → 권한 **Object Read only**, 버킷 **vocalzip-media** 만 → 만든 직후 보이는 Access Key ID / Secret Access Key |
| `OPENAI_API_KEY` | 지금 Supabase에 넣어 둔 것과 같은 키 (곡 자동 분류용, 없으면 보컬 측정만) |
| (선택) `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API → service_role. 예전에 Supabase Storage에 올라간 녹음까지 분석하려면 |

## 3. GitHub에 등록
GitHub `eye215/Vocalzip` → **Settings** → **Secrets and variables** → **Actions** → **New repository secret** 로 위 이름 그대로 하나씩.

## 4. 첫 실행
GitHub → **Actions** → **Analysis worker** → **Run workflow**. 이후엔 5번(새 업로드 자동 시작)을 해 두면 저절로 돌아요.
앱 보관함 위 **서버 자동 분석** 카드에서 진행 상황(측정 완료 · 자동 지정 · 대기 · 확인 필요 · 실패)이 보여요.

## 5. 새 업로드 자동 시작 (Supabase가 서버를 깨움)
GitHub의 10분 자동 실행이 이 저장소에서 돌지 않아서, Supabase가 5분마다 대기열을 보고 녹음이 있으면 서버 분석을 시작시켜요.

1. **GitHub 토큰 만들기**: GitHub → 오른쪽 위 프로필 → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
   - Token name: `vocalzip-worker` · Expiration: 원하는 기간 (만료되면 다시 만들어 교체)
   - Repository access: **Only select repositories** → `eye215/Vocalzip`
   - Permissions → Repository permissions → **Actions: Read and write** (다른 권한은 건드리지 않음)
   - Generate → 보이는 `github_pat_…` 값을 복사 (채팅에 붙여넣지 마세요)
2. **Supabase Vault에 저장**: Supabase → **Integrations** → **Vault** → **Add new secret** → Name `github_actions_token`, Secret에 위 값 → Save
3. **SQL 실행**: SQL Editor에서 `supabase/migrations/20261110_wake_analysis_worker.sql` 내용을 붙여넣고 **Run**
4. **확인**: SQL Editor에서 `select public.vzip_wake_worker(true);` → `started (…)` 또는 `idle`(기다리는 녹음 없음).
   몇 초 뒤 `select * from public.vzip_wake_worker_status();` → `github_status`가 **204**면 성공. 401·403·404면 토큰 권한·저장소를 다시 확인.

서버가 이미 분석 중이거나 15분 안에 시작시켰으면 다시 부르지 않아요. 비용 없음 (GitHub Actions 무료, Supabase 확장 기능 무료).

## 자동 지정 기준 (보수적)
가사 유사도는 정답 확률이 아니라서, 다음을 모두 만족할 때만 자동 지정해요. 나머지는 "곡 확인 필요"로 TOP 3와 함께 남아요.
- 매칭기 자체 기준 통과 + 1위 유사도 0.40 이상
- 2위와 0.12 이상 차이
- 인식된 가사 30자 이상
- 그 녹음에 아직 곡이 없을 때만 (직접 지정한 곡은 절대 바꾸지 않음)

자동 지정된 녹음은 보관함에 "AI 곡 지정"으로 표시돼요. 틀리면 정보 수정에서 바꾸면 되고, 그 뒤엔 서버가 다시 건드리지 않아요.
